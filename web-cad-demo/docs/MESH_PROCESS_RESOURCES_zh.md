# 网格进程资源保护（候选，未部署）

后续候选已增加自主迟到退出观察和逻辑磁盘准入，见 [网格存储与后台退出](MESH_STORAGE_zh.md)。下文是原内存专项的历史验证边界，不应把原“依赖状态读取”描述当作后续候选仍未补齐。

## 保护范围

Gmsh 进程在初始化和读取任务前接入现有 `NativeResourceGuard`，与几何内核使用同一套实现，不引入第二种近似内存监控。Windows Job Object 同时约束该进程及所属作业的提交内存。它不是 RSS/物理内存采样，也不是整机、Gateway、Pi、浏览器/GPU、磁盘或全部并发任务的总预算。限制语义见 [Microsoft 官方文档](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)。

配置 `MESH_WORKER_MEMORY_LIMIT_BYTES`，默认 2147483648（2 GiB），严格范围 128 MiB～8 GiB，单位是整数字节。它与 `GEOMETRY_WORKER_MEMORY_LIMIT_BYTES` 独立；0、空值、科学计数法或未验收平台不能关闭保护。资源配置属于服务，不写入工程网格方案。日常 `.env` 没有改动，本批不能通过刷新旧页面启用，仍须用户允许的受控更新。

## 启动与执行

- 每个新网格进程先做准确请求身份的健康握手，核对服务种类、保护版本、实际进程/作业预算、强制执行状态和内存失败策略。通过前不发送建模/网格输入；旧内核、缺失能力或预算不符拒绝，不退回无保护执行。
- 并发等待共用本代握手，专属任务进程继承相同预算。大请求仍在启动前拒绝。上一代实际退出未确认时，不启动替代进程；停止/关闭期间的迟到握手不能恢复就绪。
- 86 表示观察到内存限额事件，87 表示分配失败，后者也可能由系统内存不足引起；88/89 分别是保护建立失败和配置拒绝。不能把每次普通 Gmsh 错误或退出都归因于内存，也不能保证底层库将所有分配失败都归为同一种事件。系统限额与通知/分配失败分类是不同层次。
- 内存失败不重发原任务，已有工程和旧网格保留。用户可以明确提交较粗尺寸的新任务。文件级修复/交叉/质量工具也走同一受保护入口。

## 结果与退出边界

新任务记录原配置字节数；结果和任务都保留该次经握手核对的资源证明。后台材料线程必须携带这份证明，封存和读取时再次检查与原预算一致。旧历史没有证明就保持没有，不补造新保护声明。证明不是峰值内存统计。

“算出结果”不等于“可发布结果”：专属进程退出确认后才写入 `complete` 并开放结果/下载。停止观察超时时，状态保留为“正在确认退出”，中间文件保留，整个网格任务槽不用于新的 Gmsh 任务。后续只读状态核对检查原进程句柄，只有实际退出得到证明，才清理未发布文件、将原任务标为中断并恢复队列中原先已提交的任务；不重剖中断任务。当前这条迟到退出恢复依赖状态读取，不宣称已有无人观察时的自动后台重核对。

正常内存失败已确认退出时直接记录失败；未知退出不会冒充“已取消”或“已完成”。没有可验证原句柄的异常情况继续保留未知，需要进一步检查或受控重启。

## 验证与剩余边界

真实 Gmsh 在 256 MiB 限额下完成粗网格，过细网格触发退出；工程及旧结果不变，再明确提交粗网格成功。另用真实进程退出门控验证计算完成但退出未确认、5 秒观察超时、结果下载拒绝、跨工程队列不重叠，以及实际退出后的只读恢复。

资源证明的缺失/矛盾、代次隔离、并发握手、旧内核拒绝、请求容量、停止期间迟到回复和完整工程方案均有回归。首轮漏传线程证明、提前发布 `complete` 及超时释放名额的失败日志保留。精确最终候选及分层数量见 `.artifacts/mesh-memory-result.json`；没有该最终回执时仍在验收。

尺寸仍不是严格单元数/内存估算；本批不提供全机总预算、原始结果磁盘配额、所有重作业硬隔离、工业规模吞吐认证、任意脏几何/离散交叉验收或安装升级完整认证。日常服务与原工程不更新，完整工业化目标继续。
