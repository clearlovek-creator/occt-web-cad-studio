# Pi 工程状态与新建任务互斥

## 用途与范围

在新建独立工程前，不能仅根据助手面板的 busy 标记判断来源工程已空闲：面板可能关闭，同一工程可能有多个 Pi 会话，原生进程也可能处于压缩、排队或重试退避。此实现复用 Pi 原生 `get_state`，不增加 CAD/大模型工具，不调用模型，不把历史读取或工程切换当成新的对话。

本批实现后台状态和创建执行互斥；控制器的一键新建、任务条、Python 兼容入口和完整页面切换仍未接入。它不是整个跨工程会话系统已经完成。

## 只读状态接口

`GET /api/pi/documents/:documentId/activity` 仅允许受信任本机 Host、连接及 Origin，无查询参数，不接受写方法。返回工程 ID 及 `activity`：

```json
{
  "version": 1,
  "documentId": "default",
  "status": "idle",
  "guarded": false,
  "checkedAt": "2026-11-17T00:00:00.000Z",
  "sessions": [
    {
      "sessionId": "source",
      "streamId": "原进程事件流 ID",
      "isStreaming": false,
      "isCompacting": false,
      "pendingMessageCount": 0,
      "status": "idle"
    }
  ]
}
```

示例 ID 和时间只说明格式，不是实际空闲证明。`idle` 是本次状态观察，不是永久许可；`guarded:true` 表示同工程后台工作区操作仍持有互斥，即使原生 AI 此刻空闲也不应发起另一次切换。

- 所有已管理的同工程会话都需要核对，不能只查当前面板的会话。
- 明确 streaming、compacting、排队消息或未确认的修改 RPC 均为 busy。当前打包 Pi 的 isStreaming 覆盖整个运行和后处理链；真实 SDK 专项验证自动重试退避期间仍为 busy，没有改 SDK 来伪造状态。
- 启动未完成是 busy；停止/退出未确认、已退出但仍映射的会话、状态超时/畸形、查询期间流/进程/命令序列变化均为 unknown，不能猜测 idle。
- 投影仅含逻辑会话 ID、流 ID、活动标志和有界原因，不返回模型配置、密钥、文件路径或对话内容。
- 没有活动会话时不启动 Pi、不写配置、不认领旧 owner、不读/改旧对话。意外退出的映射会话由用户显式恢复连接或显式停止核对，不为状态查询自动重启。

同工程并发观察合并为一次。每次最多核对 32 个会话，最多 64 个公开工程观察并发，每次原生 get_state 截止 5 秒；超限返回 429，不将遗漏会话当作空闲。另有最多 64 个工作区互斥，内部准入核对和公开观察可能各有一次读取；这不是整个 Pi/Gateway 的硬内存或全局会话数量认证。

## 新建工程的准入

专用 `project.create` 执行进入原任务名额后，在来源工程取得进程内互斥，再进行一次新鲜的原生状态核对。若已有公开观察，先等它结束，再重新读取，不能用互斥建立前的旧 idle 响应授权创建。只有 idle 才进入来源状态检查及原有新目标事务。

互斥一直保持到新目标完整事务返回或抛错，包括原生创建、检查点发布和受保护提交，不是在发送创建命令后提前解除。

期间同来源 Pi 的 prompt、追加、压缩、会话/模型修改，以及新会话启动/重连和显式归属采用均在实际写入/配置生成前拒绝；只读 RPC、abort/abort_retry 仍可使用。其他工程不因此被全局锁住。失败、取消、未知及嵌套拒绝只释放自己的互斥。

busy 返回 `PI_DOCUMENT_ACTIVE`（409），unknown 返回 `PI_DOCUMENT_ACTIVITY_UNCONFIRMED`（503），竞争操作返回 `PI_DOCUMENT_TRANSFER_BUSY`（409）。创建任务在目标准备前被拒绝时保留原任务并报告 execution:not-started，不触发目标原生命令或重做原请求。用户停止原会话后可发起新的独立创建，不能重用已结束的失败任务偷偷续跑。

## 边界与后续

互斥是运行时内存状态，不新增持久任务队列或历史系统。重启后的创建结果仍由既有持久任务、事务和准确原回执核对；不重放创建。该状态接口覆盖当前 Runtime 管理的会话，不扫描或证明任意外部/孤儿 Pi 进程已退出，不是任意断电或强杀进程树的认证。

最新候选还将互斥用于专用文件打开任务执行，以及当前页面的来源绑定激活；来源/目标两个工程按固定顺序取得保护并去重。新建任务也加入目标侧准入。详见 [工程切换说明](WORKSPACE_SWITCH_zh.md)及 `.artifacts/workspace-switch-result.json`。这不代表旧 Agent/Python 或直接几何 API 已全面协调，也不把目标 ID 的 Pi 旧磁盘历史新鲜度问题当作已解决；历史新建页面专项仍见 `.artifacts/project-create-ui-result.json`。

真实回归使用独立临时工程、私有端口、本地免费模型及真实 Pi/OCCT，覆盖多会话中的次级会话忙碌、停止后一次新建、执行/提交期间拒绝插入 AI 命令、保留只读/停止与旧配置，以及自动重试退避空隙。精确版本和分层证据见 `.artifacts/pi-workspace-guard-result.json`；日常服务不更新。
