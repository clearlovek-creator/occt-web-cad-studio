# Body 显示状态的持久化与恢复

状态：2026-11-17，独立内核候选，未部署。修复透明度在工程重开、撤销重做、特征抑制恢复、阵列扩展和复制中的丢失，并统一现有显示状态的写入。准确候选和验收证据见 `.artifacts/body-display-result.json`。

## 原因与修复

此前 `body.update` 可以立即返回设置后的透明度，但原生工程快照没有保存该值，重算的显示状态也没有读取它。因而“设置成功”不代表保存、重开或恢复后仍然有效。新增 9 个实际接口场景全部在旧内核失败，保留 `.artifacts/body-display-before.log` 及对应私有工程材料。

新快照在 Body 标签中使用实数字段 `system.bodyOpacity.v1`，保持双精度；模型回复及特征记录不再把透明度截成六位有效数字或小数。现有 0.05 至 1 的范围不变，值越大越不透明，1 表示完全不透明。

名称、显隐、颜色、材料和透明度现在由共同写入函数记录，供布尔输入输出、阵列、复制、放样、扫掠、旋转、偏移和生命周期恢复复用。恢复读取透明度，复制继承源 Body 的透明度；新增阵列槽位继承当前源显示值，现有实例自己的设置不被覆盖。新建独立几何原有默认规则保持。

Body 显示更新先在临时记录上校验全部输入，再写入当前记录。含有非法透明度的组合请求不能先改变名称或颜色，也不会推进修订版。这个保护针对本次 Body 显示更新，不代表所有原生操作都已具备独立的完整事务边界。

## 旧工程与异常数据

旧文件缺少新标签字段时，只从该 Body 当前生成特征中、与当前输出 Body ID 完全对应的显示记录读取透明度。不搜索相似几何、别的 Body 或任意旧历史槽位；确实没有记录时保持原不透明默认值。旧记录若已被截断精度，不能凭空恢复丢失的数字。

新字段类型错误、数值越界或旧记录格式损坏会明确拒绝，不自动截断或钳制。旧文本记录最多解析 64 个字符。加载失败发生在临时工程中，保留原工程、修订版和原生文档所有权。旧内核可忽略新增标签继续读取几何，但不能由此保证旧版本保留透明度；本轮不修改日常文件或执行数据迁移。

## 验证

9 项新增接口测试覆盖便携工程重开、Undo/Redo、阵列抑制后保存与恢复、布尔输入恢复与删除、扩展实例、复制、精度、范围端点与真实后台重启。原生检查另保存和修改实际 XBF，核对新实数字段、旧标签缺失、无记录默认、其他 Body 的旧记录、错误类型及越界数值；损坏加载与非法组合修改必须原子拒绝。

最终 2065 项应用及 94 项 Python 回归、23 项专项、16 项几何与 3 项网格 CTest、封存候选 8 项实际布尔改参及属性网格链路通过。5 项新增页面检查使用真实键盘、页面撤销重做和 WebGL 材质透明度参数，不只检查接口或文本；另有 13 项独立页面、55 项工作台和 8 项历史引用兼容流程通过，页面异常为零。1440px 与 640px 截图已复核。类型检查和修改的 JavaScript 文件检查通过，原生编译保留既有 `Standard_True` 弃用警告。

首次原生测试编译因测试容器类型推断失败而修正；首次页面撤销验收从外部接口发命令，未走页面状态同步，现改为用户实际使用的按钮。两份失败记录均保留，未增加产品重试、放宽断言或宣称修复了跨客户端实时同步。

页面检查使用当前机器的 Chrome 软件渲染，不构成工业装配、真实 GPU 或像素等价认证。前端、后台 JavaScript 与 Pi SDK 不改；日常服务、默认内核、R222、Box10、295 份保护文件与完整 Pi 历史保持。复杂拓扑全部生命周期、任意脏离散表面、总资源治理和安装升级仍需继续。
