# 正式共形四面体组件与输出保护

离散四面体、独立质量计算和优化退步恢复已进入 `mesh-worker` 共享核心，并通过 `discrete-tetra` 任务接入工程持久任务框架。候选后台保存 CAD 来源、材料快照、分区、最终结果或失败诊断，支持取消、服务重启和完成记录的明确恢复。派生结果已接入页面、容量准入、认证、质量、边界、网格线和 MSH 下载接口；第三版工程包支持携带网格保存与恢复，见[工程网格保存与恢复](PROJECT_MESH_ARCHIVE_zh.md)。日常服务未更新，原始结果继续保持 `normalMeshAdmitted: false`；只有独立认证的派生结果可以作为普通可用网格。

## 组件与进程

继续使用现有 `gmsh_mesh_worker.exe`，通过固定参数 `--discrete-single-job` 启用新入口，不增加第四套原生运行库。原有无参数入口和普通网格操作保持。实验入口只作兼容检查，与正式入口使用同一份四面体和质量代码。

表面、体域和四面体调用共用从既有客户端抽出的单任务进程管理。每次调用拥有一个实际进程，先核对能力和 Windows 内存保护，再发送固定输入；取消、超时或异常退出不自动重试，不启动重叠替代进程。新入口只执行一次算法后退出，不加载用户 Gmsh 配置，不启用 GUI。握手同时核对实际运行版本和 API 版本，均固定为 4.15.2。

## 输入与质量规则

四面体调用要求原始离散来源以及已核对的体域结果。调用端重新检查来源、闭合壳、体域归属及体域组件的正常退出证明，再固定请求快照。底层组件的 Body、Face 和 Solid 标签本身不是 CAD 证书；工程任务通过实际 OCCT 私有副本导出，绑定完整 Body 集合、持久身份、拓扑修订、几何指纹、实际内核代次和输入摘要，不采用显示网格或调用者自造标签。

几何与材料在同一次工程串行操作内捕获，并核对导出前后状态。使用中的材料定义和每个 Body 的赋值另有摘要；材料变化会让旧结果 stale，未使用材料的编辑和单纯显隐不使几何来源失效。每个分区单元保留全部来源 Solid。交叠来源材料不一致，或部分已赋材料、部分未赋材料时，在 Gmsh 启动前停止并保存冲突诊断；全部未赋材料则明确记录为 unassigned，不自动指定材料或优先级。

正式调用默认明确使用严格质量规则：SICN 门限为 0.2，低质量单元允许比例为 0；也可显式请求诊断模式。这是当前调用规则，不是所有工业模型的通用合格线。规则同时检查每个连通体和全局。不合格时返回 `MESH_QUALITY_REJECTED` 和有界质量概要，不返回节点、单元或可用网格。

三种优化、公共边界保护和不退步恢复继续沿用[质量算法](VOLUME_MESH_QUALITY_zh.md)。优化完成不等于质量合格，质量合格也不等于材料归属和工程准入已经完成。旋转相交样本优化后仍不满足当前门限，会明确拒绝，不放宽断言。

## 开放面精确归属与空腔构造

原生组件新增显式 `volume.partition-constrained` 入口，复用现有单任务进程、资源保护和客户端。它需要独立的固定能力与 `exact-nef-membership-with-open-sheet-constraints-v1` 来源体系；旧 `volume.partition` 仍拒绝开放 Sheet，旧工程材料和旧分区规则不改写。该入口目前是后端组件能力，尚未接入工程任务、页面或 Agent 的几何生成工具；约束四面体组件的后续进展见下节，不能据此宣称开放面剖分已在产品中完成。

全部来源面先共同交叉切分，再通过精确集合运算区分以下三类。体边界继续使用一侧或两侧相反的有向体用途；内部开放面记录唯一包含它的闭合连通体，但不加入闭合壳；体外开放面保留来源，不丢弃，也不生成虚构实体。贴合边界的 Sheet 可以与真实体边界共享面片，Sheet 的方向不改变实体壳方向。跨多个体或交叠分区的 Sheet 必须先切开，不能根据包围盒或最近中心点猜测归属。

新结果按每片三角面保存 `constraints.triangles`，使用 `boundary`、`embedded`、`exterior` 和明确的连通体索引。CGAL 给出精确面片集合归属；调用端复核分类结构与计数、来源覆盖、闭合壳、有向体积及原始实体覆盖。旧四面体入口继续拒绝将新分类结果冒充旧闭合体域；新组件单独证明开放面嵌入、两侧单元连接和完整来源，普通工程网格准入尚未开放。

空腔修复同时作用于原有闭合体域路线。固定 CGAL 版本的 `Nef(PolygonMesh)` 会标记所有有界区域，直接传入多壳模型会填满内壳。来源现在逐个闭合壳构造有界集合，通过精确对称差保持嵌套奇偶关系，并核对原始有向体积。对深层嵌套，整体 Nef 转网格可能产生错误方向和体积，因此改为逐个实际标记的 SNC 连通体导出、验证，再证明它们互不体积交叠且精确还原原集合。错误内壳方向、开放实体和没有闭合体的纯 Sheet 仍拒绝，不依靠采样点、距离阈值或降低断言通过。

17 个解析原生场景覆盖内部面、体外面、部分相交、反向贴合、公共界面、三个交叠分区、交叉 Sheet、真实空腔、空腔边界和空腔中的独立小实体。真实 OCCT 布尔空腔也经过 CAD 来源捕获、分区与四面体校验，体积保持 `7 mm³`，未修改工程几何。它们是受控组件证据，不是工业复杂几何的完整验收。

## 开放面共形四面体组件

2026-11-21，现有 `--discrete-single-job` 组件增加独立的 `mesh.discrete-constrained-tetra` 操作和 `constrainedDiscreteTetra` 能力，结果使用 `shared-constrained-discrete-cells-gmsh-tetra-v1`。旧操作、旧结果、请求和回复预算不变，不能猜测旧程序具备新能力；旧闭合体路线在启动进程前拒绝新分类输入。新入口要求原精确分区的实际退出与资源证明，不增加第四套原生运行库。

| 精确分类 | 网格核验 |
| --- | --- |
| `boundary` | 每个体边界面匹配一个四面体面；公共界面在两个体中反向共用 |
| `embedded` | 每片开放面必须与同一包含体内的两个相反四面体面共享节点编号，不能只按坐标相近匹配 |
| `exterior` | 保留独立表面网格及原来源，不给它虚构实体或四面体归属 |

新构造显式保留每个精确分片的顶点、共享边和有向平面面片，再将内部面嵌入对应体。不是修改工程 CAD，也不是用包围盒生成替代面。自动推断离散拓扑的初版曾把开放面外缘的折线并成一条曲线，重划时切掉角点；保留反例中单片面积从 1.125 缩为 1.08。显式边界修正后，沿用原面积、平面内覆盖、共享节点、体积及坐标质量断言通过，未放宽误差。

17 个解析几何场景及 1 项严格质量拒绝共 18 项原生检查通过，涵盖内部、体外、部分跨界、边界贴合、跨体、交叉 Sheet、空腔和嵌套实体；纯 Sheet、错误壳方向和未封闭 Solid 仍明确拒绝。最终 2589 项应用回归、86 项协议专项及 21 项原生测试通过，879 份应用文件摘要前后一致，原生测试另绑定准确源代码与程序。封存候选再验证 4 项严格成功、严格拒绝和旧闭合体兼容流程，运行库与原测试构建逐字节一致。

逐三角面路线的质量和产品接入仍有边界。显式 Gmsh 优化 3 次后，内部开放面和交叉 Sheet 在 0.2 阈值、零低质量单元比例下通过；原部分跨界样本未通过。同一样本显式缩小全局尺寸到 0.4、0.3、0.2 和 0.15 也未达标，不能把增密当成修复。局部诊断发现同一来源 Face 的分片中有约 7.125° 的细长角；下节的独立实验开始取消人工分片边，正式逐三角面入口尚不使用该拓扑。

## 同来源平面分片合并

2026-11-21，`gateway/constrained-surface-patches.mjs` 新增独立派生拓扑 `exact-dyadic-source-face-planar-patches-v1`。输入仍先通过原约束体域、来源覆盖、算法和实际退出证明校验。坐标转换为精确二进制有理数，通过平面方程、反向共边消去和有向环面积相等证明分片集合不变，不采用角度阈值、最近面或中心点归属。

只有完整来源 Face 集合、规范方向下的体用途和精确平面都相同，且沿共边连通的三角形才合并。不同 Face、真实微小折角、不同连通块和体域分类不合并。每个面片保存原三角形及其方向、来源面、孔洞环和规范平面。共线边界点只有在两条约束边的用途完全相同且精确反向共线时才能简化，原边链仍保存。

交线可能终止在 Face 内部，不能只靠把 Face 分为两个连通区表达。拓扑因此同时保留面片边界和嵌入曲线，曲线的全部面片用途保持一致。隔离入口 `experiments/patch-volume-mesh` 将这些环和曲线交给固定 Gmsh 4.15.2，并复用正式的坐标规范化、质量计算、不退步优化和边界保护核心，不改写正式程序或新增运行框架。

## 正式面片四面体入口

2026-11-21，面片算法进入既有 `cad_discrete_volume_mesh_core`，实验程序只保留调用该核心的兼容入口。正式 `--discrete-single-job` 模式增加 `patchedDiscreteTetra` 能力与 `mesh.discrete-patched-tetra` 操作，结果使用 `shared-source-face-patch-gmsh-tetra-v1`。请求携带原约束体域、精确派生面片和固定质量策略；原 8 MiB 请求、64 MiB 回复及实际进程退出规则不变。旧两类操作和结果不改写，不宣称旧程序支持新能力。

原生结果逐面片保留全部原分片编号、方向、来源 Face 集合、体用途与分类。调用端复用原四面体坐标质量、体积、连通性和单元面核验；新表面校验允许网格跨越已取消的人工对角线，但逐原三角形裁切并核对覆盖。面片须连通、方向一致，孔洞与边界不得出现裂缝。每条真实交线在其全部面片用途间必须共享实际节点编号；内部 Sheet 须对应唯一包含体内两侧真实四面体面，体外 Sheet 不能虚构体用途。

裁切使用局部平移、缩放坐标，避免直接累加远原点投影面积。二维包围索引仅筛掉不相交候选，不用于决定归属或代替几何验证。固定预算为最多 5000000 次裁切候选和 20000000 次索引节点访问；超出后明确拒绝，不发布部分认证结果。输入、结果与失败阶段均接入原材料线程的固定操作表、二进制快照及退出屏障，不增加主线程的大回复验证或第二套工作池。

24 项正式原生流程覆盖 19 项严格质量成功、质量阈值 1 的拒绝、伪造面片启动前拒绝、真实进程取消及原闭合体/逐三角面操作兼容。封存候选再通过 5 项流程，10 个实际材料线程经同版预检启动并正常退出。真实旧程序没有新能力时只启动一次并拒绝；检查点进程既不宣告新能力，也不接受新操作，避免在尚未支持嵌入关系的旧快照中丢失交线。

## 约束面片的 CAD 来源与派生归属

2026-11-21，内部可信捕获 `captureProjectConstrainedTetraSource` 允许实际 Solid 与 Sheet 共同捕获，在同一工程动作内核对几何、材料和导出前后状态。只有存在真实开放面时使用第二版来源 `cad-discrete-constrained-tetra-source-v1`；原第一版来源继续拒绝 Sheet，纯 Sheet 也不会被提升为闭合体。第三版绑定结果 `cad-source-bound-constrained-tetra-v1` 保留完整原始分区、精确面片计划和原生结果，重新核对固定拓扑能力、资源保护、实际退出及 CAD 身份，不改写原有两版结果。

## 工程任务的优化检查点保存

配套后台候选已将显式要求优化的离散体任务接入检查点流程。运行配置固定使用原封存网格角色，内部设置 `optimizationProcess: "checkpoint-v1"`；外部请求不能指定进程路径或伪造此设置。未请求优化的任务和已保存的旧任务继续使用原格式，旧优化结果不会被改写为新进程证明。

任务先保存实际 CAD 来源与精确分区，生成进程正常退出后，现有材料线程将完整检查点写入专属暂存。主线程等待同一线程真实退出，复核身份、容量、当前几何与材料，再发布 `optimization-checkpoint.json` 并保存任务凭据。只有这些步骤完成，才重新读取认证文件组装独立优化命令；保存失败不启动优化，也不从内存中的未发布对象继续执行。检查点发布后来源发生变化，保留原检查点，不发布过期优化结果。

检查点文件绑定原来源与分区摘要、完整 CAD 快照摘要、生成输入、质量策略、实际生成退出与资源证明。新结果使用第二版任务包装，单独引用检查点摘要，保留真实优化回复及其算法身份；不伪装成旧的单进程四面体回复。普通网格派生同时核对检查点与最终结果，显示缓存的文件身份与来源令牌也包含检查点。检查点本身从不准入普通显示、质量导出或 MSH。

检查点最多 128 MiB；含检查点的原始任务要求至少 384 MiB 单任务逻辑磁盘预留，未请求优化的原要求仍为 256 MiB。文件计入既有全局存储清点。校验仍在原材料池内执行，新进程协议的校验快照最多 272 MiB，旧阶段仍保持原预算；优化命令本身仍必须满足原生 128 MiB 请求限制，超限明确拒绝而不截断。上述额度不等于整机峰值资源认证。

崩溃、取消、严格质量拒绝或受控停机后，已发布检查点保留。任务重启只发现原记录，读取时重新认证检查点，返回节点数、四面体数和原质量是否达标等概要，不自动生成或优化。临时 Windows 文件占用返回 I/O 拒绝，不把已完成任务标坏。第三版工程保存与打开包含固定的检查点文件角色，完整保留原字节及命名空间；完成、失败、取消和中断任务均可随工程迁移，恢复后的显示仍默认隐藏。

11 项新增应用检查和 10 项真实封存后台场景覆盖实际 OCCT 来源、独立进程、检查点先发布、严格派生、文件占用、终止、取消、受控停机、质量不足、重启不重跑以及真实工程保存打开。真实受控终止证明了产品任务的故障保护，不证明 Netgen 访问异常已修复。证据见 `.artifacts/checkpoint-task-service-final/result.json`；日常服务未更新。

## 明确恢复优化与独立尝试记录

2026-11-20，候选后台提供 `POST /api/mesh/jobs/:id/resume-optimization`。请求只接受 `requestId`、`failedStateToken` 和 `checkpointToken`，分别绑定本次操作、原失败状态和检查点内容；不接受路径、几何子集、算法、质量或其他参数。来源必须是有认证检查点、没有最终结果的失败、取消或中断任务，且原实际进程已经退出。完成记录保存失败、但计算结果仍在的任务继续使用原 `recover-completion`，不重复优化。

恢复建立关联的新任务，返回 202 和新 `meshJob`，不改变原任务状态、检查点、诊断或完成凭据。同一请求身份重复提交，包括重启后提交，返回同一次尝试；不同失败或检查点不能复用旧身份。新任务不执行 CAD 导出、体域分区或三维生成，只执行一次独立优化。再次失败或取消保留为独立记录，用户可以明确选择该记录建立下一次尝试，不自动重试。

恢复能力按宿主接口明确启用。不具备恢复能力的旧资产管理宿主继续提供原功能，不因新增状态查询报错；恢复操作返回明确的不可用错误，不静默改走普通建模或网格生成。

现有材料线程重新认证原记录及全部输入，复制来源、分区和检查点的原字节，并保存直接来源的失败记录及已有有界诊断。四个文件作为 `recovery-inputs` 目录共同发布，主线程在同一线程真实退出后核对文件身份、磁盘余量、原状态归属及当前几何和材料，再持久登记与排队。捕获期间暂不允许删除原任务；发布后的新尝试自包含，不依赖原目录继续存在。复制、准入或来源检查失败不会启动优化。

恢复仍使用原生成设置和进程保护证明。当前运行资源策略与原证明不匹配时明确拒绝，不静默修改设置。每个新任务继续要求至少 384 MiB 逻辑预留，直接来源记录最多 16 MiB，记录保留还受现有任务总数、单工程容量、全局磁盘和本地每检查点 32 条恢复尝试限制。预留不是操作系统配额，删除记录必须由用户明确执行。

从工程包恢复的检查点也可作为来源。原始 CAD、检查点和生成记录保留其原命名空间；新任务仅将当前工程归属写入自身记录与派生结果，不改写原始输入。工程再次保存打开，恢复尝试、原失败记录及检查点一同携带，保持隐藏、不重跑。修复了再次打开时按普通目录查找恢复检查点的问题：先认证任务元数据，再选择固定的恢复子目录，不接受元数据中的任意文件路径。

10 项新增应用检查及 11 项真实封存后台场景覆盖原记录不变、重复提交、再次失败后明确恢复、Windows 文件占用、取消、资源预算、重启去重、跨工程检查点恢复、严格派生与工程再次打开。真实后台观察到的全部网格执行均为 `mesh.discrete-optimize`，没有重新分区或生成。证据见 `.artifacts/optimization-recovery-service-certified/result.json`。此阶段完成后台恢复闭环；页面后续进展见下节。Agent 工具仍待接入，Netgen 崩溃根因、任意写入点硬终止和工业规模也未完成验收。

### 页面中的明确恢复

失败、取消或中断任务具有可用检查点时，任务详情显示“从检查点继续优化”。操作创建独立尝试，保留原任务和诊断；任务详情与记录显示来源关系，并可返回来源任务。取消只针对当前尝试，不取消或覆盖来源。优化成功后不自动剖分或准备派生文件，用户明确准备显示与导出后仍默认隐藏。

页面先在浏览器中保存工程作用域内的请求身份和两个内容标识，再发送一次请求。重复点击共用一次提交；回复丢失、刷新或切换工程后，仅核对原身份。即使列表未出现新尝试，也不会据此释放请求并重新提交，因为后台可能仍在做容量准入。匹配的任务记录才可确认已接受；记录损坏、身份不一致或存储拒绝时保留原内容并阻止新恢复。该记录不构成跨标签页事务锁，后台去重、来源和容量约束仍是最终准入依据。

客户端新增 16 项检查。独立封存前后台的 7 项真实浏览器流程覆盖恢复、取消、已接受但回复丢失、刷新后身份恢复、工程切换隔离、只读核对及最终结果保持隐藏；3 次网格执行全部为实际独立优化，没有几何导出、重新分区或重新生成。桌面与窄窗口使用既有浅色工作台与原生按钮，不增加确认弹窗或网格显隐入口。证据见 `.artifacts/optimization-recovery-ui-browser-final/result.json`。首轮发现旧完成结果抢占新任务详情、读取失败时误禁用只读核对两个问题，反例保留并已修正。

## 结果独立核验

调用端从输出坐标重算每个一阶四面体的正体积和 SICN，不只接受引擎摘要。检查重复单元、单元面连通、内部面的反向使用、每个连通体及并集体积，以及完整 Body、Face、Solid 来源。

公共界面必须在两侧使用同一组节点编号和三角面。每片实际边界面对应一个真实外露的单元面，方向符合原体域的有向边界；顶点在原来源三角面内，面积覆盖完整。坐标相同但节点断开的裂缝、遗漏边界或伪造单元质量均拒绝。

质量和优化报告区分原网格、优化候选和最终选择。任一连通体或整体退步时，恢复原节点、单元、分类和质量；恢复后仍执行相同的结果核验。材料优先级始终不自动选择。

## 远原点计算与坐标精度

离散剖分内部采用以首个来源点为原点的平移坐标系，避免 Gmsh 在较大绝对坐标上计算单元质量时出现相消误差。只平移、不缩放或旋转；输出节点恢复到工程坐标，Body、Face、Solid 和公共界面编号不变，原 CAD 与原始分区不改写。

质量计算之前，内部节点先按最终工程坐标的双精度表示完成一次往返规范化；优化后的候选同样处理。这样质量门限约束的是实际返回的坐标，而非精度更高、却无法原样保存的内部网格。原生独立 SICN 与 Gmsh 的差异仍不得超过 `2e-10`，调用端继续从实际输出重算质量、体积、公共界面与来源覆盖。优化前后的边界仍精确核对，退步时恢复原网格。

来源点无法原样往返，或节点往返位移超过固定 `1e-8 mm` 精度时，返回 `MESH_COORDINATE_PRECISION`，不随距原点距离放宽精度，也不降低质量门限。用户需将过远或尺度悬殊的模型调整到可表示范围；这不意味着任意 `1e12 mm` 坐标都能满足微小特征精度。

13 个可重复的解析合成压力样本覆盖平移、斜交、接近重合、薄层、间隙、窄交叠与开放边界，并包含远原点优化流程。修复前，三组 `1e6 mm` 平移样本在质量数值核对处失败；修复后这些样本通过原标准。薄层与窄交叠仍被严格质量规则拒绝，开放壳不进入体剖分。此组是合成回归样本，不代替真实工业 CAD 语料验收。记录见 `.artifacts/discrete-local-frame-corpus-qualified/result.json`。

## 退出与输出收尾

单任务成功需要三个条件同时成立：回复合法、同一实际进程正常退出、标准输出完整结束。Windows 可能先关闭输出管道再通知退出，也可能先通知退出而最后一段回复尚未读完。通道现在分别核对这两种顺序，不把临时的管道关闭当成最终进程失败，也不因退出码为零就提前接纳结果。

正常退出后的输出收尾沿用有界退出等待，默认 5 秒。收尾期间仍检查回复字节上限、多余帧、非法 UTF-8 和未结束的尾部；超时或截断拒绝结果，晚到的取消同样有效。非零退出不进入成功收尾模式。该模式只用于这些单任务客户端，原有长驻几何和普通网格通道保持默认行为。

结构化算法拒绝使用退出码 2，也必须等待同一实际进程退出和完整输出结束，才能保留可信诊断。严格质量拒绝保存质量与优化概要、版本、资源保护和退出证明，不保存可用网格。回复与退出码矛盾、多余帧、截断或取消会使诊断失效；内存保护退出码 86 至 89 优先于回复内容，不进入延迟错误输出读取。

## 工程任务保存与恢复

`POST /api/documents/:id/mesh/jobs` 接受 `kind: "discrete-tetra"`，设置放在 `discreteTetra` 中。默认导出全部工程几何，最多 4096 个输入三角面、6 个来源 Solid；当前新路线不支持开放 Sheet，不能忽略它后只剖分剩余实体。Body 和 Face 选择仍属于后续显示控制，不缩小联合剖分范围。候选入口仅在配套封存的 CGAL 和 Gmsh 运行库可用时配置，不从继承 PATH 寻找替代组件。

任务复用现有目录、队列、磁盘预留、计算材料线程、取消和完成凭据。待执行队列只保留经过摘要认证的文件凭据，不常驻完整来源 DTO。任务目录内的 `discrete-source.json`、`partition.json`、`result.json` 或 `failure.json` 分别记录来源、分区和成功或失败结果；已发布材料不可覆盖。每阶段先在专属暂存中校验和保存，材料线程真实退出后才核对文件身份并发布。单任务结果查询只返回重新核验后的概要。

一个任务共同拥有两个单次调用客户端。分区和四面体阶段都可以取消，关闭任务会阻止后续阶段启动，等待原实际进程退出后才结束。中断任务重启后保持 interrupted，已完成任务重新核对原材料并保持隐藏，均不自动导出、重算或重发。文件占用、权限和空间问题与内容损坏分开；暂时读取失败不把已完成结果改坏。

完成凭据保存失败时，已计算结果保留为 `MESH_COMPLETION_UNCOMMITTED`。用户通过既有 `recover-completion` 操作绑定原失败状态和本次恢复身份，只核对并发布原结果，不重新调用几何、CGAL 或 Gmsh。材料冲突与质量失败则保存独立诊断，不作为“恢复完成”绕过算法要求。

## 离散来源的普通网格适配

派生网格使用独立的 `cad-discrete-partition-v1` 来源体系，不标记为 BREP 历史。适配前重新核对已保存的 CAD 快照、材料、原始结果及两阶段实际退出证明；默认 BREP 准入和面查询不会因为结果自带新标记就接受它。只有经过原材料核验的调用端才能明确选择新来源体系。

每个输出体对应一个连通分区单元，保留该单元全部原始 Body 和 Solid。一个 Body 的多个 Solid 可以进入不同分区，多个 Body 也可以共同拥有同一个交叠分区；这种共享不复制四面体。输出 `solid-N` 是派生体编号，不是原始 Solid 身份，原始关系另存于 `sourceSolidIndexes`、`sourceSolidIds` 和完整来源清单。

每个派生网格面保留对应原始 CAD Face 的持久身份、当前面编号和双向映射，支持一个 CAD Face 拆成多个网格面、一个共同网格面关联多个 CAD Face。几何近似参数继续保留，不把离散来源或交叉消除当作严格 CAD 曲面精度认证。

质量索引从坐标重新计算一阶四面体 SICN 和 Jacobian。适配结果继续执行现有完整体面覆盖、逐单元归属、连接方向、重复单元、空间正体积重叠与共形接口检查；预算不足明确失败。普通派生网格采用严格准入，不能含低于封存阈值的单元。明确的诊断模式即使恰好具有合格单元，也不自动提升为普通可用网格。

## 派生文件与发布

材料池内部的 `derive-tetra-mesh` 操作只接受已完成的离散体任务，读取认证原材料后，在空的任务专属暂存目录中生成以下文件。

| 文件 | 用途 |
| --- | --- |
| `mesh.msh` | MSH 4.1 ASCII，保留唯一节点和单元身份 |
| `quality.json` | 与 MSH 相同单元编号、角点、体编号和完整 Body 归属 |
| `render.bin` | 有界分块的双精度网格线，Body 共享同一分区显示数据 |
| `result.json` | 来源、独立准入、材料、CAD 面映射及 Body 和 Face 分组 |
| `manifest.json` | 原始内容摘要、派生文件摘要和默认隐藏状态 |

MSH 的三维物理组分别保留 Body 和原始 Solid，二维物理组保留 CAD Face，交叠体域属于所有相应物理组，不复制单元来表达多源归属。三角面单元先编号，四面体随后编号；质量定位和导出共用相同身份。被明确移除且无目的面的 CAD Face 保留在来源报告中，不创建空的 MSH 物理组。

线程写入并同步文件、计算摘要后，仅返回概要和文件身份。主线程仍须观察同一真实线程退出，核对完整文件集、身份和长度，然后将整个暂存目录一次改名为 `derived-mesh`。取消、超时或文件变化不发布，暂存清理在退出后执行；重复申请不会覆盖已发布文件。原始来源、分区、结果和任务完成记录不改写。暂时占用、权限和空间错误使用 `MESH_ARTIFACT_IO`，不把存储拒绝当作原材料损坏。

MSH、质量和显示文件各限制为 128 MiB，结果与清单各限制为 16 MiB。工程服务另使用既有全局磁盘准入，新派生写入至少需要 416 MiB 的逻辑预留；实际配置可以更高。所有派生与暂存文件计入既有网格存储清点，发布前重新核对空间和来源，退出与发布屏障结束后才释放租约。这不是操作系统磁盘配额或整机峰值认证。

## 工程服务派生登记与读取

已完成的严格离散任务通过显式派生请求生成普通网格，请求只接受唯一 `requestId` 和服务提供的 `sourceToken`，不接受路径、几何子集或临时质量设置。同一在线操作身份重复提交不会启动第二个写入。已经发布的结果只重新核验，不再申请完整写入预留；明确清除派生结果后，下一次请求才生成新文件。

| 接口 | 行为 |
| --- | --- |
| `POST /api/mesh/jobs/:id/derive` | 绑定原始来源，生成或核验派生结果 |
| `POST /api/mesh/jobs/:id/cancel` | 取消活动派生时保留原始任务的 complete 状态 |
| `POST /api/mesh/jobs/:id/derive-discard` | 明确清除派生目录，不删除原始来源和结果 |
| `GET /api/mesh/jobs/:id/quality` | 分页查询坐标质量，保留原始 Body 和定位身份 |
| `GET /api/mesh/jobs/:id/boundary` | 查询 CAD 面关联；仅来源当前时连接当前属性 |
| `GET /api/mesh/jobs/:id/render` | 返回已认证网格线的数据块 |
| `GET /api/mesh/outputs/:id.msh` | 按认证摘要流式下载实际派生文件 |

重新读取会先核对原 CAD、材料及两个原生阶段，再复用同一生成逻辑，只计算预期 MSH、质量、显示、结果和清单的完整字节摘要，不写文件、不调用 CGAL 或 Gmsh。磁盘中的每份文件都必须与预期内容相同；同时改写派生文件及其清单摘要，也不能伪造验收。私有文件身份凭据只留在服务内，不发给页面。网格线请求复用认证时仍核对全部原始与派生文件身份，变化后重新认证；共同读取者不互相修改凭据。

原始记录与完成凭据保持不可变，派生登记从受管目录重新认证后建立。重启只发现并核验已有材料，默认隐藏，不自动导出或重新剖分。派生内容损坏使用 `MESH_DERIVED_ARTIFACT_INVALID`，保留原任务 complete；原始来源损坏仍按原始材料错误处理。文件暂时占用不将任一结果判坏。用户可以明确清除损坏的派生目录，再从原结果生成派生文件，不重算几何或网格。

发布前若几何或使用中的材料变化，则拒绝过期发布。发布后的旧结果可以查询质量，但不能显示、开启显隐或作为当前工程网格下载；边界属性连接明确标记来源过期。取消、删除和停机均等待实际材料线程及容量核验结束，再清理专属暂存与释放租约，不把原始完成任务改成中断。未知下载文件仍返回 404，已知但未派生的离散任务及纯表面任务返回明确的 409 类型错误。

页面工作流和第三版工程包已接入这些材料，工程打开将几何、工程数据、历史与网格登记一起提交或回退。完整重读的工业规模开销、硬停机遗留暂存治理和异常 Windows 退出组合仍需继续验证。

## 页面工作流与材料失效

网格工具提供“CAD 网格”和“交叉修复四面体”两条明确路线，不自动回退。交叉修复默认采用全部工程几何、严格质量、零低质量单元比例和一致材料规则。页面显示当前最多 6 个来源 Solid、4096 个离散三角面和 128 个分区的限制，不将受控范围描述为工业复杂几何已经全部支持。

“联合剖分并准备结果”一次发起新任务，并且仅在本次创建回复已确认、当前工程与选择意图未变化时，为该任务继续准备显示及导出文件。准备完成后仍默认隐藏。历史恢复只读取和认证已有结果；没有派生文件的历史任务需要明确点击“准备显示与导出”。创建或准备回复丢失时只核对原任务，不重复提交；切换历史任务、取消或离开工程会撤销尚未开始的自动后续操作。

结果准备可取消，取消后原始剖分仍为已完成。清理派生文件会立即移除浏览器中的旧显示、质量准入与 Body 网格按钮，并保留原始结果；明确再次准备只生成副本，不重跑原生剖分。已核验网格沿用现有视口、全局开关和每个 Body 的单一网格按钮，共有分区只加载一份数据。隐藏几何后暂停该 Body 的显示，再显示几何会恢复原网格意图。CAD Face 来源报告连接当前面属性，不以网格编号猜测 CAD 面。

后台在认证后的回复中附带原始材料快照，派生文件格式不变。页面与后台共用材料投影规则：修改材料赋值或使用中的材料定义，立即隐藏已驻留的旧网格，并停止当前网格下载；透明度、几何显隐、未使用材料或定义字段顺序不导致误失效。普通 CAD 网格保持原来源策略。

## 校验线程与取消屏障

离散体持久任务的原生输入、体域闭合和来源、四面体坐标质量、公共边界以及结构化失败检查，通过闭合操作注册表进入现有 `MeshArtifactPool`，不新建平行线程池。分区后读取已认证文件组装四面体命令，结果和失败材料也在线程内绑定 CAD 快照后保存；Gateway 不再调用整份协调器做重复几何深度核验。无异步校验边界的独立组件调用继续作为同步参考，原有表面任务路径保持。

每个校验包绑定阶段、原生操作、请求身份和完整内容 SHA256，工作线程只返回认证概要，不回传整份几何。校验快照使用 Node V8 二进制序列化，不再先转成 JSON 再解析为第二棵对象树。实际派发时将专用、固定长度的 ArrayBuffer 独占转交线程，主线程的原缓冲区随之失效；排队期间取消则不转交。共享缓冲区、可变长度缓冲区、未知编码、长度不符或重复派发已转交缓冲区均拒绝，不静默回退。线程内解析后仍执行原来的几何和来源检查，并绑定原始二进制内容摘要。

二进制快照只用于配套 Node 运行环境内的临时线程传输，不是跨版本工程文件格式；原生协议和持久材料继续使用 JSON。输入在第一次等待前固定；校验尚未结束时客户端已占据准入名额，不能启动第二个进程。收到合法校验回复不等于完成，材料池必须观察同一线程真实退出后才交付。原生进程的能力、内存保护、实际退出和完整输出收尾仍由主线程独立核对，不由线程回复代替。

校验沿用一个材料线程、八条排队、1 GiB 老代和 32 MiB 年轻代、180 秒含排队截止，以及与其他重计算共享的 FIFO 名额。校验包最多为 80 MiB 加 8192 字节，认证回复不携带可用网格。取消、关闭或校验截止先退休实际工作线程，不接纳迟到的合法回复；原生内存退出优先，协议错误不会被其引发的终止信号或后续校验超时掩盖。结构化质量失败在校验中被取消时，不发布失败诊断作为终态。

真实后台在“校验已回复、工作线程尚未退出”的受控窗口内验证健康接口可继续服务，并覆盖输入校验前取消、结果/失败校验中取消、校验截止和停机重启。这个窗口验证退出屏障与线程隔离，不是工业几何吞吐、整机峰值内存或所有请求时延的认证。主线程仍处理有界原生协议 JSON 解析、初始命令和上下文克隆、二进制快照序列化与摘要、来源捕获及运行库清点；不能把缓冲区独占转交解释为端到端零复制。线程阶段证据见 `.artifacts/threaded-tetra-result.json`，二进制快照阶段见 `.artifacts/binary-validation-result.json`。

## 校验快照打包测量

同一实际 CAD Box 的三档 Gmsh 结果分别包含 195、5059 和 73360 个四面体。每档使用六个独立子进程交替测量 JSON 参考与二进制快照，各三次；测后核对内容等价，并再次独立检查实际几何。下表为打包耗时和进程 maxRSS 中位数。

| 四面体数 | JSON 耗时 ms | 二进制耗时 ms | JSON maxRSS KiB | 二进制 maxRSS KiB |
| --- | --- | --- | --- | --- |
| 195 | 0.388 | 0.347 | 68868 | 68924 |
| 5059 | 2.103 | 1.015 | 70708 | 70576 |
| 73360 | 23.060 | 9.015 | 97204 | 93364 |

耗时仅包含快照打包，不含原生生成、线程深度校验和快照落盘。maxRSS 在打包完成后采样，也包含此前加载输入的峰值；小样本内存略增，不能据此宣称所有输入都更省内存。测量不代表完整 Gateway、整机、工业脏几何或端到端吞吐，原始样本和逐次记录见 `.artifacts/binary-validation-benchmark-qualified/result.json`。
