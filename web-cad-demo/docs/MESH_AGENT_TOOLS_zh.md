# AI 网格任务工具

网格任务查询、取消和明确恢复接入现有 Pi 原生扩展与 CAD MCP 目录，不新建 Agent 框架。工具绑定会话的当前工程，不接受模型指定其他工程；只返回有界任务概要，不返回网格数组、完整 CAD 来源或输出文件路径字段。候选尚未部署到日常服务。

## 工具及参数

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `mesh_jobs__list` | 可选 `offset`、`limit`、`requestId` | 分页读取当前工程任务；按原请求编号核对恢复尝试 |
| `mesh_jobs__get` | `jobId` | 读取状态、质量准入、来源有效性和恢复凭据 |
| `mesh_jobs__cancel` | `jobId` | 明确取消任务；不删除几何或原网格材料 |
| `mesh_jobs__resume_optimization` | `jobId`、`requestId`、`failedStateToken`、`checkpointToken` | 从检查点建立独立优化尝试，不重新剖分 |
| `mesh_jobs__recover_completion` | `jobId`、`requestId`、`failedStateToken` | 重新校验已有结果并恢复完成凭据，不再执行优化 |

列表默认每页 20 项，最多 50 项。概要保留原状态与错误码，错误文字最多 500 字符；详细诊断仍在原任务中。两种恢复的状态标识必须从当前任务概要原样复制，不能用新的几何修订号、另一个任务或猜测值替代。

Pi 始终使用已有单一建模模式。旧外部客户端若选择只读模式，仍可查询，但不能取消或恢复。只读网格工具可重连已退出的 MCP 桥接进程，不自动重放旧写入，也不会代替 `query_model` 清除既有几何写入核对要求。

## 一次恢复的身份

仅在用户明确要求恢复时，为本次操作生成一次 UUID，写入工具参数的 `requestId`。Pi 原生工具调用记录保留该参数。原失败状态、检查点及新请求编号共同绑定这次尝试；新任务另有 `jobId`，原失败记录和材料不覆盖。

调用超时、取消观察或丢失回复后，返回 `outcome: unknown` 和 `meshRequest`，不能据此断定后台未执行。先用相同 `requestId` 查询列表，再用找到的 `jobId` 查看任务。空列表不证明请求未被受理；不能换一个 UUID 自动重试。桥接层每次调用最多发送一个控制请求，不自动补发。服务端保留原请求的去重记录，重启后仍能核对。

原始失败任务仍可供用户明确建立后续尝试，但这不是一次网络失败的自动重试。当前几何、材料、失败状态或检查点已变化时，由既有工程服务拒绝，不自动替换标识或放宽质量。

## 状态的解释

控制请求返回 `status: accepted` 仅表示已受理，不代表优化完成、质量合格或进程已停止。通过 `mesh_jobs__get` 观察新任务；`complete` 也不等同于可显示的网格，还要查看准入、来源状态和派生状态。恢复工具不会自动生成派生显示文件或显示网格。

完成凭据恢复有独立的 `completionRecovery.state`。核对期间它可以为 `checking`，而原任务的 `state` 仍为 `failed`；不能提前把原失败状态当作此次恢复失败。只有恢复状态为 `complete` 且原任务完成，才能报告恢复完成；`failed` 表示本次核对失败，原结果继续保留。取消同理：`cancelling` 不代表原生进程已经退出。

## 工程接口与边界

概要列表使用 `GET /api/documents/{documentId}/mesh/jobs?summary=1`；单任务使用同一工程路径下的 `/{jobId}`。控制动作分别追加 `/cancel`、`/resume-optimization`、`/recover-completion` 并使用 POST。工程归属在受管访问区内检查，其他工程的编号返回不存在，不泄露其状态或执行控制。既有全局任务接口为现有页面保留。

列表先过滤工程、请求编号并分页，再构造选中项的概要；单任务概要不读取或解析整份网格材料。工具 HTTP 观察最多 10 秒、256 KiB、4096 个片段，拒绝跳转、错误编码、无效分页及回复身份不符。观察截止不表示后台任务已停止。

## 验收范围

最终 2574 项应用回归通过，878 份项目文件前后摘要一致；47 项相关检查和 21 项原生测试通过。真实固定 Pi SDK、MCP 和原生 Gmsh 优化链路覆盖六项流程：目录发现与实际调用、工程隔离、真实进程取消、丢失回复后的单次请求核对、无重算的完成凭据恢复，以及几何不变和结果默认隐藏。模型端为本地协议夹具，不收费，不代表供应商稳定性或语言模型智能评测。

配套前后台另通过 7 项真实浏览器兼容流程。295 份历史/属性文件、4 份 Pi 宿主文件、配置、日常版本选择及默认原生程序离线核对不变，全部隔离验收进程已退出。日常服务不启动或更新，不能据此声称在线工程修订版或在线原生会话被重新验收。

第一份夹具误选质量失败样本，实际工具正确保留 `MESH_QUALITY_REJECTED`；第二份夹具在异步恢复仍为 `checking` 时提前结束观察。两份记录保留，最终验证选用临时进程退出样本，并等待准确恢复终态，产品实现与质量门槛未因此修改。完整应用、原生及真实链路证据分别为 `.artifacts/mesh-agent-full-result.json`、`.artifacts/mesh-agent-native.log` 和 `.artifacts/mesh-agent-live-final/result.json`；准确版本和汇总凭据见 `.artifacts/mesh-agent-result.json`。

开放 Sheet 的产品共形嵌入、Netgen 原生异常、工业语料和规模资源、任意写入点硬停机以及完整开源分发材料仍未完成，不以这批工具接入替代整体工业化验收。
