# 属性继承：版本证据校验

本批修复属性关联读取中的版本/缺损记录风险，不修改 OCCT 几何命名算法，不增加 Agent 工具或新确认弹窗，也不更换日常运行服务。

## 问题与规则

此前解析器可能把缺少 resultRevision 的语义重算记录当成可用映射；普通操作的结果/计算版本同时缺失时，`undefined === undefined` 甚至会误判 current。未来记录被直接跳过时，另一条正常分支可能使整个结果误报完整。空 mapped 记录可能被当删除，损坏容器还可能使读取抛错。这些是可复现的解析边界，不是已证明正常内核经常生成此类损坏数据。

现在优先核对持久 Body/拓扑身份：当前身份直接匹配的关联，不依赖旧历史；需要追溯的关联才检查历史证据。

- 操作结果和特征计算版本必须为正安全整数，结果不能晚于计算版本；若工程摘要提供修订版，还需在该上限内。
- 每条语义重算记录都要有有效结果版本；不能用 mapped 标签替代证明，也不能将未来记录静默丢弃后宣称所有分支完整。
- 来源若显式提供 sourceRevision，必须与规范面/边 ID 一致；目标不能晚于该映射声明的结果版本。旧格式未提供来源版本时仍从规范 ID 读取，不额外发明证明。
- inputPreserved 只接受布尔值。缺少目标的 mapped 记录不是已证明删除；真正当前 OCCT 操作的空删除记录仍可判孤立。
- 空对象、null、非数组容器和未知格式不能使查询崩溃或产生假成功。无法索引的证据意味着旧关联完整性无法证明，保守待复核；独立的当前身份不因此失效。

不确定关联使用 needs-review，原始锚点和属性值不重写；独立证明的候选仍可供用户显式修复。既有单目标歧义、多目标全后代策略、汇合去重和孤立规则不改变。网格属性只接收 active 的准确当前面，因此不确定关联也不会作为物理边界交付给网格。

## 验证

新增 15 项测试覆盖缺失/非法版本、未来分支、目标超前、未版本化删除、空 mapped、坏容器/记录、来源矛盾、非布尔保留标志，以及直接身份兼容和真实网格连接函数。初版 14 项中 12 项在旧解析器失败，反向材料保留 `property-lineage-revision-before.log`；第 15 项后补保留标志回归。原 3000 层测试原本声称 R9 却包含 R3000 目标，现改为真正向前的 3000 次历史，仍验证非递归解析，没有放宽新版本约束。

独立实际场景为 30×20×4 的带孔板，经过两次布尔后绑定端面、孔壁及竖边，再改厚度与孔径。实际测量核对端面面积 100、孔壁面积 30π、对应质心与竖边长度 5；原生属性和类型化属性指向同一当前面。实际 Gmsh 来源连接取得两个正确边界值，Undo/Redo 与便携工程重开保留关联。

缺损/未来版本仅注入已读取的内存副本，不将损坏历史写入测试 CAD 文档。坏证据不能向真实网格附加属性，已证明候选保留，工程 stateToken 和原始锚点文件字节不变。固定后台再次运行同样 8 项，通过时核对解析模块摘要；6 项空宿主浏览器/OCCT/SSE/损坏恢复也通过。准确完整回归、类型检查、lint、版本和日常保护以 `.artifacts/property-lineage-revision-result.json` 为准。

## 未完成边界

本批没有提高复杂曲面在歧义时的唯一自动命名能力，也没有借助距离、面积或序号回退选择。来源本身不足时仍需人工修复。原生 PropertyStore 的底层命名/迁移算法未更改；整个工程全部血缘索引和所有实例的总 CPU/内存预算仍需后续治理。未提供文档修订版的旧调用只能做特征局部版本校验，不冒充完整工程时间界限验证。
