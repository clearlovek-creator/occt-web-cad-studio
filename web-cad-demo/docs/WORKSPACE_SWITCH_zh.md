本说明对应 2026-11-17 的开发候选，未部署到日常服务。精确版本与实际验收见 `.artifacts/workspace-switch-result.json`，不将历史候选的测试数量计入本轮。

后续候选已补充目标 Pi 身份检查、显式旧历史恢复及首次同工程只读推进修正，见 [Pi 历史恢复说明](PI_HISTORY_RECOVERY_zh.md)和 `.artifacts/pi-history-ownership-result.json`；以下保留本批原验证边界。

## 后续候选：同工程读取与跨工程激活分离

当前工程的首次载入、刷新与重新显示改用 `GET /api/projects/:id/view`，携带唯一 `X-Request-Id`，不接受查询参数；服务返回准确的 `workspaceRead`（protocolVersion/operation/documentId/requestId）和完整模型状态。它不启动、停止、认领或互斥 Pi，不创建新工程，也不切换会话。AI 正在讨论不影响读取；几何修改仍由原共享动作队列保护，读取等完整原生操作和持久提交结束，不暴露中间状态。来源文件恢复保护、工程包恢复和原生进程代次检查继续生效。

控制器合并同工程并发读取，保留选择、操作窗口、对话与 Python Run/未知请求恢复材料。回复必须匹配原工程、请求和有效状态；较旧状态、相同序号却矛盾的 token/版本、切换后迟到，以及 A→B→A 的旧代次均不采用。读失败不把错误写到另一个工程；释放页面观察会废止旧读取，网络读取有 60 秒上限。跨工程激活与文件操作尚未结束时，不穿插新的页面读取。

浏览器在构造控制器时读取有效的 tab 工程身份，再退到共享存储与 default，而不是先连接 default 助手再跨工程激活。服务器渲染仍使用稳定空首屏，客户端接管后才采用记住的工程，避免首次身份错配及 hydration 差异。页面恢复不再重复从可能变化的共享存储改写当前工程。不存在的工程不生成空文档，坏检查点不伪装恢复成功；真正首次打开的 default 可读取原生空工程。

这些是后续候选的实现，精确版本与实际验证以 `.artifacts/workspace-read-result.json` 为准，不把旧批统计算入本轮。日常服务不更新。以下激活协议与双侧 Pi 保护仍用于跨工程切换、新建/文件打开后的目标采用，未被只读路径替代。

## 页面行为

恢复工程、新建成功后的目标读取、工程文件打开后的目标读取，以及任务条的“打开目标工程”，均通过同一个来源绑定的激活流程。开始时保留原模型、选择及原生 Pi 历史；页面私有切换归属保持到读取和采用完成，禁止本页面继续追加 AI 消息、压缩或切换模型/会话。

先只读核对来源和目标的全部 Runtime 管理会话，busy、unknown、已有互斥或无效响应均不作为空闲。后台再次准入，不信任先前的页面检查。文件打开在上传前预检，排队后真正执行时再次核对；不会为了打开文件停止原会话。

成功激活必须同时满足：目标身份和模型状态有效；服务返回准确原来源、目标、请求号及来源状态证明；原页面的 documentId/revision/stateToken/stateSequence 没有变化。失败、回复丢失或证明不匹配时保留原页面，不回退到无来源请求，也不重传文件。激活是读取，不创建新几何；用户可在核对后再次显式读取。

未启用任务协议的控制器不再通过旧的直接上传回退来打开工程文件，返回 `PROJECT_OPEN_TASK_REQUIRED`。现用页面已经启用任务协议；这不是取消旧的底层工程包导入 API。

## 激活协议

`POST /api/projects/:target/activate`，可信本机 Host/Origin、无查询参数，`X-Request-Id` 与 command.requestId 一致。

```json
{
  "command": {
    "protocolVersion": 1,
    "operation": "project.activate",
    "documentId": "target",
    "sourceDocumentId": "default",
    "requestId": "workspace-view-fresh-request",
    "sourceRevision": 7,
    "sourceStateToken": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "sourceStateSequence": 9
  }
}
```

状态数值是格式示例，实际来自页面当前工程。后台在共享工程动作队列内核对完整来源基线，再读取目标当前视图；返回 `workspaceActivation` 为归一化后的原 command。不是历史创建/上传回执，更不能由旧的空工程回执拼出当前目标几何。

若本页面没有载入过来源模型，三个来源状态必须明确同时为 null。此路径仍核对双方 Pi，但不读取或修复来源几何，使用户可以离开恢复文件损坏的工程。它不证明来源几何有效或已恢复；有已载入但状态不完整的模型时，页面拒绝静默降级成 null。

旧空 body 激活仍保留为底层只读互操作接口，至少核对目标 Pi；它不带来源证明，当前页面不会采用这种回复来切换工程。未将旧 API 冒充新的来源协调协议。

## 后台互斥

复用 `PiRpcRuntime.withDocumentQuiescent`，最多对来源/目标两个 ID 按固定顺序取得互斥，同一 ID 去重。第二个工程忙碌、竞争、失败或停止时，只释放本次已持有的互斥；反向竞争直接拒绝，不互相等待形成死锁。

激活的互斥覆盖排队、来源核对、目标几何读取和回复数据组装。工程文件任务覆盖实际恢复及完整受保护提交。期间双方新的 Pi prompt/steer/压缩/模型/会话修改与配置启动均被拒绝，原生只读与 abort/abort_retry 仍可用。互斥在服务端操作结束时释放，不是跨网络一直持有到浏览器确认的持久租约。

专用新建任务也核对来源和目标的已管理 Pi 状态，避免只保护来源却忽略目标已有活跃会话。此项不等于证明目标不存在任何旧磁盘历史。

## 验证与未完成边界
