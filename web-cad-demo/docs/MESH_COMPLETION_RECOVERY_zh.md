# 已生成网格的受控恢复

网格已经生成，但完成凭据保存失败时，可以在原任务上重新校验并保存原结果，不必重新剖分。恢复入口放在既有网格任务行内，没有新增确认弹窗；本批仍是隔离候选，没有更新日常服务。

## 在工作台中操作

打开“网格工具”的“任务记录”，找到标记为完成记录保存失败的任务，选择“恢复原结果”。先修正磁盘空间、访问权限等存储条件；恢复只使用这份任务保存的来源和参数，不采用当前面板中临时修改的尺寸、阈值或优化设置。

检查中会禁用重复提交，用户可以关闭工具窗口，后台仍通过原材料线程处理。成功后显示“原结果已恢复”，网格保持隐藏，再通过“查看结果”和既有显隐控制核对。恢复不修改工程几何，不生成新任务或替换成另一份剖分结果。

如果回复丢失，操作改为“核对恢复状态”，只读查询后台，不自动重复恢复。任务列表同时断网时，保留上次记录并标记“未读取”，禁用新剖分和依赖已知列表的操作，但保留只读核对入口。读取有效状态后再决定下一步，不根据按钮超时推测后台失败。

原文件缺失或校验失败会显示恢复未完成，文件和原失败记录保留。只有用户明确再次操作才开始新检查。成功后清除该任务自己的旧失败提示；其他任务的未确认警告不因此清除。

## 可恢复的范围

只支持持久记录为 `failed`、错误码为 `MESH_COMPLETION_UNCOMMITTED`，且仍保存工程来源、结果文件凭据的任务。原网格进程必须已经确认退出。剖分本身失败、未知进程仍活动、任意孤立 MSH 文件或缺少有效失败记录的材料不能通过此入口强行改成成功。

恢复会通过现有材料线程重新核对结果 JSON、MSH、显示与质量文件、来源和既有验收规则，并清除该任务的验收复用记录以进行重新校验。恢复完成不等于网格必然适合工程使用：未通过既有工程质量准入的结果仍受显示和下载保护，不降低原阈值或放宽规则。

本功能不能补造已丢失文件，也不能自动修复任意坏文件。测试中的损坏字节只在独立测试目录中恢复，不是建议用户手工修改任务记录或绕过校验。

## 请求身份与状态

`POST /api/mesh/jobs/{jobId}/recover-completion` 只接受 `requestId` 和 `failedStateToken`。前者是本次明确操作的 UUID，后者是原失败记录准确字节的 SHA256。附带路径、建模参数、额外字段或身份不匹配会被拒绝。202 只表示已接收检查，不表示恢复成功。

任务描述中的 `completionRecovery` 为版本 1，状态为 `available`、`checking`、`failed` 或 `complete`。检查及终态包含操作身份，查询任务列表不启动新检查。校验前、校验后和预算检查后都核对原失败记录，期间变化不能被旧检查结果覆盖。

同一进程内，重复接受的操作共用同次检查，旧失败操作不能在新尝试之后重新启动工作。检查期间删除任务返回冲突；停机等待检查收尾，并阻止迟到的成功检查发布。沿用原材料线程与计算名额，不增加独立恢复服务或 Gmsh 进程。

每个进程最多保留同一任务的 32 次恢复尝试，最多同时接受 32 个恢复工作，仍受既有线程池排队和处理预算约束。达到上限保留材料，不自动清空记录或扩大额度。

## 持久恢复凭据

重新校验通过后，完成凭据使用 `revalidated-retained-artifacts-v1` 依据，记录原失败字节摘要与操作身份。旧状态仍未同步时，重启只在原失败记录准确匹配的条件下采用该凭据；结果文件照常重新验收，默认隐藏，没有再次剖分。

已完成的恢复可以在重启后从凭据核对。进行中的检查身份保存在当前进程内，并非跨重启的接受日志；若服务在凭据发布前退出，原记录仍保持失败，之后需要用户再次明确操作，不自动重试，也不宣称跨崩溃的校验执行恰好一次。

完成凭据和状态增长量继续进入既有存储总量、可用空间及其他任务预留检查，最多 32 MiB 计划记录写入量。恢复不申请一份新的完整剖分磁盘预留，不复制或重新生成原网格。空间不足时保留原失败状态和材料，不发布成功。

旧后台不理解新增完成依据，跨版本数据回退仍需专门核对。本批没有迁移日常 R222 数据、改变默认内核或移动原 AI 会话。

## 交互和验证

入口沿用工作台浅灰表面、蓝色操作和状态色，使用 13px 加粗标题、12px 说明、4px 间距基础和至少 40px 操作控件。状态、原任务信息和恢复动作分层显示，不输出完整 JSON。键盘操作完成后有焦点归处，用户已经移到其他输入时不抢回焦点；参数草稿保留。

后端、客户端与存储测试覆盖明确恢复、请求去重、丢回复、未知列表、跨工作区迟到回复、记录变化、校验拒绝、容量不足和停机。真实 OCCT/Gmsh 测试核对原文件摘要、重开后的质量与 Body/Face 来源保持，以及没有额外剖分。

页面验收使用实际失败任务，包含 1440、900、640 三种宽度、受控丢回复和断网、坏质量文件、明确重新检查、键盘焦点、普通成功路径清除旧错误和重新载入。准确候选、分层数量、反例、截图与日常保护结果以 `.artifacts/mesh-recovery-result.json` 为准。任意孤立材料修复、原历史引用偶发系统错误、工业规模及完整安装升级仍属于后续范围。

本批新增 18 项测试，最终 60 项专项、2056 项应用及 94 项 Python 回归通过。封存版通过 3 项真实接口，其中恢复接口补充核对重启后的质量、Body/Face 归属；9 项恢复页面和 76 项既有兼容流程通过，无页面异常。类型检查和修改文件检查通过，项目仍有既有 26 项检查警告，未重跑 CTest。

反例分别保留未实现时的后端与客户端失败、断网仍显示已知列表，以及恢复成功仍残留同任务旧错误的日志。旧版页面截图也保留，最终验收使用包含两项修正的准确前端，不将前一轮绿色检查当作最后源码的证明。
