## 已验证基础：Pi/MCP 建模任务与主动取消（历史后端批次，未部署）

AI 修改工具不再直接绕过任务登记。MCP 为每次调用生成独立 UUID，先登记原工程/操作/完整参数，再携带原任务头提交同一份已捕获的命令；任务登记、命令及取消都最多 POST 一次。未知登记、旧后台不支持任务或无效凭据均拒绝，不退回直发命令。只读工具继续原查询路径，没有新增模型可调用的取消/管理工具。

- Pi 原生工具的 AbortSignal 由桥接进程发送标准 `notifications/cancelled`，使用准确 MCP requestId。stdio 接收层在普通串行命令之外处理这个控制通知，只影响准确类型和值的活动/排队请求；不会启动另一个几何操作。未发送请求撤回，已发送修改等待原工具的真实终态，不能以发送控制或收到 HTTP 202 作为回滚证明。
- 修改工具持有后台原任务。用户停止时先查询该任务；排队/执行阶段发送一次取消，准备恢复点阶段等待可取消阶段，提交/恢复/已完成阶段不强行取消。取消回复丢失或与提交竞态时不再次 POST，原命令成功结果仍可证明已提交。HTTP 观察不直接绑定用户停止信号，以免把断开请求误当内核取消。
- 执行取消复用现有任务/工程事务：等待实际 OCCT 进程退出，再恢复几何、两套属性及历史。只有任务证明 `cancelled` 且 `execution:not-started` 或 `restored:true` 才返回未执行/已恢复。退出或恢复未经确认保持 unknown，保留恢复日志，工具写入锁要求先显式查询工程；没有自动重发或自动改参数再次执行。
- 提交回复丢失时只读原任务；成功才读取原 `/result` 回执，不能用当前几何拼接旧成功。凭据必须匹配任务 UUID、工程、操作和原调用 requestKey，成功结果的 revision/stateToken 也必须与任务一致。原生结果的 `requestId` 可能来自合成显示时的后续 `document.view`，不能拿它冒充调用方身份；调用身份由持久任务 requestKey 证明。
- 工具结果保留简短结构化 outcome、原任务、请求键及可用参数字段提示。未执行且后台明确允许修正的参数错误仍可反馈给模型；结果未知或用户停止不会变为可自动重试。原生 Pi 的错误结果钩子及现有缩略显示保持不变。
- 任务控制读取默认 5 秒/64 KiB，提交结果观察 150 秒/32 MiB，控制轮询 250 ms；采用严格 UTF-8、有界流及片段数，拒绝跳转。观察截止不是物理工作截止，也不是整个 Node 内存硬上限。清理不等待失控响应流无限结束，不进行收费供应商调用。

新专项 `tests/cad-mcp-modeling-task.test.mjs` 覆盖原输入捕获、身份拒绝、登记丢失、取消竞态、不重发及原回执。`tests/cad-mcp-task-api.test.mjs` 使用真实桥接进程/OCCT，验证退出等待、两套属性/历史恢复、受保护提交和未知退出材料；另通过真实 Pi RPC 加本地确定性模型夹具验证 abort 全链路，不把外部信号模拟当作原生 Pi 验证。

本批没有改前端、原生程序或 Pi SDK，没有新增确认弹窗或部署日常服务。尚未完成浏览器停止状态/任务呈现的成套专项认证、Python 会话归属、新建工程全部入口、旧归属认领 UI/CLI 和受控迁移；持久归属的发布前置条件继续有效。精确固定后端与分层证据见 `.artifacts/pi-task-result.json`；不能把上一版本浏览器数量复用为本版发布资格。

## 已验证基础：Pi 原生会话持久工程归属（历史后端批次，未部署）

Pi 会话 ID 与工程 ID 的绑定现在持久保存，不能在服务重启后借同一会话 ID 把原对话恢复到另一工程。Gateway 在写入会话配置前核对，原生 RPC 启动前再次核对；直接调用 `setContext` 也不能修改工程身份。拒绝改绑不停止原会话、不改写原配置或历史，不自动发送模型请求。

- 新建的空会话目录通过独占创建 `web-cad-owner.json` 建立绑定，并刷新落盘、读回校验。记录包含逻辑会话/工程、随机归属标识、时间、来源及完整性摘要，不包含密钥、模型对话或绝对路径。它不是签名的安全审计账本。
- 归属记录属于逻辑会话归档，可随原目录备份/恢复；不把永久 inode 作为跨恢复身份。读取时仍核对目录和记录的当前文件身份；未知、截断、摘要不符或共享硬链接记录保留并拒绝，不自动覆盖重建。
- **非空旧目录不能自动认领。** 没有归属记录时返回 `PI_SESSION_OWNER_REQUIRED` / HTTP 428；仅凭浏览器传来的 sessionId、旧文件名或 cwd 不能决定工程归属。旧 `.jsonl` 不会被本模块重写。
- 运维核对 `GET /api/pi/session-ownership/:sessionId?documentId=:id` 不创建目录、写配置或启动 Pi。旧历史返回文件数量、字节数及核对摘要，不返回对话内容、文件名和本机路径。核对只接受独占普通 `.jsonl`，最多 256 个文件、单文件 64 MiB、合计 256 MiB，分块计算并核对原句柄/路径身份；未知材料保留。
- 显式采用旧归属使用 `POST /api/pi/session-ownership/:sessionId`，请求必须恰好是 `{documentId, historyDigest}`。再次完整核对同一批文件，摘要绑定所选会话和工程；变化或另一工程的摘要不能提交。该摘要证明材料未变，**不证明材料在语义上属于所选工程**，仍需操作者先核对。正在创建、运行或退役的会话不允许采用；停机关闭采用准入。
- 绑定不同返回 409；材料变化/冲突 409、核对繁忙 409、预算 429、不可用/正在停止 503。接口沿用本机 Host/Origin 限制，拒绝多余查询、字段及任意路径。相同归属可以只读检查，不能通过 API 改绑。

**发布前置条件：** 本批没有迁移日常旧会话，也没有新增认领页面/命令行工具。以后更新前必须确认会话空闲、备份原历史、核对真实上下文和明确工程归属，再按原摘要显式采用并验证恢复内容；若不能证明，不部署此候选或保持拒绝，不能临时绕过保护。Pi SDK 正常恢复可能追加原生元数据，此行为与归属采用本身不改写旧历史应分开验证。

本批只处理 Pi 持久归属，未完成底层 CAD 工具主动取消、Python 上下文切换、新建工程全部入口归属、安装升级恢复及完整发布门槛。真实 Pi 接口专项包含采用前后字节保护、原生 `get_messages` 恢复和实际 Gateway 重启，不调用收费模型；精确候选与证据见 `.artifacts/pi-owner-result.json`。原生程序、SDK 和前端未修改；日常服务未更新。

## 已验证基础：维护清单页面接入（历史批次，专项验证，未部署）

“工程 → 备份管理”现在分为“备份文件”和“维护清单”两个窗口内视图。异常、未发布条目提供“核对异常材料”；正常条目的折叠详情提供只读核对入口，后台判为完整正常备份时明确拒绝异常清理。界面不接收任意路径，材料身份仍来自当前工程目录的原条目。

- 打开窗口、刷新或重新载入页面只查目录和清单，不创建新清单、不清理、不续删。刷新恢复的记录不自动选中；用户明确选择后才显示执行区。新预览失败时不遗留另一份旧清单的执行按钮；只有成功收到对应新清单后才自动展示该清单。
- 核对清单显示固定文件、准确大小、范围和实际状态，摘要/标识折叠且可复制；过期记录禁用执行。选择安全、材料范围、待处理状态与永久删除语义是主要层级，不增加确认弹窗或常驻侧栏。沿用浅色 CAD 令牌、4 px 节奏和至少 40 px 按钮，桌面与 640 px 真实截图复核。

| `POST /api/documents/{id}/modeling-tasks/{taskId}/cancel` | 接收/排队可停止；执行中必须等实际进程退出和完整工程恢复；准备检查点、恢复及提交时拒绝取消 |
| `GET /api/documents/{id}/modeling-tasks/{taskId}/result` | 只返回该任务准确的原始持久提交回执；不重传、不再转换，也不以当前模型冒充旧结果 |

接收使用独立 `pending-step-inputs` 名额，默认两份、合计 512 MiB 暂存预算；单个 STEP 的默认上限仍为 50 MiB（`GEOMETRY_STEP_LIMIT_BYTES`），不是单文件允许 512 MiB。上传等待沿用 `GEOMETRY_REQUEST_TIMEOUT_MS`（代码默认 15 秒，暂存最多接受 600 秒配置）；运行配置可以不同，不能把这些默认值当作大文件性能认证。来源路径在登记时由后台分配；安装采用独占创建、固定大小分块复制、源内容摘要、落盘读回及转换前重校验，不在 Gateway 构造整份上传 Buffer。执行期间可能同时保留上传暂存和来源副本；永久接受的来源不在暂存配额之内，这不是全应用总磁盘或总堆内存限制。无任务头的老 STEP 接口仍兼容旧传输路径，不宣称它已经流式化。

取消接收只有关闭本次上传所有权并清理不再使用的材料后才报告完成。转换取消只有原进程实际退出、几何/原生属性/类型化属性/变量/历史完整恢复后才报告已取消。返回结构化失败或抛错均仅在事务回滚被确认时附加内部证明；任务协议白名单保留 `restored:true`，旧 HTTP 失败对象不增加可枚举证明字段。准备阶段失败不能仅凭 `failed` 标签推断工程未变。`unchanged` 只来自未开始执行、已证明取消或完整回滚，不来自“请求失败”。

成功导入保留来源；结果未知、退出未确认、恢复未完成或保留材料被修改时保留证据。清理按身份和内容检查，不用文件名/长度/时间戳假定文件仍归本任务；发生同大小内容替换也不会删除后来文件。此实现不是同用户恶意文件替换的原子安全边界，也不提供未知来源的自动回收或完整维护界面。

STEP 旧进度报告保留给完成统计及兼容接口；任务管理的活动/失败/未知状态只使用公共任务条，避免两套取消/进度控制。文件名随同任务身份显示，长名称换行，原有浅色令牌、40 px 控件与折叠详情不变。显式取消与关闭窗口是不同操作；刷新只读恢复原任务。

验收入口：`npm run test:ui:step`（固定候选和真实 OCCT）、`tests/step-import-task-{api,client,status}.test.mjs`、`tests/step-upload-inputs.test.mjs`，以及原任务/工程事务专项。`npm run test:ui:step:legacy` 仅覆盖旧版页面报告。重任务进程隔离、工程文件/Pi 统一取消、暂存维护及工业规模认证仍未完成。

2026-11-16 本批最终候选已完成 1341 项自动测试、15 项原生测试、166 条浏览器流程及 27 项服务检查。前后端版本、源码/原生/测试清单摘要、首次失败与修复后的日志、日常工程/Pi 上下文不变的审计统一封存在 `.artifacts/step-tasks-result.json`。该文件认证的是候选，不是部署记录；日常服务仍运行此前获批版本。

## 目的与边界

旧 Gateway 即使 PID 不变，按需启动的查询线程仍会从工作区读取新脚本，导致一套运行实例混用多个开发版本。受管生产入口从独立快照启动；当前默认 V3 发布封存项目代码、OCCT/Gmsh 的 PE 静态/延迟导入依赖，以及 Pi SDK 源码运行闭包。主进程、后续质量/材料查询线程、自有 CAD/Pi 适配器与原生 Pi 使用同一份已认证候选，不从开发仓库临时加载新版 SDK。

| 范围 | 当前处理 |
| --- | --- |
| Gateway、共享 MJS、查询线程、CAD MCP 服务与 Pi 扩展 | 复制、语法检查、清单/长度/SHA256 核对，固定版本加载 |
| Pi 原生 SDK | V3 保留源工作区路径，封存锁文件匹配的已安装运行依赖、入口、配置及随包许可；不执行 SDK 构建或安装脚本 |
| OCCT/Gmsh、来源检查/替换及目录锁辅助程序 | V2 封存入口及递归 PE 静态/延迟导入 DLL；geometry/mesh 分目录，不能合并同名 OCCT DLL |
| 原生动态插件/数据文件 | 不按 PE 导入表发现；尚未建立通用插件/资源依赖认证 |
| Node、系统运行库 | 外部安装；项目快照要求 Node 精确版本一致 |
| 工程、历史、Provider、密钥、用户资源 | 留在原数据/配置位置，不复制到发布目录 |

这仍不是完整可移植安装包，不提供 OS 写锁、签名信任链或抵御同一用户恶意程序的保证。JavaScript 构建校验引擎解析出的内置/相对静态模块依赖；原生构建解析 PE32+ AMD64 静态/延迟导入，不代表任意运行时 LoadLibrary、插件或动态资源都已打包。Windows 系统 DLL 只保留明确系统清单/API-set 声明，不复制系统文件。SDK 对照锁文件检查包身份与依赖元数据，并封存本机实际安装字节；这不是 npm 原始压缩包完整性、供应链签名或许可证合规认证。前端生产运行器仍使用工作区安装的 vinext，Node 亦须外部安装。对外分发前仍需完成第三方许可、随包声明、动态资源和完整干净安装核查。

格式实现依据 [Microsoft PE Format 的导入目录及延迟导入定义](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#import-directory-table)，当前策略只接受 RVA 型延迟导入，不猜测旧 VA 型地址。

## 构建及选择

```powershell
npm run build:backend
```

默认在 `.backend-releases/` 创建 `backend-<时间>-<UUID>`，先使用专属暂存，再核对源码复制前后清单、逐文件摘要及所有 MJS 语法；不执行模块进行语法验证。验证成功后更新 `selected.json`。项目代码最多 2048 文件/32 MiB；原生运行库另有总计 2048 文件/512 MiB、单映像 64 MiB 上限。SDK 单独限制 50000 文件/512 MiB、512 包、单文件 64 MiB、目录清点 150000 项和清单 16 MiB。发布排除 `.env`、`.data`、`.pi`、`.npmrc` 和用户配置；只纳入经过清点的 SDK 运行依赖，不复制整仓库 node_modules。失败不会替换原选择，也不会重启服务。

构建从 `GEOMETRY_WORKER_PATH`、`MESH_WORKER_PATH`、`GEOMETRY_SOURCE_INSPECTOR_PATH`（如有）或默认构建目录选入口。辅助程序默认取几何入口同目录；DLL 按显式的应用目录、OCCT 安装目录和 MinGW/Gmsh 目录递归解析，不从任意继承 PATH 猜依赖，不复制整套 MSYS。可通过 `OCCT_BIN` / `MINGW_BIN` / `GMSH_BIN` 指定对应构建输入。封存后逐文件再检查源输入，缺失、损坏、非 x64 或不支持的导入地址直接失败。

上述构建输入取当前进程环境，不自动读取 `.env`，也不将配置或密钥写入发布包；如果原来仅在 `.env` 指向自定义 Worker，构建前需显式设置对应进程环境变量，并核对候选清单/能力。发布后的 `.env` Worker 路径不能替换已封存入口。PE 导入闭包也不等于导出转发、运行时插件和数据资源的完整依赖认证。

`native/geometry/` 存建模内核及三个辅助程序，`native/mesh/` 存 Gmsh；它们可能依赖不同版本的同名 OCCT DLL，保持各自闭包，不去重合并。这两组都使用完整文件清单校验。

隔离候选可使用：

```powershell
node scripts/build-backend-release.mjs --release-root .artifacts/candidate-backend-releases
```

发布目录不能手工编辑。启动器先校验选择/指定版本，随后从快照自己的启动入口加载；缺失、损坏、Node 不匹配或身份不符时拒绝，不回退工作区。启动器清除继承的旧后台/原生凭据及 Node 预加载/模块搜索路径；V2 启动入口随后强制采用清单中的五个原生角色路径与两组运行库目录，覆盖继承或 `.env` 的旧 Worker 路径，不把打包版变成混用版。

V1 仅项目代码的旧版本仍可显式回退，健康范围保持 `project-code-only`，不会被重新解释为已封存原生库。`--project-code-only` 显式构建 V1；`--external-pi-sdk` 显式构建 V2，保留外部 Pi CLI。两者与 `--pi-sdk-root` 互斥。生产默认命令产生 V3，不能将兼容测试产物当作完整 SDK 发布证明。

## Pi SDK 封存与运行隔离

默认 SDK 输入为相邻 `../pi`，也可使用构建进程的 `PI_SDK_ROOT` 或 `--pi-sdk-root <目录>`。当前支持已验证的 `pi-monorepo` 源码布局与 v3 安装锁，不是任意 npm SDK 的通用打包器。按已安装的 dependencies、optionalDependencies 和 peerDependencies 递归清点；必需依赖缺失或包版本/元数据不符即拒绝，缺失的可选包记入清单。工作区别名解析到已知源码后复制为普通目录，保留 `packages/...` 与嵌套版本，不生成发布链接。包内链接、硬链接及越界配置拒绝。

实际 Pi 0.84.2 闭包为 48 包、6769 文件、54558119 B（约 52 MiB）。没有先编译第三方 SDK：固定 tsx 与 tsconfig 从保留的源码路径运行。将源码工作区迁到 node_modules 会使 tsx 不采用原路径映射，因此不能随意扁平化。原锁保存为 `source-package-lock.json`，只用于溯源，不是重装配方。SDK 示例/文档/许可随包保留，但示例额外可选依赖、用户扩展和任意运行时动态加载不因此获得完整支持。

V3 忽略外部 `PI_CLI_PATH`，采用快照入口，并固定 `PI_PACKAGE_DIR`、tsx 配置与缓存目录；清除继承的 Node 预加载以及 JITI/TSX/ESBUILD 覆盖项。设置、模型配置、会话与缓存仍写入数据区。没有显式用户 `PI_CLI_CWD` 时，Pi 工作目录为 `<data>/pi-workspaces/<projectId>`，不把发布目录当作可变工作目录。显式用户工作目录属于外部资源上下文，不由 SDK 清单认证。

**工作目录变化不是自动会话迁移。** Pi 0.84.2 在显式 session-dir 下的 `--continue` 按会话头 CWD 过滤；从旧 SDK 仓库工作目录改为工程隔离目录时，旧 JSONL 即使仍在也可能被跳过并打开空会话。升级前须记录实际原生上下文和完整历史摘要；不能只验证进程在线。需要跨 CWD 时使用原生 `SessionManager.forkFrom(sourcePath, targetCwd, sessionDir)` 保留全部非头记录，并在空闲状态切到迁移副本；原文件保留、parentSession 指回来源。会话 ID 会变化，不能伪称原地继续。不要用全局旧 `PI_CLI_CWD` 关闭工程隔离，或手工改 JSONL 头。2026-11-16 的实际恢复和限制见 `CONTROLLED_UPDATE_20261116_zh.md`。

嵌入 CAD MCP 的 `CAD_GEOMETRY_API_URL` 强制指向本 Gateway 的实际本机端口，不继承默认 8788 或外部旧地址。独立端口验收会故意将继承地址设为不可连接的端口 1，证明 SDK 不会误读/修改另一套日常工程。外部独立启动的 MCP 仍需自行配置目标地址。

## 几何进程中断与排队预算（2026-11-16，独立候选、未部署）

几何 RPC 已由独立 `NativeRequestChannel` 管理，每个对象只属于一个具体 OS 子进程。回复按 `requestId` 匹配，成功回复还核对协议和工程 ID，不以 FIFO 下一个槽位猜测。复用现有 `BoundedJsonLines` 字节分帧器，逐行预算、分块 UTF-8 完整解码；错误编码、无主/重复回复、错误工程、部分写入和输出异常均使该进程代际退役，不将后续回复错配。

中断顺序是：立即禁止旧通道接收/发送 → 保留原待决请求 → 请求停止具体子进程 → 观察同一个句柄确实退出 → 清除旧代际 → 拒绝原调用并进入完整工程回滚。不是“调用 kill 就当停止”。退出核验超时标为 blocked，旧句柄实际退出前不启动替代进程、不向它发送恢复；迟到回复即使 JSON 合法也丢弃。旧句柄、旧计时器和旧回调不能影响新进程。

项目事务还捕获执行代际，从 action 开始一直核对到完整检查点发布前。内核先返回成功、通道随后失效时，不能在新进程恢复原基线后把它误当作成功修改提交。`command()` 也拒绝返回前代际已变化的结果。只有几何、类型化数据和历史全部回滚成功，错误才附带 `projectRollback:{documentId,confirmed:true}`；失败保留 prepared 日志并阻止后续修改。STEP 超时在已证明回滚后记为 failed，否则仍保留 unknown 与上传来源供恢复，不以超时错误码单独推断最终状态。

原生通道预算（均为每个几何进程的 RPC 传输预算，不是 OCCT 堆内存上限）：

| 配置 | 默认 / 上限 | 行为 |
| --- | --- | --- |
| `GEOMETRY_WORKER_PENDING_REQUESTS` | 64 / 256 | 已发送未完成的请求数；超限在写入前拒绝 |
| `GEOMETRY_WORKER_PENDING_BYTES` | 16 / 64 MiB | 待决请求序列化 UTF-8 总字节；完成或退役后回收 |
| `GEOMETRY_WORKER_REQUEST_LIMIT_BYTES` | 4 / 8 MiB | 单次 native 请求，不替代 HTTP JSON/上传上限 |
| `GEOMETRY_WORKER_STARTUP_TIMEOUT_MS` | 未设时取 worker 时限与 5000 较大者，最多 300000 | 握手单独计时；示例显式设 10000 |
| `GEOMETRY_WORKER_STOP_TIMEOUT_MS` | 5000 / 30000 ms | 退出核验截止；超过不代表进程已退出 |
| `GEOMETRY_WORKER_TIMEOUT_MS` | 原有操作时限 | 包含在 native 串行队列中的等待，不自动重放 |

`/api/health` 的 `runtime.workerChannel` 公开状态、排队字节/数量和预算，不包含请求参数、工程内容或密钥。排队满返回 429，单请求超限 413，协议错误 502，超时 504，退出未确认 503；`WORKER_INSTANCE_CHANGED` 表示结果不能跨代际采用。Native 错误不会要求模型自动调整参数重试。

内部通道支持显式 `AbortSignal`：发送前取消不启动/结束进程；发送后取消要退役该共享进程并等待退出，再回滚受影响事务。这一能力尚未接到产品建模任务取消 API/按钮。**浏览器断开、关闭参数窗口不自动取消已发送修改**，保持已有幂等恢复约定；不是已经完成前端取消功能。当前仍共享一个几何进程，跨工程 pending 调用会一起被中断，而非按单任务 OS 隔离。

停机最后阶段会继续持有工程目录写锁，直到跟踪到的来源替换、几何及每个网格任务的原生句柄真实退出。真实集成故意拦住已经执行两体建模的回复及进程结束，验证原工程一体、两套属性、历史和身份恢复；另验证 STEP 超时后的 failed/unknown 区分、退出未确认日志保留及服务重启恢复、停机时第二个 Gateway 无法抢占目录、有效原生回复紧跟坏帧时不发布假成功。故障门只在 `tests/fixtures`，产品没有测试开关或任意执行入口。

这是总资源治理的中断基础，不是最终资源隔离：该批本身不提供 OCCT 内存硬限制，后续候选见下一节。应用总资源、重计算任务 API/用户取消入口、重任务隔离、更多 Pi/插件派生过程的完整所有权资格仍需推进，不能把排队字节上限说成内核内存上限。

## 几何内核提交内存硬限制（后续候选，2026-11-16，未部署）

新内核在进入 `DocumentManager` 和读取任何工程 RPC 前创建自己的 Windows Job Object，设置 `JOB_OBJECT_LIMIT_PROCESS_MEMORY` 与 `JOB_OBJECT_LIMIT_JOB_MEMORY`，将自身关联并读回核对两个限制。限制对象是系统计算的提交内存，不是 RSS/工作集采样，也不是 STEP 文件大小估算；提交拒绝由操作系统执行，通知线程不是硬限制本身。依据见 [Microsoft 的扩展 Job 限制说明](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)。

配置为 `GEOMETRY_WORKER_MEMORY_LIMIT_BYTES`，默认 2 GiB，允许 128 MiB 到 8 GiB 的整数字节值；0、空串、浮点、科学记数和越界拒绝，不能用来关闭保护。Gateway 先验证配置再建立持久 Store；本批仅 Windows 通过编译与运行资格，其他平台不静默退回无保护模式。示例配置已补齐，用户实际 `.env` 未修改。内核在进程入口才安装保护，**不覆盖 DLL/CRT 装载及安装保护前的启动峰值**。

启动握手必须由实际进程声明 `processResources`：版本 1、依据 `windows-job-commit-v1`、已执行标记、与 Gateway 配置完全相同的进程和 Job 字节限制及已知失败策略。缺失、错配或旧内核即退役并标为永久 blocked，不自动重启，也不回退默认旧二进制。非 health 工程 RPC 等待这一握手通过；不是先排一条 health、再同时把修改交给未经认证的内核。健康状态只在该代际有效时公开 `resourceGuard`，并区分配置值与实际 enforced/blocked/pending。

通知及分配失败策略：

- Job 的进程/总提交限制消息到达时，以退出码 86 退役；`operator new` 的失败处理器、OCCT `Standard_OutOfMemory` 或显式分配失败以 87 退出。紧急路径不分配字符串、不使用 iostream，也不写 stdout/stderr，直接终止自身所在 Job/进程；日志管道堵塞不能阻止保护动作。父进程在观察实际退出后按权威退出码记录诊断。
- Microsoft 明确指出相关 [completion-port 通知不保证交付](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_associate_completion_port)。所以不把通知当作硬限制，也不承诺每个第三方内部分配失败都能被同一通知捕获；策略名称明确是 `retire-on-memory-event-or-allocator-failure-v1`。硬提交限制始终独立生效，未到达通知不意味着没有发生拒绝。
- 87 表示受限预算下的分配失败，也可能是系统内存不足，不谎称一定触及本 Job 上限。保护无法建立/验证为 88，配置非法为 89；两者阻止无保护自动重启。EOF 可能早于 OS exit，此时先观察原句柄退出，不立即额外终止并覆盖内核自行退出的资源码；达到退出截止仍未退出才进入 blocked 并请求停止，实际退出前仍不得恢复或替换。确认退出后保留 86/87/88/89 的权威分类，不用“管道关闭”掩盖资源原因。
- 内存不足不在内核本地事务里尝试昂贵重放，而由上一节完整持久检查点恢复。诊断、STEP 合法性、面坐标等宽泛 catch 不将 OOM 吞成几何无效或引用失效。Gateway 映射 `WORKER_MEMORY_LIMIT` / `WORKER_MEMORY_EXHAUSTED` 为 503，禁止模型自动重试；只有完整回滚成功才附 `projectRollback.confirmed`。原完整工程本身无法在预算内恢复时，仍会保留 journal 并阻止修改，不虚报恢复成功。

实际验证包含：同样 160 MiB 分配在 256 MiB Job 中成功，在 128 MiB Job 下拒绝；复杂 B-spline STEP 的相同字节在 128 MiB 下退役并完整恢复原 Box、原身份、原始/类型化属性、历史和真实体积，在 1 GiB 下成功导入 128 个命名面。恢复后的新进程仍按原 128 MiB 预算执行，之后显式新建模型正常。错误声明试验只在测试夹具重写握手，不冒充完整旧 Windows 内核资格；确认只发出 health，不发送任何工程 RPC且不重启。非法 Gateway 配置在 Store/原生进程之前拒绝。

兼容要求：此 Gateway 必须与具备该能力的新内核一起打包；不要只切换 JS 或继续指向保留的旧默认编译目录。真实保留的无保护旧内核验证为 blocked；具备资源保护但仅声明旧建模能力的测试进程仍可执行其基础功能，不能因此获得高级工具权限。日常旧冻结版本仍保持原样。完整工程格式、拓扑命名与 SHA 算法没有因资源上限而迁移。开发/测试仍使用登记的 `build-import-naming` 与 `build-artifacts` 独立对，不覆盖日常二进制。

边界继续保留：这是几何工作进程操作阶段的提交预算，不是 Gateway/Gmsh/Pi 的总内存限制，不是物理 RSS 上限；当前一个几何进程仍共享多个工程，全部常驻文档也计入预算。通知辅助退役不等于所有插件/派生进程生命周期已资格验证。任务隔离、完整累计资源控制、取消 API/按钮、工业规模及所有 Windows 环境仍需继续验证。

本批验收：完整 1232 项自动测试通过（无跳过）、15 项原生 CTest（14 几何 + 1 网格）、18 条固定 V3 前后台浏览器流程和 27 条受管服务兼容流程通过，类型检查通过。服务脚本使用私有 V2 快照及外部 Pi 确定性夹具，不作为 V3 SDK/付费供应商在线资格。饱和 stderr、EOF 先于 exit、真实 STEP 小预算失败/大预算成功、恢复后继续建模均有专项；最终源码/候选/测试/日常工程与会话审计摘要见 `.artifacts/native-memory-result.json`。该报告只证明列出的范围，不代表整套工业前处理目标完成，也不表示已更新日常服务。

## 共享几何进程的工程操作准入（后续候选，2026-11-16，未部署）

原先只按工程串行：A 的原生调用超时并等待退出/回滚时，B 仍可能已经进入同一个进程。原生请求字节预算不能防止这种跨工程事务交织。候选改为 `DocumentActionQueue`：经过 `serializeDocument` 的工程操作按全局 FIFO 使用唯一执行名额，涵盖加载、操作、检查点发布、失败后的完整事务回滚；不是某条 RPC 一返回就放行下一工程。现有单工程顺序自然保留，后台健康、加载状态和工程目录查询仍不经过几何队列。

| 配置 | 默认 | 范围与语义 |
| --- | --- | --- |
| `GEOMETRY_ACTION_QUEUE_LIMIT` | 64 | 1..256，所有工程尚未开始的操作总数，不含活动项 |
| `GEOMETRY_ACTION_DOCUMENT_QUEUE_LIMIT` | 16 | 1..64，且不超过总数；未显式设置时取 `min(16, 总数)` |
| `GEOMETRY_ACTION_QUEUE_TIMEOUT_MS` | 120000 | 1..600000 毫秒，只限制等待，不中断已执行操作 |

队列配置在工程目录写锁和持久 Store 建立前严格验证，不接受 0/空串/浮点/科学记数来绕过预算。超量返回 429 `DOCUMENT_ACTION_QUEUE_LIMIT`，等待到期返回 504 `DOCUMENT_ACTION_QUEUE_TIMEOUT`；均携带 `execution:not-started` 和 `retryableByModel:false`，不自动重发。未开始的项从队列移除并释放引用/计时器/取消监听，不留下长 Promise 链等前项结束。停机立即拒绝全部等待项，仍等待活动操作及其恢复结束；实际内核退出门禁和目录写锁规则不变。

类级 `AbortSignal` 可取消等待项；开始后不据 abort 自动释放名额，执行方必须等真实停止和恢复后才结束 action。当前服务器尚未向产品任务 API/按钮接入此信号，不可称为用户已经能主动取消建模。关闭参数窗口、浏览器断线仍不取消修改。重入同一队列直接拒绝而非死锁；不能据内部重入错误把外层整个请求说成从未执行。`health.lifecycle.documentActions` 仅报告活动/等待数量、涉及等待工程数、配置与完成/失败/拒绝/到期计数，不输出工程 ID、参数或待执行函数。`completed` 表示 action 正常返回（可能返回业务失败结果），`failed` 表示抛异常，不作为几何操作成功率。

真实隔离工程测试验证：A 已执行但扣住回复时，B 不得发送任何工程原生请求；A 超时并扣住实际退出时，B 继续等待，直至 A 在新进程完成原检查点恢复；队列超限/等待到期的命令没有原生执行且工程历史不变，健康检查仍能响应。另有 FIFO、每工程/总数、取消监听释放、活动取消不提前放行、关闭排队及重入专项。第一轮夹具错误遗漏 `fixture.` 事件前缀，修正后用原断言通过，保留失败日志。

本项是共享进程的正确性屏障和数量准入，不是多进程隔离或实际堆内存硬限制。长任务仍会延后其他工程请求，不能把单名额包装成并行性能提升。此节描述数量准入批次，后续输入预算和公开任务控制见下一节，不表示日常服务已替换。

## 交互式任务控制与输入准入（2026-11-16 受控上线）

### 执行与取消边界

工作台交互式 `/api/commands` 修改及 Undo/Redo 先登记服务端 UUID，再以 `X-Cad-Task-Id` 提交冻结输入。记录绑定工程、操作、请求键、原始输入摘要及历史结果指纹，不保存命令参数或 Provider 密钥。阶段为 `reserved → queued → preparing → executing → committing → succeeded`。执行取消先停止内核，再完整恢复工程；只有确认原进程退出及几何、两套属性和历史恢复后才报告 `cancelled`，不能证实时为 `unknown` 并保留事务证据。

排队可取消；准备恢复点、提交和恢复阶段不可取消；完成后的取消不执行 Undo。停止/恢复未结束仍持有完整工程动作名额。恢复先移除中断信号，再写阶段报告，报告故障不能阻止恢复。状态区沿用浅色工作台、默认折叠详情。关参数窗口、断网不是取消；刷新只查询，丢回复只读原回执，不重发。当前范围仅交互式单命令和 Undo/Redo，排除 `document.naming.upgrade`；批量、STEP、工程文件及 Pi/MCP 主动取消仍待接入。既有 STEP 阶段记录保持独立。

### 本机接口与恢复

任务控制校验本机连接、Host 端口、受信任 Origin 及工程身份，控制请求不能附带命令参数：

| 请求 | 行为 |
| --- | --- |
| `POST /api/documents/{id}/modeling-tasks` | 唯一字段 `command`；仅登记 |
| `GET /api/documents/{id}/modeling-tasks` | 最多 100 条，优先活动及未确认任务 |
| `GET .../modeling-tasks/{taskId}` | 查询阶段，不重放 |
| `GET .../{taskId}/result` | 读取原始成功回执 |
| `POST .../{taskId}/cancel` | 空对象；202 不代表取消完成 |
| `POST .../{taskId}/abandon` | 空对象；仅清理本进程仍未接收的 reservation，不能取消已接收任务 |
| `DELETE .../{taskId}` / `DELETE .../modeling-tasks` | 显式清理已完成记录，不改几何/历史，不删活动或未确认任务 |

后台重启后，旧所有者未完成任务仅在历史准确请求键及指纹证明成功时报告成功，否则未确认，不重放。`modeling-tasks` 默认最多 2048 条、单条 32 KiB；当前所有者最多 65 条等待登记/执行任务。满额明确拒绝，不自动删除未知结果。回执过期返回 410，应载入当前工程，不换键重试。任务文件不是签名的防篡改审计账本，不能据此宣称恶意本机程序、机器断电或所有第三方插件已认证。

### 排队输入与工程包暂存

`GEOMETRY_ACTION_QUEUE_BYTES` 默认 64 MiB、最高 256 MiB，限制等待动作已计量的序列化输入。单条修改、预览及批量步骤等入队前计量；超限返回 `DOCUMENT_ACTION_INPUT_LIMIT`，未执行内核。活动项不计等待预算，仍受独立 HTTP/内核预算约束。此处不是所有闭包、整个 Node 堆或全程序 RSS 的硬限制。

工程包打开以独占文件流式写入 `pending-project-inputs`，计算摘要并刷新，获得执行名额后才有界读取，排队仅保留 128 字节描述预算。默认合计 512 MiB、两个名额；接收截止遵循 HTTP 请求预算，最高 600 秒。声明长度提前占位，无长度按单包最大值占位，完成后按实际长度计量。读取核对普通独占文件、设备/文件号、纳秒时间、长度与内容摘要；变化拒绝并保留。

成功、普通失败或排队到期释放自身确认未变的暂存文件；修改、替换、硬链接、未知文件或清理故障保留并占预算，健康字段 `lifecycle.projectInputs` 提供诊断。启动不猜删残留。尚无安全维护界面；容量耗尽应先受控停机、备份并调查，不应运行中清空目录。STEP 上传尚未由此改为流式暂存。

专项包括 `tests/modeling-task-{service,api,client}.test.mjs`、`tests/project-input-admission.test.mjs` 和 `tests/pending-project-inputs.test.mjs`。`scripts/verify-modeling-tasks.mjs` 验证实际内核执行后取消、退出等待、完整恢复、草稿保留、提交保护、丢回复/刷新不重放及显式记录清理。故障闸门仅在私有测试夹具，产品没有注入入口。统一重任务隔离、总资源治理及工业规模认证仍待推进。

### 下一候选：整批任务控制与原始回执

工作区后续代码已将交互式原子批次接入同一任务服务，日常已运行版本不因此自动更新。任务登记采用 `command.operation = "project.batch"`、稳定 `batchId`、工程和完整 `steps`；实际修改只发往 `/api/command-batches`，携带原任务头及同一冻结输入。批次不是发给内核的新几何命令。预览、Undo/Redo、STEP 和维护类命令不能混入修改批次，整批及每一步均在登记前验证。

一个批次只占一个完整工程动作名额，取消中间步骤会退役实际内核并恢复整批的几何、变量、坐标系、原生属性、类型化属性及历史。已经完成的步骤不能再报告成功，已经尝试但回复未到的步骤不能谎报为从未执行；未开始步骤明确标注。退出或恢复未经确认时，不发布“已取消/已回滚”的步骤列表，保留事务和未知任务。最后一步执行完成后、输出检查点开始前进入不可取消的提交阶段。

受控批次除已有分步去重材料外，在同一次历史提交中保存 `project.batch` 的整批原始回执，包含当时工程视图、属性、状态标识、批次 ID 和全部步骤结果。指纹由有序步骤 ID、操作及规范化语义指纹组成；任务登记另外绑定原始请求摘要。丢回复、重启和任务记录重新登记都只能读取准确回执，不能把当前模型拼接到旧步骤上冒充原结果。原始回执的状态序列较旧时，前端不会覆盖较新的当前工程。

老批次只有分步记录时，原无任务入口仍保留兼容重放行为；不能给它补造不存在的整批回执，新任务入口会明确拒绝并要求核对当前工程。回执仍受最近 100 条/配置字节窗口限制；每个受控批次会额外占一条记录，不保证永久 exactly-once。分步与整批材料合计必须同时装入保留窗口；完整批次 JSON 还为任务/HTTP 包装预留 4 KiB，超过预算整批回滚，不提交无法查询的半份结果。

新增 `tests/modeling-batch-task-api.test.mjs` 使用真实内核验证排队/部分执行取消、提交保护、属性/变量恢复、旧回执拒绝、容量回滚、实际退出未确认及提交后终态报告前的真实 Gateway 退出。浏览器以 `MODELING_TASK_BATCH_UI=1` 扩展现有验证，检查缺失变量+几何的单事务、任务栏键盘取消、窄窗、草稿、丢回复、刷新及记录清理。补充变量面板在任务期间禁用局部取消和输入，统一使用任务区的取消入口，执行前清掉旧错误；不新增右侧面板或确认窗。

此候选仍未接入 STEP、工程包及 Pi/MCP 工具的统一取消，未提供独立重任务进程，也不把批次状态当作仿真求解能力。后续受控更新必须单独完成工程空闲、备份、回退和上线核对，不因源码测试通过自动发布。
