# 大工程属性关联的按需解析与共享预算

本批处理属性查询的辅助计算，不更改几何命名规则、属性值、原始锚点、工程格式或 UI。日常服务不更新。

## 行为

原实现总是先扫描全部特征历史，再验证关联当前身份；每条锚点各有一份 10000 分支限额，全部实例合起来仍可无限重复展开。新实现先检查当前持久身份，只在确实需要追溯时建立历史索引；纯工程属性完全不读取几何和历史。属性列表接口复用同一次解析结果，避免同一请求算两遍。

每次调用共用一份确定性额度，计费在读取下一记录或保留下一节点之前进行；缓存有独立容量，不跨请求或修订版复用。类型和实例沿用已验证 Store 的 1000/10000 数量范围，集合仍最多 256 个锚点。

| 辅助计算资源 | 硬默认上限 | 超限语义 |
| --- | ---: | --- |
| Body 元数据记录 | 50000 | 未读取 Body 是未知，不是假删除 |
| 特征记录 | 20000 | 历史索引不完整，旧关联不能判完整 |
| 操作/重算记录 | 100000 | 保留旧锚点，需复核 |
| 整次工作计数 | 500000 | 包括索引、遍历、环检查及诊断组装 |
| 估算保留状态 | 32 MiB | 约束索引/图/缓存/诊断的记账值，不是 V8 堆或 RSS 硬限制 |
| 候选/成员诊断槽位 | 262144 | 不把截断的集合当完整 active |
| 解析缓存条目 | 4096 | 容量满后替换，不扩大到全部实例 |

内部调用可降低限额以测试失败路径，不能升高硬默认值、设为零或使用未知配置。生产接口不暴露此选项。原单锚点 10000 条记录/目标限制继续保留。

额度不足时，已独立证明的当前身份仍可正常使用；未完成关联为 needs-review，而非 orphaned 或部分 active。原始值和锚点不重写，资源不足的集合不会以少几个成员的形式悄悄生效。单引用和集合最多列出 256 个候选，并明确标记截断；候选计数在截断后是已知下界，不冒充所有未扫描后代的精确总数。

公共读取增加 `associationResolution`，包含本次计数、额度、触发项、是否建索引及缓存峰值。它是处理资源状态，不代表所有属性都有效。Store 归一化会去掉该诊断，读取不会写进属性文件、撤销历史或工程包。已有面状态和网格连接仍只采用实际 active 的准确当前目标。

## 验证与真实性

新增 17 项测试，覆盖无需历史、共享计数、提前准入、缓存容量、预算不足不判删除、诊断不持久化、网格排除等。首批 15 项在旧实现有 13 项失败。开发过程中额外复现并修复两个边界：缓存数组编码把 undefined 与 null 混为一谈；最终恰好 257 个候选被截成 256 个后可能误判完整。反向日志均保留，未放宽状态断言。

68 项属性专项、完整 1945 项应用回归和 94 项内嵌 Python 回归通过。固定后台的 7 项真实检查证明列表各只读取/解析一次、正常改参对应面仍有效、真实当前身份不读历史、小额度仅影响内存副本、Undo/Redo 和原文件字节保持。另有 8 项连续布尔/物理面积质心/Gmsh/工程重开检查及 6 项空宿主浏览器验收通过。新增模块定向 lint 无警告；server 保留既有未用 confirmed 参数警告。类型检查通过；C++ 源码/程序未变，没有重新跑 CTest。

对上批真实固定后台另跑同一列表计数夹具，明确复现旧接口为 2 次而非 1 次；失败日志为 `property-association-budget-old-list-before.log`。私有工程与正常停机凭据保留，已核对无活动工程/请求，不把反向失败材料覆盖成通过。

## 元数据基准，不是工业模型资格

`scripts/benchmark-property-associations.mjs` 在独立的 GC 可用 Node 进程中生成合成元数据，排除输入构造、模块导入与输出序列化，每个场景三次。基线是上批封存解析模块，记录准确源码摘要。当前机器观察为：

| 合成场景 | 基线中位数 | 新版中位数 | 结果 |
| --- | ---: | ---: | --- |
| 10000 个当前有效属性、100000 条无关历史 | 162.2 ms | 28.2 ms | 全部 10000 个 active，新版不建历史索引 |
| 10000 个一跳历史关联 | 67.3 ms | 91.2 ms | 全部 active；新版预算/诊断检查有额外成本，不是所有路径都更快 |
| 1 个旧关联、200001 条历史 | 未运行无界基线 | 135.9 ms | 新版最多索引 100000 条，明确待复核，无假成功 |

这是非独占 CPU、非工业 CAD/GPU 的元数据观察，不能换算为真实模型吞吐量或硬时限。记录的前后堆/RSS 快照也不是峰值。输入已在内存中，Store 克隆/原生回复解码、原始属性值、完整 JSON 返回和客户端渲染不属于辅助预算，不能宣称全应用内存或延迟已被硬限制。
