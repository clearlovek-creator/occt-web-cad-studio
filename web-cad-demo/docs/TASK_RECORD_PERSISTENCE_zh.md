# 建模任务记录保存与失败诊断

任务阶段记录用于显示执行进度，不是几何提交的最终凭据。候选版修复了保存成功后被清理错误误报失败、误删未成功创建的临时文件，以及清理错误覆盖原始失败的问题；几何是否提交仍以工程持久回执为准。本批没有更新日常服务，也没有迁移任务文件格式。

## 与历史引用预览的关系

原历史引用页面的超时日志包含“建模任务阶段无法持久保存，未继续新的执行阶段”。流程在保存任务阶段时中断，因此页面没有发送后续的 `feature.input.preview`，并非已经证明预览内核或大模型响应过慢。旧日志没有保留具体文件系统错误，不能据此认定是文件占用、磁盘不足或某次清理失败。

隔离对照使用同一封存前端、同一原生内核及相同放样工程。在任务记录完成替换后，测试夹具拒绝多余的临时文件删除：旧后台返回 `MODELING_TASK_REPORT_UNAVAILABLE`，不打开历史引用预览；候选后台不再执行这次删除，能够进入实际的截面失效诊断、打开历史面预览、明确修复并提交，再用一次 Undo 恢复。此对照证明该类误报已经修复，不把受控故障等同于原偶发异常的确切原因。

## 单次保存与结果核对

每次阶段保存只进行一次独占临时文件创建、写入、文件同步、关闭和替换。记录编码不得超过现有读取器的 32768 字节上限。成功替换已经消费临时文件，不再进行第二次无必要的删除；只有成功创建且仍观察到相同目录、相同独立普通文件身份的临时材料才可在失败路径清理。

若替换调用报错，但临时文件已消失，系统允许只读核对目标是否就是本次写入的文件。核对包含目录身份、实际文件身份、完整有界字节及读取前后的长度和时间；内容相等但文件身份不同不能证明发布成功。只有这些条件全部通过才采用已发布阶段并增加 `reconciled` 计数，不再写第二遍。

写入或清理失败时，保留最初的失败阶段和错误类型。清理失败不能盖过写入失败，未成功独占创建的同名文件不得删除。未知、替换过或无法安全清理的材料保留，重启仍按既有规则拒绝未知任务目录内容，需要核对后处理，不能通过自动清空目录恢复。

这不是目录锁、任意恶意竞态或断电后的完整存储认证。任务记录保留既有版本 1 格式，工程回执、完整事务恢复及任务身份绑定仍负责几何结果判断。

## 诊断接口

严格保存失败仍返回 503 和 `MODELING_TASK_REPORT_UNAVAILABLE`，并设置 `retryableByModel: false`。新增 `details.taskPersistence`：

| 字段 | 含义 |
| --- | --- |
| `stage` | `validate`、`encode`、`open`、`write`、`sync`、`close` 或 `replace`。 |
| `ioCode` | 白名单内的系统错误，如 `EPERM`、`EBUSY`、`ENOSPC`，其他值为 `UNKNOWN`。 |
| `publication` | `not-started` 表示未尝试替换；`unconfirmed` 表示已尝试但未证明本次发布。不是几何执行结论。 |
| `cleanup` | 临时材料不需清理、已删除、保留或清理失败。 |
| `phase` 和 `sequence` | 本次试图保存的任务阶段及序列。 |
| `at` | 本次失败的时间。 |

健康接口的 `lifecycle.modelingTasks.persistence` 增加尝试数、失败数、只读核对成功数和最后一次失败。计数属于当前进程的诊断，重启不恢复；旧 `lastError` 仍保留曾观察到的故障。诊断不包含文件路径、原始系统错误文本、建模参数、请求身份或模型密钥。

## 几何安全与处置

真实 Windows 共享句柄测试允许读写但拒绝文件替换：接口指出 `replace` 阶段失败，旧任务 JSON 和工程状态保持，解除占用不会触发自动操作。用户明确再次发起取消后才能保存新阶段；已经取消的任务不能再创建几何。

进入恢复或已获得几何提交回执后，辅助阶段保存继续采用既有尽力报告语义。写入失败标记 `reportDurable: false`，不能中断必要恢复、把成功回执改成失败或重放建模。警告回调自身失败也不能替换真正的任务结果。

出现错误时，先按任务身份只读查询任务及工程回执，并检查诊断阶段、磁盘和访问条件；不要因进度保存失败直接重发建模请求。保留原文件和未确认材料，不删除工程数据，不关闭系统安全功能来绕过错误。

## 验证与剩余工作

`tests/task-record-persistence.test.mjs` 覆盖成功后清理误报、独占创建冲突、准确发布核对、不同文件相同内容拒绝、原始错误保留、陌生材料保留、大小限制、警告回调和真实 Windows 共享拒绝。`tests/task-record-persistence-api.test.mjs` 使用实际隔离 Gateway 与 OCCT，检查 HTTP 诊断、旧记录、原工程、任务身份和不重放。

`scripts/verify-task-record-persistence.mjs` 保留旧版与候选版的真实页面对照、截图及进程退出证据。准确版本、分层测试数量与日常工程保护结果以 `.artifacts/task-report-result.json` 为准；原始偶发失败的系统错误尚未恢复，后续应凭新增阶段诊断继续定位，而不是延长预览等待或添加自动重试。

新增 11 项测试，连同既有任务服务与接口共 38 项专项通过；类型检查和修改文件检查通过。封存版通过旧版与候选版 2 个对照场景，以及 76 项既有工作台、历史引用和空宿主兼容流程，无页面异常。完整回归实际为 2023 项中 2022 项通过、1 项失败，94 项 Python 回归通过，未新增 CTest 运行。

该批唯一完整回归失败位于另一条网格任务保存路径：后台退出观察后队列已经启动下一项，网格也已生成，但 `MeshJobStore` 替换 `metadata.json` 返回 `EPERM`，任务最终为失败。原记录及结果文件保留在 `.artifacts/task-report-mesh-failure`，不能称为队列从未恢复；该批验收记录保持失败结论。后续独立候选通过 [网格完成凭据](MESH_COMPLETION_PERSISTENCE_zh.md) 处理这一保存路径，准确结果不回写或涂改旧失败证据。
