# STEP 导入拓扑命名与属性继承

状态：2026-11-16，独立候选实现；尚未切换日常服务。只增强现有内核的命名根与重算链，没有增加几何感知工具、属性存储或另一套几何内核。

## 本次解决的问题

以前 STEP 导入 Body 的 `Names` 为空。选择器虽然能在整个 BRep 完全相同时按已有精确证据使用原索引，但没有可沿后续操作传播的根。结果包括：

- 在导入体上创建圆角，给圆角面设置属性，再改圆角半径，属性变为待复核。
- 导入体平移后关联面坐标系，再修改平移量，坐标系引用失效，依赖它的建模无法重算。

两例在原实现上实际失败，证据为 `imported-naming-before-behavior.log`。不是把 STEP 的面序号当作构造角色，也不是源文件发生修改。

## 命名依据

```text
验证过的 STEP 字节指纹 + 原始分件精确 BRep + 输出 Body 上下文
    → 导入 Face / Edge 的精确源根
    → 既有变换、生成特征与 Boolean 的真实历史 / 语义匹配
    → 属性、面坐标系与下游特征引用
```

`TopologyNaming::ImportedSource` 使用现有 `ShapeFingerprint`，排除显示三角化和临时 Free/Modified/Checked 标记，不修改输入形状。根的上下文包含导入 Feature ID、输出 Body ID、已认证的 `sha256-chain-1m-v1` 来源指纹和整个原始分件的精确 BRep 摘要；Face/Edge 根再包含自身精确 BRep 摘要。

具体约束：

- 不使用 Face/Edge 序号作为语义根，不做最近距离、包围盒、面积相似匹配。序号仍是当前显示/命令 ID 的一部分，但不是跨重算对应依据。
- Body 上下文区分几何完全重合的不同导入输出，不能从另一个实例借用名字。
- 整个分件摘要防止导入分件顺序变化时，只凭某个重合子面误认另一分件。几何完全相同也不等于同一个源实例。
- 来源字节变化继续由既有 STEP 重放校验拒绝；不会因为新文件看起来一样就认作原来源。源路径重定位不是内容变化，便携工程保留相同来源字节与定义后可继续使用。
- 重复/对称的根仍由现有邻接与完整性规则检查，不能唯一证明时保持待复核。“命名覆盖全部面/边”不等于“所有后续变化都能唯一继承”。

这为不可变导入几何提供固定源根，不是任意外部 STEP 修改后的设计意图识别。改变源文件、修复导致拓扑语义变化、任意重新导入或跨内核版本改变 BRep 表达时，不保证自动对应。没有将项目整体迁移到 OCAF TNaming。

## 保存、重算与旧工程

新导入 Feature 记录 `numberParameters.importNamingVersion:1`。创建与重算调用同一命名方法；既有变换、圆角/倒角/壳/扫掠/Boolean 的名字传播和持久选择器继续使用，不另设属性迁移通道。原始简单属性和类型实例仍由现有真实拓扑历史与持久身份解析。

旧导入没有该字段，保持原有空命名根和精确整个形状的选择行为，不在读取、保存或普通重算时偷偷补造根。旧属性值保留；已有手动引用修复和待复核规则继续生效。未知版本在重放提交前以 `STEP_NAMING_VERSION_UNSUPPORTED` 拒绝，不能当作当前版本猜测。

旧工程的受控显式命名升级已实现后台和工作台入口的独立候选，尚未发布到日常服务。不能通过手改 JSON/XBF 加版本字段来升级。旧版内核也不能据此保证新工程重算后的属性继承，降级需配套兼容验证。

## 工作台操作（独立候选）

入口：**工程 → 来源与引用 → 引用升级**。与来源检查、恢复记录共用现有非模态窗口，不增加菜单栏、常驻右栏或第二个确认弹窗。

1. 查看旧导入数量及保持范围。打开页面仅读取实际后台能力，不自动验证或修改工程；没有 STEP、已采用当前命名版本、后台不支持和模型尚未同步都有独立提示。“无需升级”是版本判断，不是所有复杂拓扑已验证的承诺。
2. 点击“验证升级”。成功报告显示旧来源、历史输出、持久引用、验证 Body 数及工程状态摘要；验证阶段不生成新修订或撤销记录。状态条在窗口滚动时保持可见。
3. 只有报告仍属于当前显示和工程状态时，“升级引用”才可用。提交前后台再次完整验证，不按旧报告中的索引直接执行。即使 native revision 相同，工程属性变化也会使报告过期；点击“核对工程”读取权威状态，再重新验证。
4. 成功回执仍匹配当前工程时，可点击“撤销本次升级”一次恢复；撤销也绑定该回执状态和独立去重键，避免误撤销后来发生的操作。之后也可使用工程功能区的常规 Undo/Redo。

请求结果未确认时：不显示假成功，不启用新的升级操作，不自动重试。“核对工程”只读当前状态，**不会把未确认状态清除为成功**；“按原请求恢复”保留同一去重键与原状态凭据，已提交则取回原回执，未提交则仅在原工程状态仍一致时继续。此按钮可能继续原操作，不是只读查询。旧回执晚到但工程已另有变化时，仅显示为历史回执，不覆盖当前模型。

关闭窗口不取消已发送的操作，也不自动重发；成功结果仍沿全局控制器及工程载入链同步到视口。关闭后重新进入不会重复提交，已升级导入显示为无需升级。来源不匹配、缺失历史选择、归档证据不一致或超过上限等失败，显示中文处理建议与可展开诊断，并提供来源检查/特征历史入口；有明确归档来源特征时直接打开该特征。不会提供绕过证据的“确认执行”。

界面沿用 CAD 浅色令牌、4px 间距和现有操作窗口。主要状态 14px/600、数据与按钮 12–13px、状态摘要 11px 等宽，按钮最小 40px；报告按行呈现，不另加指标卡或主题。桌面、900px、640px 均检查控件边界和截图。

## 旧工程显式升级：后台候选

本轮新增独立维护命令，不加入 AI 建模工具目录，不在打开、保存或普通改参时自动运行：

- `document.naming.preview`：只读验证，返回 `importedNamingUpgrade` 汇总。
- `document.naming.upgrade`：重新完整验证后提交；使用现有工程事务、持久检查点、去重结果与 Undo/Redo。不是执行此前缓存的索引列表。

两者都要求当前读取返回的 `baseRevision` 和 `baseStateToken`；不接受 `inputs`、`parameters` 或通用 `options.preview`。维护命令不能混入批量建模命令。工程属性变化即使未改变原生修订，也会使旧状态凭据失效。已完成升级的再次调用不增加修订、历史事件或撤销步骤；同去重键重试返回原提交结果。

验证与提交仍复用唯一的历史重算引擎：

1. 保持原参数和原命名策略完整重放，记录每个实际历史输出的精确 BRep 摘要及每条选择的已解析对象；最终全部 live Body 必须与当前工程精确相同。
2. 在第二份局部重放定义中给受认证的旧导入建立命名根。在完全相同的历史输入上重新捕获 Face/Edge 选择、面坐标系、Loft 截面及孔种子、曲线扫掠截面/路径边。每个历史输出还必须与第一遍精确相同；引用/输出数必须全部覆盖，不靠最终同名 Body 替代历史输入。
3. 只提交命名元数据及持久选择器。实际 Shape、Body/拓扑 UUID、拓扑修订、当前属性目标、显示三角化和边数据保持不变，工程修订前进一次。现有原始属性和类型实例不经另一套猜测性重映射通道。

选择的索引只在两遍完整 BRep 精确一致的证据范围内用于捕获新选择器；不是把索引作为后续改参的继承规则。未来重算继续采用命名根、邻接完整性与真实操作历史。升级也不会使已有孤立或待复核属性自动变为 active，更不恢复已经丢失的设计意图。

当前准入限制：

- 必须是已保留来源、`decompositionVersion:2` 和 `sha256-chain-1m-v1` 的导入。更老、未经认证的源不能靠读当前文件补证；需要独立的来源恢复/重新导入流程。
- 来源字节变化、任何中间/最终精确几何不一致、无法解析的选择、坐标系未解析或实际标架变化均整组拒绝，不留下部分新名字。
- 历史特征只有原始 Face/Edge 编号、未保存持久选择器时，返回 `IMPORT_NAMING_UPGRADE_REFERENCE_MISSING`。最终外形相同也不能证明被后续操作隐藏的历史选择，因此不在迁移中临时生成旧证据；须走已有历史输入检查/显式重选流程。
- 归档 `SuspendedTopology` 恢复证据必须经过下节的独立双遍重放再认证。无法精确证明的任一归档会拒绝整次升级；不能把普通工程验收推广到所有归档、失效依赖或任意历史参数组合。
- 证据暂限 10000 个历史输出与 10000 条选择；大型 STEP 的总耗时、峰值内存和完整资源预算仍待资格验证。

原生健康声明在 `importedTopologyNaming.upgrade` 中报告 `version:1`、`basis:unchanged-dual-replay-v1`、`archivedRecovery:exact-recertification-v1`、`maxArchivedSources:64`、`maxArchivedProofs:256`。网关和界面仅接受明确的已知策略与有界限制；旧的 `archivedRecovery:false` 仍可执行原有不含归档的升级，但界面明确提示其不支持归档。未知策略或仅支持新导入命名的旧内核不能执行升级。

## 归档恢复证据再认证（当前独立候选，验收中）

被抑制的阵列、加厚等生成输出可能已离开当前几何，但其 Face/Edge 属性和面坐标系仍需在日后恢复时找回正确对象。升级不能删掉旧证明，也不能直接给旧索引换一个新名字。

1. 按原记录的源 Feature ID 与持久身份分组。在局部重放分支中只恢复该源的输出及其真实祖先依赖，不改变当前工程的抑制状态、不生成持久实体、不保存临时几何。当前输入状态不能精确恢复原输出时，返回 `IMPORT_NAMING_UPGRADE_ARCHIVE_UNVERIFIED`；不搜索旧参数、不强行恢复被抑制的祖先。
2. 对相同输出分别以旧命名与新命名重放，逐项核对完整 BRep、原所有权、生成定义和完整原拓扑选择集合。每个原 Face/Edge 均须唯一解析，任何缺项、歧义或变化都会使整次升级拒绝；不部分迁移。
3. 捕获新的版本 2 证明，保留原拓扑身份和修订，嵌入完整 `priorNamingProof`、其规范化摘要 `priorNamingProofSha256` 与 `namingUpgradeBasis:exact-archived-output-v1`。三项审计字段必须共同有效。旧版本 1 摘要算法保持不变，不能通过改哈希规则让旧证明“自动通过”。
4. 版本 2 生成定义仍包含持久选择证据；仅在已有对应持久选择器时排除重放时会变化的临时 `faceId` / `edgeId`。真实选择、参数、源身份改变仍使证明失效。旧内核不理解版本 2 时会拒绝，而不是降级猜测。
5. 对仅有休眠面坐标系、没有被移除 Body 证明的抑制特征，同样验证其输出和选择器。只更新选择证据，不把坐标系标为 resolved，不改变原坐标轴、原点和诊断。以后显式恢复特征时，沿现有属性恢复与坐标系解析链工作。

报告增加 `archivedSourceCount`、`archivedProofCount`、`archivedReferenceCount`。来源非零时界面显示紧凑行式汇总，并明确“验证不会提前恢复几何或激活孤立属性”。旧后台不含这些计数字段时按零处理；不完整或越界回执拒绝显示成功。

预算：最多 64 个独立归档来源、256 份输出证明、640000 次归档选择检查；每份新证明连同保留的原证明不超过 17 MiB，总计不超过 64 MiB。超限返回 `IMPORT_NAMING_UPGRADE_ARCHIVE_LIMIT`，不提交、不删除原记录。这是防止无界处理的安全限额，不是大型工业装配的性能资格结论。

顺带修复阵列抑制的一致性：复用源 Body 的阵列抑制后，该 Body 的实际几何和来源须恢复为前驱特征。已保存且存在此不一致的旧工程不会在命名升级时被悄悄修形，仍需显式检查与重放。

## BREP 摘要分块与规模观测（后续独立候选，未发布）

精确摘要原先把整个归一化 BREP 写入 `ostringstream`，再由 `str()` 复制完整内容交给 SHA256。现在保留同样的拓扑复制、瞬态旗标归一化、classic locale、无三角化/法向和 BREP v3 编码，只将输出接到固定 64 KiB 的摘要流。写入失败或摘要失败必须抛错，不能将截断内容当作有效证据。没有引入全局 Shape 缓存、持久身份新版本或属性迁移。

`ShapeFingerprintStats` 只提供原生测试/内部性能统计：实际序列化字节数及缓冲中最大有效载荷，不进入 Agent 或产品 API。SHA256 用独立的累积上下文；不共享请求数据。Windows CNG 已编译运行验证；OpenSSL EVP 分支本轮未在非 Windows 平台编译，不宣称跨平台资格已完成。

新增基准用确定性三次 B-spline 面组生成真实 STEP，使用产品 `ReadStepParts(...,2)` 读回；纯非实体面组按实际分解规则保留为一个 Body。每个样本包含 N 个独立曲面、每面 P×P 极点。旧、新路径采用相同输入，在相互独立进程中按 ABBA 顺序运行两遍，比较完整 BREP 字节数和全部 SHA；不是重复字节文件代替几何。

| 16×24 | 0.60 | 0.71 | 0.38 | 19.98 / 19.27 |
