# 前端实际编译组成记录

本批补齐“锁文件不等于交付清单”的缺口。只影响构建与离线报告，界面、几何算法、Agent 协议和日常服务均不更改。

## 原理与边界

构建插件从 [Rolldown 输出分块的 modules](https://rolldown.rs/reference/Interface.OutputChunk) 记录模块包含关系，而不是枚举所有已安装依赖。Vite 的 [构建插件接口](https://vite.dev/guide/api-plugin.html) 为不同环境分别调用输出钩子；本工程明确要求 client、rsc、ssr 三份材料，缺任何一份都不能封存新前端。

每份图保存在对应输出目录的 `.cad-module-evidence.json`，记录分块最终代码的长度/SHA256、静态/动态导入，以及模块的工程/包/生成分类与 renderedLength。零长度记录保留，不当成正代码量。模块长度不是压缩后字节占比，也不是费用、性能或许可判断。虚拟/未知模块使用不透明摘要，不从名字猜供应方，不写入绝对宿主路径或原始查询内容。

真实文件按依赖包位置核对包名、版本、package.json 摘要和包内许可文本。不同环境的同一包凭据不一致、封存前安装包凭据变化、输出分块被后续插件改写、硬链接/联接或越界材料都拒绝。它仍不是原始 npm 包签名、完整构建供应链签证或高权限文件系统竞态认证。

新构建将汇总和去重声明保存到 `runtime/provenance/composition`，由原有发布清单逐文件封存，并在 `compiledComposition` 绑定汇总摘要。脱离原源码、构建器和安装依赖后仍能独立复核分块、图、归属、声明及未记录脚本列表。原 V1/V2 候选不补写材料；新构建必须完成封存，不能悄悄回到“只有锁文件”。现有运行层验证整份文件清单，组成语义另由构建器和离线工具核对，不宣称新增了持续运行时供应链扫描。

## 本批实际结果

- 三种环境，10 个分块、467 条模块记录（跨环境会重复，不是 467 个独立文件）。
- 7 个实际编译包：`@vitejs/plugin-rsc`、`react`、`react-dom`、`react-server-dom-webpack`、`scheduler`、`three`、`vinext`。
- 3 份去重声明字节随新前端保存；`@vitejs/plugin-rsc` 没有包内独立声明，继续保留审查缺口，不套用另一个包的许可文本。
- 11 条生成模块记录、2 份分块后生成的资源清单脚本，以及非 JavaScript 资源仍未逐项归属。

新整包报告位于 `.artifacts/frontend-composition-inventory`，共 7,453 个文件、192 个组件和 118 份去重声明。编译分块可同时关联多个组件，不能把整个分块归给一个包。旧候选继续显示原“无编译图”缺口，新候选改为更具体的生成/资源缺口；整体组成状态仍为 incomplete。
