# 全新工程任务与工作区切换边界

本说明对应 2026-11-17 的专用新建候选。当前源码已接入“工程 → 新建工程”及共用快捷入口，底部任务条按原工程找回和控制新建任务；用户要求暂不更新日常服务。后台基础证据见 `.artifacts/project-create-result.json`，本轮页面专项以 `.artifacts/project-create-ui-result.json` 的实际验收范围为准，不代表已经上线。

后续目标 Pi 历史身份检查与显式旧归属恢复见 [Pi 历史恢复说明](PI_HISTORY_RECOVERY_zh.md)，其准确候选和验证单独记录，不与本批数量混用。

## 为什么单独建立新建流程

已有 `document.create` 是几何文档重置命令，不是“只能创建新工程”的承诺。旧控制器会先修改页面 documentId，再执行创建和读取；此时 Pi 可能已开始连接新 ID，失败后再回退整个页面，容易发生状态错位。

新的 `project.create` 是工程任务协议，**不是新增原生命令或 Agent 工具**。它复用原建模任务、完整工程事务及历史保存引擎，最终仍调用 OCCT `document.create`。只允许全新目标，原工程在任何情况下都不作为重置目标。

## 不变量

- 来源与目标不同；目标不能有工程、属性或未确认恢复材料。登记和真正获得执行名额时都核对，不能覆盖期间被其他请求占用的目标。
- 原请求绑定来源工程、目标、名称、请求键，以及来源 revision/stateToken/stateSequence。三个来源状态字段全部必需；排队后原工程变化则拒绝，不把新状态补签到旧请求。
- 任务与完整绑定同次持久写入。登记不执行内核、不创建目标工作区、不启动 Pi。一个目标只能绑定一份新建请求，相同身份仅返回原登记，不允许换名称、换来源或换请求键重新使用。
- 同一任务只接收一次创建提交，重复、重启前已接收或重启前未提交的旧任务均不能重新执行。后者有 `execution:not-started`，可显式取消，不自动恢复创建。
- 真正创建在原全局工程动作队列中执行。验证来源后，使用现有完整工程事务保护新目标；原工程几何、原生属性、类型化属性和历史不修改。
- 提交前读取真实空工程视图，核对 0 Body、0 Feature，空 features/bodies/bodyMetadata/variables/propertyRecords，以及零面、边、三角形统计。视图是现有 metadata 协议，不虚构不存在的 positions/bodyPresentations 数组。结果同时带空类型化属性及来源绑定。
- 完整空检查点、状态标识及 `project.create` 原始回执在同一次历史提交中保存；原生历史事件仍是 `document.create`。任务指纹来自完整新建协议，不与原生命令参数指纹混淆。回执受既有条目数/字节窗口限制，不保证永久可读。
- 名称登记为辅助发布。几何及回执已经提交时，即使名称更新失败，也报告“已创建、名称待核对”，不能误称创建失败并重新创建目标。

## 接口

全部接口沿用本机 Host/Origin 限制，不接收文件路径、任意额外字段或任务控制参数。路径中的工程必须与请求目标一致。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/documents/:target/project/create/tasks` | 唯一字段 `command`，登记一次；201 |
| `GET /api/documents/:target/project/create/tasks/:taskId` | 原任务及创建绑定，包含 `canCreate` |
| `POST /api/documents/:target/project/create` | 唯一字段原 `command`，携带 `X-Cad-Task-Id` 和同一 `X-Request-Id`，提交一次 |
| `GET /api/documents/:source/project/create-tasks?limit=50&after=:taskId` | 通过原页面来源发现目标任务；分页、全部活跃身份及待核对身份分开 |
| `GET /api/documents/:target/modeling-tasks/:taskId` | 原任务阶段 |
| `POST .../:taskId/cancel` | 既有空对象取消接口；202 不是取消完成 |
| `GET .../:taskId/result` | 已证明成功时读取原始创建回执，不重做或读取当前模型冒充原回执 |

`command` 示例：

```json
{
  "protocolVersion": 1,
  "operation": "project.create",
  "documentId": "project-fresh-unique-id",
  "sourceDocumentId": "default",
  "requestId": "fresh-request-unique-id",
  "name": "未命名工程",
  "sourceRevision": 7,
  "sourceStateToken": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "sourceStateSequence": 9
}
```

示例状态只是格式占位，实际必须来自原页面当前工程，不应复制示例数值使用。名称 1–120 个 UTF-16 单元，去除两端空格，拒绝控制字符；ID 和请求键采用明确白名单。来源列表最多每页 100 项，全部活跃任务仍受既有 65 个本进程活跃/登记预算约束，记录总量沿用原 2048 默认上限。没有第二个任务队列或无界单独创建存储。

## 取消、恢复和未知结果

登记/排队可取消。执行取消必须等待实际 OCCT 进程退出，再恢复新目标的完整基线；准备恢复点、提交和恢复阶段受保护。由于原事务需要新目标的空基线，执行失败/取消后可能保留一个可恢复的空目标检查点；这不是来源工程被清空，也不代表应自动删除目标材料。

未确认内核退出或恢复时保持 unknown，保留新目标事务日志，不宣称已恢复或创建成功。原工程持久来源仍保留，重新读取时走原统一恢复路径。不能从“目标看起来为空”推断旧创建请求成功或未执行。

真实进程故障区分两个时点：

1. 空工程历史已发布，但完整事务仍为 prepared：重启恢复原目标基线，原任务结果保持未知，不能把暂时写出的回执当作正式成功。
2. 完整事务已经提交，但任务 succeeded 报告尚未持久化：重启通过准确请求键/指纹找到原始回执，报告已恢复成功；不再运行一次创建。

这些回归是确定性进程退出/重启与文件保留证明，不是任意断电、磁盘故障或恶意本机文件系统认证。

## 前端任务客户端

`ModelingTaskClient` 已支持专用新建登记、冻结输入、一次原提交以及断线后仅通过 GET 读取原任务和原回执。任务观察保留 `projectCreate` 的来源/目标及完整来源基线；来源和目标均计入 pending，取消仍请求目标任务接口。普通目标任务列表不发布缺失来源绑定的 `project.create` 条目。

单页同一任务的并发调用不能重复提交；迟到的 reserved 登记回复也不能覆盖已发现的 succeeded 状态来授权再次提交。回归先证明后者会多发一次请求，再以当前会话所持最高状态和创建许可决定是否仅找回原结果；后台既有 claim 防线仍保留。

来源发现 `restoreProjectCreates(source)` 合并同来源的并发读取，整页和待核对身份验证后再批量发布。最多加载 120 个身份，超过部分报告遗漏；重复清单不触发页面更新，迟到清单不能回退阶段或恢复创建许可，关闭后的回复不再发布。清单容量不足时整页拒绝，不发布半份状态；这不代表后台任务被取消。

创建回执单独验证原请求号、任务 ID、目标、完整来源基线、目标版本/状态及空工程几何/变量/属性证明。它只证明原创建已提交，不能充当目标当前视图。新建后台合并视图时显式保留创建请求号，避免被内部 `document.view` 请求号覆盖。旧候选回执若缺少一致证明会保守拒绝，不自动改写历史或重复创建；页面接入必须与包含此修正的后台配套验收。

## 页面入口与任务条

控制器在完整新建期间持有原工程、版本和状态序列，开始时不清空模型、选择、活动窗口，也不切换底层 Python 或目标 Pi。先核对来源 Pi 空闲，再登记并提交一次专用任务；缺少任务协议、完整来源状态或有效空闲证明时保守拒绝，不退回旧 `document.create` 重置路径。

后台执行继续在自身互斥内重复核对来源 Pi 空闲，覆盖同工程全部 Runtime 会话，不只检查当前面板。前端预检只改善提示，不代替后台准入。只读状态接口、unknown 与边界见 [Pi 工程状态与新建任务互斥](PI_WORKSPACE_ACTIVITY_zh.md)。本项不代表所有旧恢复/文件打开入口已有同样的原生 Pi 准入。

原回执校验成功后，单独读取目标**当前**工程，再核验页面仍属于原来源/版本/状态，才一次采用目标模型、清除选择并切换会话归属。读取失败提示“已创建但尚未载入”，保留原页面；目标后来有新几何时，“打开目标工程”读取最新模型，而不是采用旧的空工程回执。来源状态变化则拒绝迟到结果，不回滚较新的页面状态。

任务条按来源显示名称、阶段及折叠的原工程/目标身份；取消和状态请求仍发给真实目标。登记回复丢失只发现原任务，不重新提交；创建回复丢失只读取原回执。刷新能找回源侧任务；刷新后共享内核仍被占用时，原模型可能暂处载入状态，任务条不依赖模型载入，可以先取消再恢复显示。640px 窄窗口打开助手也保留任务条，不再把取消入口随视口一并隐藏。新建及最终读取期间，助手保留原会话但禁用新增提示、压缩、新会话及模型修改。

Python 兼容客户端的底层工程切换、独立缓存和请求找回已接入成功采用时点，范围及未完成的服务命名空间/异常治理见 [Python 工程归属说明](PYTHON_WORKSPACE_OWNERSHIP_zh.md)。仍未完成全部旧工程入口的 Pi 协调、目标持久 Pi 历史新鲜度认证、旧归属认领/迁移、外部/孤儿进程证明和重任务独立进程隔离；本轮不宣称整体工业化或成套发布资格完成，也不更新日常服务。
