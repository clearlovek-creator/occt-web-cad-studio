# Python 兼容入口：工程归属与原请求恢复

主助手仍是原生 Pi，本批没有恢复旧 Plan/Edit 界面，也没有替换 Pi 工具链。这里修正仍保留的 Python 兼容客户端：旧实现切换工程后仍可能保留原 documentId、Run 和固定缓存键，迟到查询也可能将旧会话写到新工作区。

## 请求身份

新客户端在发送创建前生成 `py-run-<UUID>` 并保存恢复记录，作为 `POST /api/v1/agent/runs` 的可选 `client_run_id`。服务将完整创建输入保存在已有 ConfigSnapshot.settings.client_creation 中，Run 使用同一 ID；Run 与配置快照的关联沿用原存储，不增加数据库列或平行任务引擎。

原始创建绑定包含 client_run_id、project_id、document_id、user_id、message、template_id 和 autonomy_level。新建状态响应及后续 GET 返回该绑定；客户端逐字段验证，不依赖 JSON 对象键顺序。请求消息最多 16000 字符；客户端的 JS 长度限制以 UTF-16 单元计算，可能比服务端更严格。

重复 Run ID 返回 409，不重新调用工作流。并发请求最终由现有 Run 主键唯一性阻止第二次创建；JSON/内存和 SQLite 的并发与持久恢复有验证。竞争失败可能保留未被 Run 引用的辅助配置快照，不能据此宣称没有任何额外材料或已有完整清理能力。

`GET /api/v1/agent/runs/:id` 支持 project_id、document_id、user_id 可选归属条件；新客户端总是携带全部条件。不匹配时在返回上下文前拒绝。它用于防止错误归属，不是多租户认证授权。

旧调用未提供 client_run_id 时保持原协议；新客户端也可以恢复已有且归属完整的旧 Run。新客户端创建需要匹配的新 Python 服务，不回退成无身份的旧创建请求。

## 丢回复与版本

- 创建、回答或审批的未知结果仅用 GET 检查原 Run，不自动重发 POST。
- 创建必须同时证明原 ID、项目/用户/工程及完整创建输入一致。
- 回答/审批若仍处在提交前版本，不能据此判断请求没有执行，恢复标记继续保留，禁止重复发送。
- 已接受更高版本后，迟到的低版本不能恢复旧状态；同版本状态矛盾也拒绝采用。
- 只读找回返回 observed，表示读取原任务当前状态，不保证某个审批一定由本次请求完成；若其他客户端推动了同一任务，也不能冒称是本次请求的独立执行回执。
- 404、非 JSON、错误归属、读取失败均不自动清除原任务身份。创建尚未持久化时的长期缺失仍保留未知，不靠清空缓存猜测未执行。

每次 GET 截止 5 秒，POST 截止 30 秒，响应最多 4 MiB UTF-8 字节；等待运行边界的轮询使用 30 秒总观察预算和最多 120 次循环。观察超时不会取消后台工作，也不授权重做。这些是正常 fetch/传输下的读取预算，不是任意不遵守取消的自定义 fetch 或整个进程硬内存认证。

## 页面和缓存归属

采用目标工作区时同步底层 Python documentId，清除旧活动引用并从目标工程键恢复自己的会话/Run。原工程缓存保留，返回原工程再恢复其独立状态。缓存键仍为 `modeling-agent:python:<documentId>`，但内容必须通过工程/项目/用户校验，不能把不匹配缓存当作新工程历史。

创建/写入前先保存并读回恢复身份；浏览器拒绝存储时不发送修改请求。没有 window 的兼容宿主可自行通过 getRecoveryState 保存状态，本批不宣称它天然具备浏览器持久恢复能力。缓存读取上限为 4,194,304 个 JS UTF-16 单元，不等于 4 MiB 的整体内存限制。

异步请求捕获工程代次，切换后旧 POST/GET 不再更新当前客户端、页面、错误或缓存键。向界面返回的是状态副本，组件不能通过修改 DTO 改变内部 Run 归属。运行中、外部等待、未确认写入或坏缓存阻止工作区切换；只等用户输入/审批或已暂停的任务可保留在原工程缓存，切回后继续，不会自动执行。

清空/删除本地会话不能遗忘活动或未知任务。坏缓存保留原字节并阻止执行；读取失败不再像旧实现那样把 404 当作任务不存在而清空引用。

## 验证和边界

已验证真实 Python HTTP 丢回复及完整服务重启、JSON/SQLite 与两工作流的请求绑定，真实 OCCT 审批只执行一次且只修改原工程。全部 Python 回归在私有 Gateway 上运行，含真实单体/双体写入和属性测试，不调用收费模型。两个旧 live 测试按当前产品语义修正夹具：单体 LangGraph 测试显式提供确定性结构化 Planner；堆叠模板一次审批执行整组，仍核对两实体和两个成功动作。没有移除产品的 Planner 要求。

Python 安装包从私有源码副本构建并安装到候选目录；测试明确核对实际加载位置。解释器和第三方依赖仍是外部测试运行时，不是完整 Python 安装器或所有平台认证。精确证据见 `.artifacts/python-workspace-result.json`。

当前页面新建按钮和来源任务条尚未接到专用创建流程，旧入口提前切换 ID 的问题尚未整体完成；本批只修正其成功采用工作区时的 Python 底层归属，不把它算作全部新建界面完成。Pi 的来源创建互斥仍沿用上一批，不代表所有旧切换入口或 Python 多客户端都有服务端互斥。

缓存还未按 Python 服务地址、Gateway 地址和账号组合建立独立命名空间；内容校验拒绝错误归属，但服务/Gateway 绑定、账号切换、外部/孤儿工作流、未注册请求的安全放弃/墓碑和坏缓存修复界面仍待后续。没有自动迁移日常 Pi 历史、修改日常服务或宣称完整工业化目标完成。
