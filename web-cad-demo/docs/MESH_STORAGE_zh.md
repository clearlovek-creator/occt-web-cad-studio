# 网格存储准入与后台退出观察（候选，未部署）

## 这次补齐什么

网格任务在启动前核对现有网格材料、正在进行的任务逻辑预留和磁盘可用空间；结果发布前再次核对。容量不足明确拒绝，不删除旧工程、旧网格或无法识别的文件。关闭页面不会使后台丢失原生进程的迟到退出观察：原进程实际退出后，后台自行清理未发布材料、终结中断任务并继续原先已提交的队列，不依赖页面轮询，也不重剖中断任务。

## 默认配置

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| `MESH_STORAGE_MAX_BYTES` | 64 GiB | 网格根目录的逻辑文件字节预算 |
| `MESH_STORAGE_RESERVATION_BYTES` | 4 GiB | 每个新写入任务的逻辑预留 |
| `MESH_STORAGE_MIN_FREE_BYTES` | 1 GiB | 保留的实际可用空间余量 |

配置按严格整数字节读取，非法值不会退回无限预算。总预算允许 1 MiB～1 TiB、任务预留 64 KiB～8 GiB，预留不能大于总预算；空闲余量允许 0～1 TiB。实际 `.env` 未修改，这些设置须经受控更新/启动生效，不是浏览器选项，也不属于工程网格方案。

这不是文件系统硬配额，也不分配占位文件或实际锁定磁盘空间。清点统计普通文件逻辑长度，而非物理分配簇；其他应用可继续占用磁盘，正在写入的原生任务也可能在再次检查前超出预留。不能据此保证永不出现 `ENOSPC`，更不能声称已限制整个应用或整机磁盘。

## 清点与准入

- 异步清点数据目录中的 `mesh-jobs`、`mesh-sources`、`meshes`，包含质量缓存、临时/失败材料和无法按名字识别的普通文件。其他工程文件、来源、备份及日志不纳入这个网格预算。
- 不读取文件内容，不按猜测归属自动删除。不跟随链接；遇到硬链接、符号链接、异常类型、读取失败或超预算清点时拒绝准入，保留原材料。
- 默认最多 250000 个清点条目、12 层目录、15 秒逻辑清点时间。异步 I/O 不阻塞整轮主线程；但单次操作系统 I/O 不保证可在 15 秒硬中断，清点也不是对抗外部并发篡改的原子快照。
- 全部写入任务共用串行准入账本，最多等待 32 项，避免并发请求各自使用同一份“剩余空间”。登记前按现有文件加全部预留核对总量和实际空闲空间；本任务发布前再按实际文件加其他任务预留核对。
- 未开始的容量拒绝返回 `507`；清点不可完成、链接或预算排队问题明确报错，不偷偷按空目录处理。工程任务尚未登记时，不启动原生几何导出或 Gmsh。

工程剖分、诊断预览，以及文件级创建/修复/交叉写入走同一账本；只读文件预检/质量诊断不因写入容量满而禁用。完成、确认失败或取消后释放逻辑预留；原进程退出未知时继续持有，不能把逻辑名额先交给后续写入。服务重启通过现有未完成任务中断规则和实际文件清点重新建立状态，不自动重放旧任务。

## 迟到退出与停机

后台直接观察本次捕获的原进程对象，而不是猜 PID、重复停止或定时创建替代进程。所有捕获的子进程都必须实际退出；一个旁路进程退出不能释放整个名额。HTTP 状态读取仍可做同样的只读核对，但不再是队列继续的必要条件。

停机等待已有观察完成；关闭标志阻止观察回调启动队列任务。缺少可核对的原进程对象时仍保留未知，不把“没有观察者”当作“没有进程”。这不是任意崩溃后跨进程重认领、全应用重作业隔离或操作系统级孤儿进程治理的完成证明。

## 出错后怎么办

旧结果仍可读取/诊断。用户可以明确删除不再需要的网格任务，释放其受管结果后再提交；无法识别的文件需管理员核对，不自动清理。若任务进行期间容量变满，新结果不作为正常完成发布，当前失败材料继续计入后续清点。容量不足不会自动重试或替用户改粗网格尺寸。

健康摘要显示预算、预留数、最近清点字节/文件数、可用空间及错误类别，不暴露新增内部路径或文件名。网格面板沿用原有字体和错误色，将当前错误移到剖分按钮正下方，优先于旧成功记录；保留草稿与旧结果，不增加确认弹窗或配色规则文件。实际浏览器核对错误在操作窗口可见区域内，而不只断言隐藏在下方的 DOM 节点存在。

## 验证范围

真实测试覆盖：容量不足在原生导出前拒绝、未知文件完整保留、只读诊断仍可使用、发布前外部容量变化拒绝、旧网格/工程保留、原生迟到退出后没有任何状态请求也能恢复队列，以及停机不再启动排队任务。确定性测试覆盖并发预留、释放身份、真实空闲空间拒绝、清点限制、硬链接、I/O 异常及未知退出期间保留预留。

首轮无人轮询和停机反例、错误调用内部 `mesh.prepare` 的测试失败均保留；后者改用公开剖分产生的真实 MSH 作诊断输入，没有放开生产操作权限。精确最终候选、分层数量及限制以 `.artifacts/mesh-storage-result.json` 为准；没有最终记录时仍在验收。

日常服务、配置、工程和默认内核未更新。全机总资源、真正的磁盘写入硬配额、自动安全清理未知材料、工业规模性能、任意脏几何/离散交叉及完整安装升级仍需继续，整体工业化目标未完成。
