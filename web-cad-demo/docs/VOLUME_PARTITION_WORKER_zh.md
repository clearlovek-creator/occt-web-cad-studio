# 正式体域分区组件与调用协议

闭合离散几何的体域算法已进入正式 `discrete-surface-worker` 共享核心。正式组件和实验入口使用同一份实现，支持独有区域、交叠区域、独立连通体和空腔壳。新后台候选已封存该组件及实际运行库，但体域到四面体的工程持久任务仍未接入，日常服务未更新。

## 与现有系统的关系

原有 `surface.refine` 和表面任务保持原语义，只生成带来源的表面，不宣称存在封闭体域。新操作为 `volume.partition`，复用原客户端的专属进程、取消、时限、内存保护和退出核验，不增加第二套进程管理框架。

进程先接受一次 `health.ping`。调用端必须核对新增 `volumePartition` 能力，包括固定 CGAL 版本、许可、算法依据、单位和额度，才发送体域输入。旧组件只具有表面能力时，在发送几何前明确拒绝，不从表面成功推断体域可用。每个进程只执行一个算法任务，然后退出；表面和体域任务不能在同一个进程中串行复用。

## 输入和结果接纳

输入为完整离散点、三角面及逐面来源，单位为毫米，来源含 Body、Face 和局部 Solid 标签。来源标识、修复参数、点索引和额度先在调用端检查，再由原生组件检查。没有 Solid 的自由 Sheet 明确拒绝；非法 Solid 标识与缺少 Solid 分开报告。

结果保留表面阶段的完整 `surfaceReport`，包括被移除的退化输入三角面。调用端复用表面协议检查，再核对原始三角面的面积覆盖、输出顶点到原三角面的距离、完整 Solid 清单及体域归属。共面且面积相同也不能随意交换两个来源三角面。

每个连通体的壳必须连通，边恰好有两次反向使用；一个正向外壳和其余负向空腔壳共同组成体边界。公共三角面由两个不同区域的连通体反向引用。壳、连通体、区域、输入 Solid 和并集的体积逐级核对。数值积分使用局部原点，避免整体平移造成不必要的消减误差。

结果通过检查后，仍须等待同一实际进程以零状态退出。取消、超时、异常退出或无法确认停止均不接纳迟到结果，也不启动自动替代进程。现阶段的 Body、Face、Solid 仍是调用方离散标签，不是新增 CAD 身份证书；工程任务接入必须继续复用既有 CAD 来源绑定。

## 固定预算

| 项目 | 当前限制 |
| --- | --- |
| 输入 Solid 与归属区域 | 6 个与 32 个 |
| 输入三角面 | 4096 面 |
| 输入和输出点 | 60000 点 |
| 公共边界三角面 | 20000 面 |
| 独立连通体 | 128 个 |
| 三角面与连通体比较 | 100000 对 |
| 请求和回复 | 8 MiB 和 64 MiB |
| 默认进程提交内存 | 2 GiB，不可关闭 |
| 默认握手、算法和退出等待 | 10 秒、120 秒和 5 秒 |

这些是当前组件的明确边界，不是大规模或任意脏几何的能力承诺。开放壳、方向冲突、非简单区域及超预算输入仍明确拒绝。

## 验证和候选版本

新增 28 项应用测试，完整 2196 项 Node 回归和配套 94 项 Python 回归通过。另通过 29 项共享核心算法检查、19 项既有表面进程检查、23 项正式体域进程检查，以及既有 20 项原生回归。封存后台中的实际客户端和运行库另通过同样的 23 项体域检查，并完成 13 项既有工程表面任务的真实保存、取消、重启和恢复检查。

共享核心的新结果还经过 91 项四面体与质量回归，公共节点、来源、体积和优化退步保护保持。但这段四面体执行仍是隔离入口，不是已接入的工程任务。界面没有修改，本轮没有重跑页面流程；原前端输入摘要保持不变。

真实进程测试发现原生 JSON 字段排序与 JavaScript 构造顺序不同，最初错误拒绝合法结果。接纳检查现按字段语义比较，仍拒绝未知字段，原失败记录和排序回归用例保留。原生构建捕获 19671 份依赖头文件和 5 个实际运行文件；固定 CGAL 6.1.2 GPL-3.0-or-later，不购买商业许可，完整对应源码分发资格仍未完成。

体域阶段的构建和测试摘要见 `.artifacts/volume-partition-result.json`；后续[正式四面体组件](DISCRETE_TETRA_WORKER_zh.md)已完成受控调用。日常 R222、Box10、295 份保护文件、完整 Pi 历史及原服务保持不变。下一步是材料冲突规则、带 CAD 来源绑定的工程任务和恢复链路；`normalMeshAdmitted` 继续为 false。
