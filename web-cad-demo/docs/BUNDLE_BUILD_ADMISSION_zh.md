# 工作台构建：路径与输入准入

本批修复构建输出先于输入检查发生的问题。旧实现会先递归创建输出目录，再发现前端、后台或 Node 材料无效；放错路径时，甚至在输入版本中留下空目录。原始两项失败回归保留在 `.artifacts/bundle-path-guards-before.log`，未用新日志覆盖。

本批不更新日常服务。最终 1877 项应用回归、31 项定向回归、7 项真实坏输入检查及 9 项完整组合验收通过；精确候选及分层证据以 `.artifacts/bundle-path-guards-result.json` 为准。

## 准入顺序

```text
解析四个完整、唯一的路径参数
→ 观察普通目录、真实路径与目录身份，检查输出位置
→ 验证前端 V2、后台 V3、当前构建模块和控制脚本
→ 只读验证 Node 材料、程序字节和 PE 依赖
→ 再观察目录身份
→ 逐级创建独立输出目录、建立 UUID 暂存
→ 认证复制并复核输入，发布新的独立候选
```

未知、重复、缺值或把另一个选项作为值的命令行直接拒绝。保留原始路径拼写到文件系统准入，不能先把 `D:relative` 解析成看似明确的绝对路径而掩盖歧义。参数允许普通相对目录，但拒绝设备命名空间、文件流、保留名称、尾随点/空格以及过深目录。

前后台版本、Node 来源材料、构建代码及控制脚本都必须通过检查，才能创建输出目录。Node 预检查与实际封存复用同一份字节/PE 检查逻辑；封存仍写出自己已哈希并解析的那份字节，不能用“预检查通过”替代实际复制验证。完成复制时再次比较 Node 输入凭据，变化则不沿用旧结论。

选定版本、构建模块、控制脚本和 Node 程序的父目录也纳入观察；不能只验证工作区根是普通目录，就放过内部 `scripts` 联接或目录替换。构建模块本身与控制脚本都要求普通单链接文件。

## 输出位置保护

- 不允许输出位于前端/后台输入根或 Node 材料根之内，包括它们自身。
- 不允许使用卷根或工作区根；工作区源码、测试、文档、依赖、工程数据、原发布选择及服务记录目录也不是构建输出。
- 普通独立目录可以位于工作区的专用输出区，也可以位于工作区外；名称只是类似输入目录前缀的普通兄弟目录不会误拒绝。已有输出目录中的无关文件保持原样。
- 已有版本目录、保留的 UUID 暂存，以及工作台/版本/选择清单所在的目录不能嵌套生成新候选。损坏的工作台清单仍保留保护，不因无法解析就允许写入。
- 所有已存在的输入/输出目录链都拒绝符号链接、Windows 联接及普通文件替代；悬空联接不能被误当成不存在的普通目录。
- 除了规范路径比较，还比较目录所在设备与文件标识，防止仅靠不同路径前缀绕过。无法提供目录身份的文件系统不降级为只比较字符串。

准备阶段记录既有目录身份；建立输出之前、逐级建立过程中、创建暂存及发布之前重新观察。被替换、改成联接、准入后出现的新目录，以及后来出现的版本清单都要求停止并检查，不静默接管。创建失败不删除输入，不回滚删除陌生目录；若已通过准入后才遭遇 I/O 故障，可能保留自行建立的空父目录或专属暂存。

## 验证边界

自动测试覆盖真实 Windows 大小写/规范路径、联接、悬空联接、目录替换和写入故障。普通目录身份别名的额外分支用确定性文件身份注入验证；这不是对 SMB、映射网络盘或任意文件系统的资格认证。

`scripts/verify-bundle-build-guards.mjs` 使用真实封存前后台，进一步验证自洽但与程序不符的 Node 摘要、坏 JSON、缺少控制脚本和硬链接脚本：除检查目录不存在外，还实际禁止任何 `mkdir` 调用，确认失败发生在输出写入前。另通过真实命令行验证相同保障，原版本和来源材料重新核对。

正常构建及完整独立运行另由工作台组合验收验证，不能只用负向检查证明交付可用。此层是操作者误用保护和目录变化检测，不是原生句柄相对操作、整个目录链的操作系统锁、对高权限恶意竞态的沙箱，也不是包签名认证。完整第三方许可、全新系统安装、升级/跨数据回滚及总体工业化门槛继续保留。
