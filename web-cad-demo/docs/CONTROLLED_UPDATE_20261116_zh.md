## Pi 历史恢复

首次上线检查只确认 Pi 在线且空闲，后来实际核对发现它打开了空会话。这是验收缺口，不是“大模型没有返回消息”。两份原始 JSONL 与停机备份一致。

原生 Pi 在显式 session-dir 下的 `--continue` 按 CWD 过滤；旧历史记录的是 SDK 仓库目录，新 V3 默认改为每工程独立的 `pi-workspaces/<projectId>`，因此旧历史被跳过。没有把工作目录改回公共仓库，也没有手改 JSONL 头。

恢复使用所选版本 SDK 的原生 `SessionManager.forkFrom`：

1. 在隔离副本上复制两份完整历史，逐项核对全部非头条目、分支/压缩及解析后的上下文，原文件字节不变。
2. 使用真实 Pi RPC 连续启动两次，均恢复最新会话的 18 条消息；只连接本机只读健康夹具，无模型提示或几何命令。
3. 当前会话确认空闲且为空后，创建相同迁移副本并执行原生 `switch_session`。两个来源文件原地保留，副本 header 有新 ID、新 CWD 和 parentSession 来源关系；不假称原 ID 被复用。
4. 当前网页连续载入两次，均显示 16 行按工具调用合并的消息、20 条完整历史记录；逐条显示内容/概要与原生消息投影一致，工具默认折叠。原生 18 消息与展示 16 行是不同计数。

目前只有 default 会话目录存在已保存的两份原历史，本次迁移没有批量打开其他工程。今后手工变更数据位置/CWD 或显式工作目录时，仍须先核对历史、使用原生迁移并验证恢复，不能假设存在文件就会自动续接。迁移脚本留在本次私有证据目录且有严格固定版本/来源保护，不是面向任意路径的通用迁移命令，不应改参数后直接对其他工程运行。
