# 网格完成凭据与重启恢复

网格已经生成并校验后，状态文件暂时无法替换，不应让系统把剖分判为失败并删除结果。候选版为每个成功完成的任务保存独立完成凭据，再同步原状态文件；重启可以核对这份凭据，恢复同一份网格，而不是重新剖分。日常服务和用户工程未更新。

## 完成判定

完成凭据保存在任务目录的 `completion.json`，格式为 `web-cad-mesh-completion` 版本 1。它包含最终任务记录、记录摘要以及之前 `metadata.json` 的准确字节数和摘要，绑定任务、工程、来源、剖分设置和结果文件凭据。它不是模型生成的文本，也不是根据“存在一个 MSH 文件”推测成功。

只有结果已完成既有校验、专用网格进程确认退出、磁盘预算重新核对且任务没有取消或停止意图时，才能发布完成凭据。修复预览同样需要完成其快照与结果校验。凭据原子发布成功后，系统尝试更新 `metadata.json`；后者被占用时，成功依据是持久完成凭据，不是内存中的完成标签。

任务描述可返回 `persistence.basis: completion-receipt-v1` 和 `metadataSynchronized`。后者为 `false` 表示完成凭据已保存、可变状态文件尚未同步，不代表重新执行或网格损坏。已有不同完成凭据不能覆盖；重复确认必须匹配原记录。警告日志不包含文件路径、原始错误文本或模型参数，日志自身失败也不改变已提交结果。

## 重启核对

网格目录恢复线程先完整读取旧状态记录，再核对完成凭据。旧状态仍为 `running` 或 `preparing` 时，只有其准确字节摘要与凭据内的原状态一致，且任务、来源、设置及最终记录协议全部有效，才恢复为完成。恢复只读，不回写旧状态、不启动 Gmsh，结果默认隐藏，显示或下载前仍须核对原始文件和工程验收。

如果状态文件已经是完成，主要结果文件凭据必须一致；合法的后续质量查询缓存可单独扩展，不改变原网格结果身份。明确删除形成的 `deleted` 记录优先于旧完成凭据，目录清理失败不能使任务复活。

未来版本、未知完成依据、错误摘要、任务冲突、硬链接、异常文件或读取期间的变化都会阻止采用凭据。目录中保留原材料并显示相应 `MESH_METADATA_COMPLETION_INVALID`、`MESH_METADATA_COMPLETION_CONFLICT` 或暂时不可读取错误，不选择一份记录强行覆盖另一份。无完成凭据的旧任务继续按原有规则恢复，不将旧未完成任务自动补判成功。

## 写入与预算

任务和网格记录复用有界原子写入组件。每次只创建、写入、同步、关闭和替换一次；准确核对已发布的同一文件可消除结果不明，但不重试建模、剖分或文件替换。成功替换后不再删除已不存在的临时文件，失败清理只作用于本次创建且观察到身份未变的独立文件，不掩盖原始错误。

状态与完成凭据各不超过 16 MiB，读取两份材料共同消耗现有 64 MiB 目录恢复总字节预算。实际打开字节在分配和解析前计费；超限不发布部分目录、不写入部分中断状态。发布前还核对凭据大小和状态文件增长量，最多 32 MiB 额外计划写入量同时进入网格总容量与实际可用空间检查，不能先按旧占用量通过再绕过预算。

这些是有界逻辑额度和已观察到的文件身份检查，不是操作系统磁盘预留、任意恶意竞态认证、断电恢复认证或 Gateway 全进程内存上限。阶段记录仍有同步 I/O；更大工程的主线程负载属于后续资源工作。

## 完成凭据也无法保存时

磁盘不足、权限错误或凭据冲突仍可能使完成发布失败。此时返回 503 `MESH_COMPLETION_UNCOMMITTED`：任务不显示、不提供正常网格下载，也不假报成功；已生成的 MSH、结果和相关文件保留，不再因辅助发布失败而删除，不自动重新剖分。

没有有效完成凭据的保留材料不会自动恢复为成功。后续候选已支持对持久记录为 `MESH_COMPLETION_UNCOMMITTED` 的原任务明确选择 [恢复原结果](MESH_COMPLETION_RECOVERY_zh.md)，重新核对文件后发布，不能用于任意孤立或缺损材料。不要删除目录或修改记录来强行开放结果，旧版本已经清理掉的文件不能凭新机制补造。

## 版本与验证

本批在独立候选中增加完成凭据协议，没有迁移日常数据。旧后台不理解新凭据，后续受控更新或回退必须核对数据兼容性；不能仅切换程序版本就宣称任意跨版本回退安全。

新增测试覆盖状态文件替换拒绝、凭据重启恢复、来源冲突、坏版本、硬链接、目录清理失败后的删除记录、字节预算和原材料保留。专用网格进程未退出时，完成凭据必须不存在；凭据发布失败时，结果必须保留但不能使用。

真实 OCCT/Gmsh 接口测试使用 Windows 共享句柄阻止状态文件替换，并在另一个工程中于完成凭据发布后立即退出服务。两种情形均核对原文件摘要、来源归属、默认隐藏、重新验收以及没有第二次剖分。原先失败的网格退出队列用例保留完整断言，没有通过延长等待或删除失败证据处理。

完成凭据批次的版本、分层测试、旧失败材料与日常保护结果以 `.artifacts/mesh-completion-result.json` 为准，后续交互以 `.artifacts/mesh-recovery-result.json` 为准。原历史引用偶发失败的具体系统错误、缺失有效失败记录或原文件时的恢复，以及工业规模、安装升级和跨数据版本迁移仍需继续处理。

本批新增 15 项测试。最终 80 项专项、2038 项应用回归、94 项 Python 回归、封存版 4 项真实剖分与恢复接口、76 项页面兼容流程通过；类型检查通过，修改文件检查无警告，项目全量检查仍有既有 26 项警告，未重跑 CTest。

首轮全量回归另保留了一次旧恢复夹具失败。该夹具在同一目录同时启动两份恢复服务，现改为先完成并停止原恢复器，再写入四种崩溃状态后重开，并补充明确的目录就绪与收尾断言，四种中断、落盘及不重放断言均保留。首轮未保留具体内部错误，不把竞争写入认定为已经证明的唯一原因；失败日志与后续完整通过记录分别保存。
