# 前端独立运行发布 V2

本批为隔离候选，未更新日常服务。目标仅是移除前端启动对开发目录的依赖，不代表完整安装包或干净操作系统验收。

## 修复的实际问题

旧 V1 已保存页面构建和项目运行代码，但启动仍读取工作区的 `package-lock.json` 和 `node_modules/vinext/dist/server/prod-server.js`。仅复制发布目录到空目录后，实际启动因缺少宿主依赖锁失败。原失败凭据保留在 `.artifacts/frontend-clean-before.log`。

新 V2 随发布保存：

- 浏览器及服务器构建、项目运行代码、原有 React 服务器外部依赖。
- Vinext 生产运行器的已审查相对导入闭包及其包身份、MIT 许可文件。
- 构建时的依赖锁，放在 `runtime/provenance/package-lock.json`，仅作为溯源凭据，不在启动时安装依赖。

当前 Vinext 0.0.50 的运行器闭包为 44 份文件、343470 字节，其中 42 份 JS，加包说明和 LICENSE。不随包复制 TypeScript、Vite、编译器或整个开发依赖目录。运行器的两个计算式导入仅允许已审查的服务器构建入口；其他计算式导入、缺失/越界依赖和未封存的外部包会在构建时拒绝。此收集器针对已验证的生产运行器，不是任意 JavaScript 加载行为的通用安全证明。

## 构建及启动边界

构建仍需要完整开发环境。新构建默认生成 V2；新增的构建器和闭包收集器也纳入前端源码摘要。发布先逐文件核对，再更新明确指定的候选选择记录，不操作其他版本根目录。

运行时直接使用复制版本内的 `runtime/scripts/frontend-server.mjs`，传入该版本的绝对 `--release` 路径、独立 `--port` 和 `--gateway-api`。工作目录不再要求有源码、宿主依赖锁、宿主 `node_modules` 或 `.env`。不得把前端进程指向用户密钥配置。

V2 启动要求 Node 与构建时的精确版本一致（本批为 24.14.0）。运行器、许可、随包依赖锁、全部发布资源仍做完整清点、长度及 SHA256 校验，拒绝增加、缺失、链接或变更，不回退宿主依赖/源码。V1 保留原校验语义，仍需匹配的宿主依赖；不会自动迁移或冒充自包含版本。校验不是操作系统写锁，也不是对高权限篡改后重写清单的签名防护。

## 本批验证

`.artifacts/frontend-standalone-result.json` 记录精确候选、来源摘要及全部证据。专项脚本 `scripts/verify-frontend-standalone.mjs`：

1. 只复制封存前端到带中文和空格的空白宿主目录；不存在宿主源码、依赖锁、`node_modules` 和配置。
2. 使用外部 Node 的绝对路径、仅含 Windows 系统目录的 PATH，且不继承 `NODE_PATH` / `NODE_OPTIONS` / 供应商密钥，执行复制版本内的真实入口。
3. 实际请求全部客户端 JS/CSS，并核对返回内容；同源代理连接独立封存后台。
4. 真实浏览器加载页面，通过同源接口和 OCCT 创建 Box，经 SSE 更新视口，无需刷新。
5. 停止并确认原前端进程退出，修改复制运行器；重启必须在监听前拒绝，原工程与原发布保持不变。
6. 恢复相同原字节后重启，无需安装依赖或重新构建。只在确认所有测试子进程退出后清理专属临时材料。

完整应用、现有内核、真实网格、Pi 原生 SDK 与服务升级/回退另分层验收。Pi 使用本地确定性服务，不产生收费模型调用。测试失败与最终通过分别留档，不把受限环境不允许创建 Windows 链接的失败解释为产品拒绝逻辑已通过。
