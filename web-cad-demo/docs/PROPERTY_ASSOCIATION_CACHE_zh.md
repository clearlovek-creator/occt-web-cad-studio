# 属性关联的同状态重复查询复用

状态：2026-11-17，独立候选，未更新日常服务。最终验收材料见 `.artifacts/property-association-cache-result.json`。

## 解决什么问题

同一工程未变化时，属性列表、Agent 查询及网格读取原来会重复验证相同的几何关联。本次在现有解析器外加有限的进程内结果复用，不新增感知工具，不改变属性继承、命名或网格归属算法。

只有完整验证且全部实例 active 的结果才能复用；待复核、关联不完整或预算超限仍重新解析。修改响应及未提交事务不使用缓存。

## 怎样保证不沿用旧结果

- 快照必须来自当前服务实际收到的内核响应，内部以对象身份记录；字段相同的外部或复制快照不能取得复用资格。
- 工程 ID、内核实例、加载代次、完整工程状态令牌、状态序列、属性内容版本及原生修订号全部相同才命中。不能只比较修订号，因为只改属性值也可能不改变原生修订号。
- 改参、属性编辑、重新关联、撤销/重做、重置/打开、恢复或内核/服务重启都不沿用旧结果。任何非纯查询原生请求都会保守清空全局缓存；其他工程写入也会使它失效。
- 关联读取仍经过工程串行队列；事务进行中、未确认恢复或内核不可用时不复用。加载和解析之后再次核对状态，变化则不发布缓存。
- 每次重新读取属性存储，只缓存关联覆盖层和验证回执，不缓存值或属性类型。存储内容是内部 JSON，返回时重新解析，调用者修改结果不能污染缓存。
- 命中诊断单列为响应中的 `propertyAssociationCache`，不混入工程属性、不写入保存文件，也不改变只读预览的数据比较。Agent 的属性查询位于响应 `query` 下。

## 有界资源与范围

最多 16 个工程条目，总编码数据 32 MiB，单条 16 MiB，编码预检最多 100 万节点、16 层。超大结果照常返回，但不缓存；按最近使用淘汰。缓存不持久化、不跨进程复用。

这些是编码后的缓存与预检额度，不是 V8 堆、全进程峰值内存或墙钟时限。原始 schema 读取/克隆、值、原生查询、结果序列化仍有成本。沿用上轮解析器的共享工作预算，不能把缓存额度当作整个应用的资源限制。

## 合成性能结果

同一解析器对比关闭/启用复用：每种路径 3 个新子进程，每进程首次读取及 5 次重复读取；每次计时都包含新 schema 克隆，不计构造输入、导入模块和原生通信。原始数据见 `.artifacts/property-association-cache-benchmark.json`。

| 场景（10000 实例） | 不缓存首次/重复中位数 | 启用缓存首次/重复中位数 |
| --- | ---: | ---: |
| 当前身份，100000 无关历史 | 43.4 / 41.1 ms | 95.0 / 26.6 ms |
| 一跳继承，10000 历史 | 112.5 / 87.2 ms | 159.5 / 26.9 ms |

首次填充有额外预检和编码成本，并非所有路径更快。每个场景缓存编码约 6.87 MB。这不是独占 CPU、峰值 RSS、工业 CAD/GPU 或端到端吞吐资格。
