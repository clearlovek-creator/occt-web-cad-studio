# OCCT Web CAD 前处理工作台

工作台使用 OCCT 8.0 维护精确几何，Three.js 显示和拾取，Gmsh 执行网格任务，Pi 通过当前工程的 CAD MCP 工具进行辅助建模。当前正在按[前处理工业化改进路线](docs/INDUSTRIAL_PREPROCESSING_ROADMAP_zh.md)完善工程可靠性与交互，不包含仿真求解能力。

### 拖拽建模与 Pi 助手

- 9 种基础体及 5 种基础面均支持拖拽。视口上方“拖拽建模 / 参数建模”或 `Alt+M` 快捷切换；参数窗口中也可切换，保留尺寸、位置和表达式草稿，不在切换时创建几何。
- 长方体等有高度的工具：点击起点，移动或按住拖动绘制底面，点击/松开锁定底面，再移动鼠标调整高度，点击完成。底面阶段只画平面预览；重复点击不会误提交默认高度。球/平面工具在半径或平面范围确认后完成。`Esc`、右键或“取消绘制”放弃；`Backspace` /“重选底面”返回上一步。圆管内径、棱柱边数等完整参数可切到参数窗口调整。
- Pi 不区分 Plan/Edit。思考、工具参数与结果默认显示可展开概要，可复制全文；模型、思考级别、停止、运行中引导/排队、会话历史、新会话及 `/compact` 保留 Pi 原生能力。展示折叠不删减原生上下文。
- 较大的工具结果只通过事件流发送同步提示，完整原生历史保留；展开详情以 24000 字符分段浏览，支持首页、前后段和末段，复制仍包含全文。折叠时不生成完整详情文本节点，概要也不反复解析巨大 JSON，避免长结果拖慢建模界面。
- Pi 请求、回复、等待队列和 stdio 均有独立预算；停止/状态控制保留余量，不会排在所有模型工作后面。超时区分未发送、只读未变化及已发送但结果未知，不自动重发。实际 Pi CLI 的 OS 退出和输出管道关闭分别核验后才允许替代进程；这些不是对模型上下文、全部 HTTP 连接或进程总内存的硬配额。
- `SIGTERM` 表示 Pi 会话进程被终止，不是供应商网络错误的同义词。重新连接恢复原生会话，不重发可能已执行的建模请求；中断或工具失败后只读核对工程显示。MCP 错误通过 Pi 原生 `tool_result` 钩子标记失败，同时反馈给下一轮模型，而不只在界面显示错误字符串。
- 上述新候选通过独立工程验收后才可发布；源码和测试通过不表示日常服务已切换。

### STEP 导入与重算一致性

- “工程 → 来源检查”提供“当前工程 / 全部工程与恢复区”两种范围。当前范围核对持久化清单中的 current/Undo/Redo；全部范围同时清点本数据目录内的工程、待恢复事务、隔离和其他保留 XBF，按实际来源路径分组，显示已识别工程 ID 与各类引用数。区分缺失、变化、旧证据未认证、路径异常及未发现引用；报告可展开、筛选、分页，关闭窗口或切换范围不停止已接受任务。报告是限额缓存，不持久化，释放缓存或后台重启后需重新检查，不会自动重跑。
- 保存工程前按内核相同的 `sha256-chain-1m-v1` 校验来源；打开便携工程前，独立检查器读取实际 XBF 元数据，核对清单特征 ID 与打包字节，再进入现有恢复事务。拒绝“包内校验和正确、实际来源已替换”的文件。新版导入必需指纹缺失时不能降级为旧版兼容；旧来源保留未认证提示，不补造证据。
- 来源检查逐块读取，保留 1 MiB 来源缓冲；文件/清单/引用数据/报告缓存的数量与累计字节均受限，两种范围共享并发上限。相同快照的不同引用角色只读取一次，证明冲突不按顺序猜选。全部范围只覆盖本数据目录内可识别材料，不跨外部数据目录。现已支持受控恢复原始来源（见下文），**仍没有安全清理或不同几何的显式重绑功能**，不能将“未发现引用”当作可删除。恢复/隔离/保留材料不等同于当前活动几何依赖。已完成报告是检查时的观察，工程、目录、清单或已检查文件发生变化会使报告过期。
- `npm run build:worker` 同时构建 `cad_snapshot_source_inspector.exe`。可用 `GEOMETRY_SOURCE_INSPECTOR_PATH` 显式指定此独立组件；它不恢复活模型、不重算特征、不接收 Provider 密钥。专项浏览器测试为 `npm run test:ui:sources`。
- 诊断链路为“界面范围 → 只读任务 → `SourceCheckpointCatalog` 磁盘清单发现 → 独立 XBF 检查器 → STEP 分块内容校验 → 带作用域与完整性标记的报告”。工程范围只排队读取元数据，使用 `loadDocument:false`，不经过懒加载/历史回退；损坏当前检查点时仍只报告问题，缺失 Undo 不会被加载器过滤后漏掉。全局清点也不会执行待恢复事务。
- 当前默认预算：工程范围 128 个检查点 / 1000 个来源 / 512 MiB 来源读取；全部范围 20000 个存储条目 / 2048 个检查点引用 / 2000 个来源 / 2 GiB 检查点累计大小和 2 GiB 来源读取。清单累计读取 256 MiB、单份清单 64 MiB，引用数据累计 16 MiB；每个检查服务最多保留 100 份、32 MiB 序列化估算的报告及观察元数据，超量淘汰旧报告，单份超量明确失败而不冒充完整。这里不是整个 Node/原生进程的硬内存上限。发现阶段显示实际条目数而不伪造百分比，目录遍历与内容读取均可取消。

- STEP 在独立 XCAF 文档中解析、转换和构建，全部完成后才替换当前原生文档；失败不发布半个模型，仍保留 Gateway 的完整工程事务保护。
- 新导入采用 `decompositionVersion=2`：含实体的复合产品拆分时保留其中的独立面、线、点，不再只保留 Solid。纯面/纯线框产品保留原分组，例如一个以 Compound 表达的多边 Wire 不被拆成多个 Body。当前依然将装配展开为 Body，不保留可编辑装配层级。
- 导入与历史重算复用同一拆分器；新来源显式按毫米模型单位转换，重复实例保留实际位置。Body 名称/颜色及可唯一对应的 XCAF 子形状元数据复制到平坦文档，避免导出时重复带出原装配根；不是把 STEP 材料/属性自动变成项目材料库或用户自定义类型。
- 新来源保存 `sourceFingerprintAlgorithm=sha256-chain-1m-v1`：以 1 MiB 块计算 SHA256 链及总长度的来源指纹，不是标准整文件 SHA256 字段。导入前后核对，重算前检查保留来源；即使只改变空白或 Body 数量相同，也拒绝隐式使用不同内容。工程包可以重绑定文件路径，原始字节不变时指纹仍有效。旧版本缺少指纹的来源不自动补造证据，按旧实体拆分规则重放；需要新版保护时显式重新导入。
- 导入响应 `stepImport` 提供根数量、Solid/Sheet/Wire/其他 Body 数、模型/来源单位、拓扑有效性异常数和子形状元数据歧义数。诊断不是深度自交或工业质量认证，转换器仍使用 OCCT 默认形状处理；应用没有另行自动修复。几何可导入不等于可剖分：独立线/点的完整网格约束支持仍未实现，不会静默丢弃后剖分。
- STEP 导入当前仍是替换文档几何，不是追加或装配合并；导入会纳入完整工程撤销历史，支持撤销恢复导入前的几何、变量、坐标系和属性数据，再重做导入。原生 revision 可以重新从 1 开始，前端以递增的工程状态序列判断新旧，不以 revision 单独判断。
- 底部独立任务区显示接收文件、等待工程、核对基线、转换几何、保存提交五个真实阶段和已等待时间，不估计百分比。数量/单位/异常诊断默认折叠，报告可以隐藏再打开，页面刷新后读取后台记录，不重新上传；隐藏不是取消任务。
- 任务阶段记录位于受管数据目录的 `step-imports`，每工程最多保留 100 条记录；同工程只接受一个活动上传，全进程最多 4 个。状态读取 `GET /api/documents/{id}/imports/step/status` 返回最近记录，带 `requestId` 可核对指定记录，读取不会启动几何操作。此阶段账本不是另一个几何真相来源。
- 上传使用请求标识与工程状态前置条件，排队后再次核对；过期请求在原生转换前拒绝。成功来源在开始转换前写入并刷新到文件；失败且完整回滚后清理未使用来源，未确认结果的来源保留待恢复，不因清理诊断报告而删除。未确认来源的资产审查/回收界面仍待补充。
- 服务中断后只依据可校验的已接受事务认定完成，否则报告中断或结果未确认；不自动重放。接受结果仍受既有 100 条/256 MiB 去重窗口限制，窗口外无证据时不猜测成功。几何提交后若只是报告落盘失败，仍保留来源并返回真实成功与警告，不能把它转换成一次失败后重试。
- 几何树区分实体、面体、线体和其他几何；点标记、大装配/真实工业 STEP 样本验证仍是后续工作。现有视口仍以 Body 单色为主，不代表每个 STEP 面颜色都已直接显示。
- `npm run test:ui:step` 使用生成的真实混合 STEP、真实 OCCT 和浏览器，验证树/像素、诊断、导入中刷新、真实后台中断、原工程保留和窄窗布局；`tests/step-import-workflow-api.test.mjs` 注入真实转换回复闸门、报告存储故障和提交后进程退出。`step-import` 原生测试另覆盖重算、位置、来源修改、颜色导出往返、旧规则和单位。生成样本不是工业文件大样本库。

### 可靠提交与重复请求

- 建模、类型化属性、撤销/重做和对应的去重结果在同一工程事务中提交。后续编辑、撤销新分支或后台重启不会清掉仍在保留窗口内的已接受请求；重复请求返回原始结果，不把旧几何与新历史混在一起。
- 完整结果保存在 `history/{documentId}/outcomes` 的不可变文件中，工程清单只保存文件名、长度和 SHA256，按需读取，不再用全局无界 Map 常驻完整响应。结果缺失或损坏返回 `IDEMPOTENCY_RESULT_UNAVAILABLE`，不会重新执行原命令；应先查询当前工程并排查存储，不要换新请求键盲目重试。
- 每工程最多保留最近 100 条、累计 256 MiB 序列化结果（可用 `GEOMETRY_IDEMPOTENCY_BYTES` 下调）。这是有限回放窗口，**已淘汰的键不保证去重**，不是永久 exactly-once。事务进行中保留原清单仍引用的文件，提交/回滚结束后清理不再引用的结果与中断临时文件。
- 单批步骤结果累计最多 64 MiB（可用 `GEOMETRY_BATCH_RESULT_BYTES` 下调）；达到限制即提前停止并整批回滚，未执行步骤明确标记，禁止发布部分成功。整批去重结果也必须能一起进入保留窗口。限制针对序列化数据，不代表整个 Node/OCCT 进程的堆内存上限。
- 新历史清单为 v2，可只读载入 v1，首次成功写入时升级；启动或查询不会批量改写旧工程。`.cadproj` 版本不变，不携带服务器请求回放记录。升级前应备份完整数据目录；降级须恢复配套备份，不能直接让旧后台写 v2 清单。
- `npm run benchmark:mutations` 在隔离工程中验证 10/50/200 个真实 OCCT 实体、后续标量编辑、精确回放及重启恢复。报告含源码/内核 SHA256、清单/结果大小及 Gateway 内存；不代表复杂工业 STEP、浏览器或原生总内存的完整验收。`npm run test:native` 使用与正式 Gateway 相同的 OCCT 动态库顺序执行原生测试。

### 工程数据目录的唯一写入保护

- 同一物理数据目录只允许一个更新后的 Gateway 使用；换端口、换启动注册表或目录别名都不能绕过。保护在 Provider/属性/历史/网格 Store 初始化及事务恢复之前建立，冲突启动不会改写既有工程；锁冲突也不会自动切换到临时目录。
- Windows 的独立 `cad_data_directory_lock.exe` 只负责启动时建立保护，将不可继承的文件/目录句柄交给实际 Gateway 进程后立即退出。锁不依赖辅助进程存活、PID 文件、心跳或超时抢占；只有实际 Gateway 进程退出后才释放。不提供运行中“强制解锁”，不要手动删除 `.cad-writer.lock`。
- `.cad-writer.lock` 可以在正常/异常退出后继续存在。文件内容是诊断记录，不是所有权依据；没有活动系统句柄时，新 Gateway 可以正常接管，不会根据旧 PID 杀进程。活动锁文件不能被普通删除/覆盖，数据根目录也不能被改名；文件硬链接或重解析锁标记会被拒绝，避免改写目录外的对象。
- 该实现对应本机 Windows 固定磁盘的 NTFS/ReFS 策略，本批真实测试为 Windows/NTFS。网络盘、非固定磁盘和未验证文件系统拒绝启动；非 Windows 尚无已验证的同等实现，会明确停止，不会回退成无锁写入。它不是跨机器分布式锁，也不能约束忽略协议的旧程序/外部脚本；不要让多个机器通过云同步目录共享活动工程数据。
- 锁组件随 `npm run build:worker` 构建，启动时缺少组件会明确报错。`npm run test:storage` 验证真实进程竞争、崩溃接管、目录别名、子进程不继承锁以及工程/属性恢复。健康接口的 `storage.writer` 报告实际所有者和获取耗时，启动器须核对所有者 PID 才认定后台就绪；旧后台须先受控停止再更新。
- 系统机制说明见 Microsoft 的 [CreateFile 共享规则](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle) 与[文件句柄生命周期](https://learn.microsoft.com/en-us/windows/win32/fileio/file-handles)。安全边界以当前代码和真实进程测试为准，不等同于全目录 ACL、恶意本机程序防护或磁盘断电认证。

### 属性关联的完整性

- 新执行的布尔操作保存 OCCT 的真实拓扑血缘，组合内部输入组 Fuse、Boolean、Refine 的修改/生成/删除关系。结果拆成多个 Body 时，血缘同时记录 Body 和拓扑 ID，不能只凭 `face-N-M` 判断归属。
- 属性类型实例保留原始关联锚点；读取时沿当前工程中的有效血缘解析现存面/边。唯一对应时自动关联，原面删除时标记失效，一对多或证据过期时标记待复核。读取不会改写原锚点，因此撤销/重做和 `.cadproj` 重开可以重新解析各自状态。
- 工程树会标出失效或待复核实例。打开实例后可展开真实血缘候选，定位并高亮后明确选用；保存才重新绑定。仅修改属性值不会重置关联锚点，也不修改几何修订版。
- 创建或重新关联实例会验证 Body、面/边编号及拓扑版本；失效选择不能作为有效关联写入。过去保存、没有真实血缘的 Boolean 不会自动补造关系。
- Body 编号不是持久身份。每个 Body 有独立 `bodyIdentity`，每次几何拓扑更新产生新的 `topologyIdentity`；关联锚点和血缘边同时携带身份。撤销/重做恢复快照中的身份，新分支即使复用相同编号或修订号也不会恢复旧面/边关联。已删除 Body 的编号在当前快照身份登记中保留，重启后不分配给新 Body。
- 身份登记和血缘保存在 XBF、随 `.cadproj` 往返；失败回滚恢复相同身份。旧工程中缺少身份信息的关联保留值并标为待复核，需明确重新关联；不能靠相同编号自动证明历史身份。
- 跨结果 Body 的命名匹配使用生成来源及邻接身份，结果序号调换不改变几何归属；对称、消失或不完整来源不强行匹配。这不是完整 TNaming 选择求解器。
- 已抑制生成特征的输出即使暂时没有 Body，也可从几何树“已抑制特征”分组编辑、恢复或删除；支持搜索、键盘菜单及统一撤销/重做。仍出现在现存 Body 历史中的抑制特征不会重复列出，也不会创建虚假的隐藏 Body。
- 抑制前保存有界的私有拓扑恢复证据，随 XBF/工程包持久化；恢复时同时核对 Body/来源特征持久身份、生成定义和拓扑来源。精确 BRep 与命名均未变且定义未换时可核对原枚举；输入改变时只采用完整且唯一的生成角色或邻接证据。不按位置、面积或旧序号补配，同位置的新截面不能继承旧截面的属性。
- 该恢复路径覆盖加厚、旋转、直线扫掠/管道、放样和阵列的现存定义输出；面/边属性、原生兼容属性及成对历史共同恢复。不存在证据的旧版已抑制特征、失去来源/分裂/歧义的关联仍保留值并要求复核；不宣称已解决所有 Boolean 消费或任意拓扑命名问题。每个输出证据最多 100000 个 Face/Edge、16 MiB；超限明确失败并回滚，不静默丢弃属性证据。
- 六类细节特征共用 `TopologyNaming::FeatureResult`，创建和历史重算采用相同规则。生成面的身份由所属特征、真实 OCCT Generated/Modified 关系、完整且唯一的源拓扑及邻接证据构成；来源摘要使用 SHA256，避免连续特征把来源字符串无限嵌套。加厚未直接报告生成面的侧壁，仅在原边、内核报告的平行生成边共同邻接唯一输出面时建立桥接证据，不按面积、质心或输出序号猜测。
- 抽壳中保留的原外表面和新内表面保持独立身份；被开口消费的原面与新口沿也不是同一张面。切换开口或圆角输入边后，旧生成面属性保留其值并按实际情况失效/待复核，不能挂到旧位置附近的新面。来源缺失或存在同名歧义时不补造生成面身份；未命名 STEP 不能仅因做过一次圆角就获得可证明的来源。
- Sweep/Revolve 的起止面由内核的 FirstShape/LastShape 确定，不按 Z 大小或输出顺序区分；反向扫掠仍保留端盖角色，全周旋转不把已消失端盖的属性移到侧面。抽取单一截面时保留完整 Body 中区分分割子面的邻接证据；改选同祖先的另一块面不能复用旧截面属性。
- 阵列副本通过真实 Transform 历史迁移原生面/边属性，并以所属特征和逻辑槽位限定生成名。矩形阵列改变列数后，已有行/列的 Body ID、属性和下游引用保持；删去槽位后再增加会获得新 Body 身份，只有 Undo 恢复旧身份。变量求值前先保存旧槽位，防止新列数覆盖旧布局。实例总数是派生信息，不作为矩形/镜像阵列的可编辑参数提交。
- Fillet/Chamfer 的输入边，以及 Shell/Thicken/Draft/Revolve/Sweep/Pipe 的输入面保存持久选择器。输入精确 BRep 未变时核对 SHA256 指纹后使用原枚举；输入改变时按生成来源、完整邻接关系及唯一性解析，不按旧序号或最近位置猜测。显示网格和内核临时检查标记不影响指纹。选择消失、分裂或来源不完整时，整次编辑失败回滚。
- STEP 等无生成命名的输入仍可在精确输入不变时修改特征参数；输入变化后不能凭旧编号重选。旧版无选择器的特征只在上游输入定义未变的参数编辑中补录引用；第一次上游修改即缺少引用时会拒绝直接重算。当前支持在特征参数窗口中查看、更换 Fillet/Chamfer/Shell/Thicken/Draft/Revolve 及旧直线 Sweep/Pipe 的输入面/边：临时视图显示执行该特征之前的真实输入，鼠标点击或聚焦视图后用方向键切换，完整重算验证通过后显式提交。临时显示编号不进入主视口选择器；工程状态、Body 身份、来源特征和精确输入指纹共同约束提交。曲线路径 v2 的显式来源重选及其边界见下文。
- 上游 `feature.update`、`variable.set`、`coordinate.set`，或特征抑制/恢复/删除因下游几何特征的面/边输入失效而失败时，会进入同一修复流程，已选择的多个下游引用随原修改合为一次提交和撤销；变量/坐标系编辑窗口、特征历史窗口和几何树右键均接入。验证/取消不写工程，主相机与原显示保持。显示截断或临时 WebGL 视图中断时禁止提交，需重新读取；并发工程数据修改即使不改变几何修订号，也会阻止旧预览提交。大工程结果显示未载入或输入 Body 被下游消费时，明确提示不展示替代 Body，不把其他几何当作该输入的结果。
- 历史输入请求在 `parameters.proposal` 中携带原操作、输入和修改参数，只允许上述六类操作的暂存重放；不接受任意命令。预览回复的 `proposalOperation` 必须与原操作一致，旧程序忽略暂存修改时会拒绝选取。正式修复写在原命令的 `parameters.selectionEdits` 中，不先保存变量/坐标系再单独补引用。临时变量、材料表达式值、坐标系、特征定义、对象编号及身份登记在读取成功或失败后均恢复。
- 阵列创建会保留数量、角度、方向等表达式；变量修改会重算全部依赖阵列的实例数，而非只改被编辑的第一个特征。抑制时不提前分配隐藏输出，恢复时按当前变量生成；源 Body 被后续 Boolean 消费后仍按历史重放，不要求它继续作为活体存在。数量维度采用 Integer，方向为 Dimensionless，角度为 Angle。旧工程中已经丢失的阵列表达式无法从数值反推出变量名，需要在特征窗口显式重新输入。
- 面坐标系另有持久来源锚点：Body 身份、来源特征身份、精确输入/生成来源选择器共同限定所选面。几何与坐标系依赖按稳定拓扑序重算，允许引用独立的后建几何，但拒绝循环依赖；不会改写几何树的展示顺序。来源是选面时的历史输出，不会漂移到该 Body 后续的任意布尔或变换结果。
- 面坐标系未被几何使用时，面消失/分裂会留下可见的“引用失效”记录，并阻止拖拽或参数建模使用旧位置；有依赖模型时，整次上游修改回滚，并进入同一历史引用修复界面。临时视图显示本次草稿下的坐标系历史来源输出；可显式更换来源特征及输出 Body、拾取新面，再与原特征/变量/坐标系修改一起验证、提交和撤销。来源被抑制或删除时不以最终活体替代；选择另一个来源仍需通过完整依赖及循环检查。多个坐标系和特征面/边修复可以逐项暂存，全部通过才提交。直接修复已有失效记录时，仍可在坐标系窗口采用当前选中面。
- 此流程复用只读 `feature.input.preview`：`inputs.featureId` 与 `inputs.coordinateSystemId` 二选一；放样另需 `inputs.sectionId`，曲线 Sweep/Pipe 另需 `inputs.sweepInputId`。坐标系、放样截面及曲线输入可指定 `sourceFeatureId` / `sourceBodyId` 更换历史来源。原操作仍在 `parameters.proposal` 中；正式坐标系重选写入 `parameters.coordinateSelectionEdits`，特征/放样/曲线输入重选写入 `parameters.selectionEdits`（放样增加 sectionId，曲线增加 sweepInputId），均包含工程、Body 身份、来源特征、精确 BRep 指纹和临时视图中实际选中的面/边 index。此编号只对该历史输入有效，不是主视口或永久 ID。每类重选最多 64 项；校验或重算失败不发布任何部分坐标值、来源身份或几何。
- 只读历史检查按所选来源的真实祖先依赖重放，不被其他待修复的独立分支阻断；所选来源自己的依赖缺失或循环仍拒绝读取。局部检查不是整图验证：预览验证和正式提交始终检查全部工程，因此不能用逐项检查绕过尚未修复的其他引用。来源下拉框基于当前工程已有的历史输出，尚未提供拟议阵列新建输出的自动发现或任意新 Body 的修复规划。
- 真实 Loft 已采用版本化的有序平面 Face 截面及同一重放链，并支持按截面逐项暂存上游联合修复，见下文；仍需继续多环/带孔放样、导入拓扑命名、一个实例关联多个子面的显式继承策略，以及更复杂的历史引用联合修复。旧工程的不完整命名不自动升级为可信证据。本流程不是完整 TNaming 选择求解器；类型化数据的统一撤销与事务说明见下文。

### 真实截面放样

- 创建区“放样”打开真实截面编辑器，可从 Body 的实际面选择视图拾取，或快捷添加单面 Sheet。支持 2–32 个有序截面、上移/下移/删除、直纹/光顺连接，以及独立只读结果预览；预览和取消不修改主视口选择或工程。
- 默认保留截面的实际位置、轮廓和空间朝向。可显式选择“按全局 Z 间距布置”：以首截面质心 Z 为起点，仅沿全局 Z 平移实际截面，保持 X/Y 和面朝向；间距可用长度变量或表达式。当前只支持有效平面 Face 的单一闭合边界，带孔面、曲面等明确拒绝，不退回包围盒。
- 新建 API：`detail.loft` 的 `inputs.sections` 为 `[{bodyId, faceId}, ...]`；`parameters` 可含 `placement: "actual" | "z-spacing"`、`ruled: boolean`，仅 Z 间距模式允许 `sectionSpacing`。选择写入必须携带选面时实际观察到的 `baseStateToken`。新建请求不再接受旧 `sectionBodies` 近似定义。
- 编辑走 `feature.update` 的 `parameters.loftDefinition`，包含 `sections`、`placement`、`ruled` 和可选间距。已保存截面用 `{sectionId}` 保留原引用和顺序，新选面用 `{bodyId, faceId}`；省略 sections 时保留已有 v2 引用。删除后重新添加会分配新截面身份，不复活旧引用。创建与重算共用 `LoftBuilder`，不维护第二套 Agent 几何实现。
- 每个截面保存来源 Body/特征身份及持久面选择器，重算读取选面时的来源特征历史输出，而不是源 Body 后续变换或 Boolean 的最终活体。已验证源 Body 被消费、同一实体的两个截面、变量/坐标系驱动及撤销/重做。来源删除/抑制或面解析歧义会整体回滚，并报告精确的特征/截面 ID；上游特征、变量、坐标系及生命周期修改会进入同一联合修复窗口，可更换历史来源并逐项暂存多个截面，也可与坐标系/其他特征修复混合，一次验证、一次提交/撤销。只读检查仅遍历所选来源的祖先依赖，不被其他独立失效分支阻断；正式验证检查整图和循环。
- 放样编辑器每个已保存截面有“查看 / 更换历史面”入口，当前布置、间距及顺序作为原修改草稿一同保留，取消不写工程。临时视图检查真实渲染的面，不接受旧显示编号；指纹/身份不符、索引越界、重复截面修复或过期工程状态均拒绝。一个来源提供多个截面的放样可抑制/恢复/删除；输出暂时消失时编辑器保持原特征，不跳到相邻节点。关闭窗口后可通过几何树“已抑制特征”分组重新打开和恢复。
- 端盖按真实 First/Last 输出及各自截面的完整唯一来源分开命名：新建特征插入中间截面时保留未变化两端的属性，但位置相同的新来源不能冒充旧端盖。侧面只采用完整唯一的全部来源与 OCCT 生成关系；改为直纹分段时不把原整张光顺侧面的属性静默挂到第一段。早期 v2 未带 `loftNamingVersion=2` 的特征保留原整份截面签名规则，不静默重解释已有属性；未知命名版本拒绝重算。无法证明来源的生成面保持待复核；未宣称所有兼容性拆边或退化情况都能自动继承。
- 旧工程未带 `loftVersion` 的特征继续原包围盒矩形近似和重放语义，树节点标“旧近似”。普通编辑仅改旧间距；只有明确选择“改为真实截面定义”、重新选面并保存才升级，保留输出 Body ID，可预览和一次撤销回旧结果。v2/v3 均按真实截面打开，未知版本明确拒绝编辑，不降级为旧近似。

### 带孔截面放样候选（内核/API/界面已接入，未发布）

当前源码增加 `loftVersion=3`：2–32 个有序有效平面 Face、每截面 1–16 个明确对应的贯通孔。原有 v2 单环定义和旧近似都保留原算法，不自动转换。候选放样窗口与几何树已识别 v3，创建、已有特征编辑和历史引用修复共用孔对应控件；此能力只在 `geometry-worker/build-loft-holes` 和独立前端候选中验收，**日常页面与原生程序未升级，不能用旧日常界面编辑 v3 试验工程**。候选 MCP 已按实际原生握手协商多孔参数；旧日常内核无证明时仍只声明单环能力，不根据磁盘源码或文件名推断支持。

选面后从现有 `geometry.measure` 读取 `boundaryLoops`：当前显示 Face、外/内环及真实 Edge 成员、闭合/平面/有效/完整标记和周长。历史输入预览返回相同的有界边界信息及已保存孔的解析结果；它们是当前临时显示摘要，不是永久 ID，也不是另一套感知工具。用户按孔 1、孔 2…明确选择相应通道；使用过的内环不能重复选取，孔数不一致、显示/边界截断或工程基线变化会阻止提交。

宽操作窗口中临时几何与孔对应并排，窄窗口上下排列；点击内环按钮独立高亮整个内环，不重置相机。新截面调整只是草稿；已保存截面保持 sectionId，历史换源时面与孔须共同验证，源不同不会借用旧孔对应。预览不写工程，提交使用现有事务，一次 Undo 恢复参数和引用。

候选 API 的每个 `inputs.sections` 项可明确提供：

```json
{"bodyId":"body-1","faceId":"face-3-2","holeEdgeIds":["edge-3-5","edge-3-9"]}
```

`holeEdgeIds` 每项选择相应孔边界上的一条已观察到的代表边；数组第 1 项贯穿所有截面对应同一个孔，依次类推。所有内环必须且只能映射一次，不按位置、面积或孔序号猜测。仍必须携带观察这些 Face/Edge 时的同一工程 `baseStateToken`；批次同时检查每条孔边的真实来源，不能只更新 Face/Body 的结果引用而继续用旧孔边编号。

特征保存 Body/特征身份、面选择器和孔代表边持久选择器，不保留显示边序号作为长期引用。孔身份基于整条内环全部边的规范化完整证明，不依赖选了其中哪条代表边；缺证据时不借用另一个孔的命名。普通参数重算及间距/直纹编辑复用已保存引用；显式更换截面仍使用新截面身份。通过原放样/布尔历史传播端盖、外壁和内壁名称，不另外维护一套几何历史。

构造先对完整截面统一布置，再分别放样外轮廓和各孔，保留真实形状，验证后扣除孔实体。检查正体积、拓扑有效性、OCCT 自交检查、孔间接触/交叉、孔越界/碰外壁、端盖单面及内环数量、材料体积守恒；失败整体回滚，不能悄悄填孔或删除失败孔。端壁距离使用 `10 × Precision::Confusion()`，体积容差使用绝对/相对阈值；这不是任意小特征、任意自交或工业复杂样本的数学完备证明。当前要求所有截面孔数相同，不支持孔的中途生成/消失、曲面截面或点截面。

### 真实曲线路径扫掠 / 管道

- 创建区“扫掠 / 管道”可选直线向量或模型边路径。模型路径从独立来源视图选择实际平面 Face 截面及同一来源 Body 的 1–32 条有序 Edge；路径支持真实圆弧、圆、多段相切边和空间 B 样条，不用折线显示网格代替精确曲线。纯 Wire STEP 来源不需要伪造面网格即可拾取。
- 路径必须连续且相切（G1），不得重复边、分叉、缺口或包含额外闭环分支。自动调整单边方向以连接给定顺序，但不自动排序或补缝；尖角过渡暂不支持。全路径可反向，移动标架可选 corrected-frenet / frenet。
- `placement: "actual"` 保持截面的真实位置，要求截面平面包含路径起点且垂直其切线；`"align-start"` 显式将完整截面副本的面积质心和法向对齐起点及切线，源几何不动。带孔截面整体变换一次，最多 32 个孔，偏心孔保持原相对位置；外轮廓及孔分别精确扫掠后沿真实 Boolean 历史组合。
- 新建使用原有 `detail.sweep` / `detail.pipe`：`inputs` 包含 `bodyId, faceId, pathBodyId, pathEdgeIds`，`parameters` 包含 `placement, frame, reverse`。必须携带观察这些拓扑时的 `baseStateToken`；当前令牌不使旧显示面/边编号重新有效。MCP 沿用现有工具，不新增平行 Agent 工具。
- 新特征保存 `sweepVersion=2`、截面/路径的 Body UUID、来源特征 UUID、持久选择器和顺序方向；创建与重算共用 `SweepBuilder` 及已有重放链。历史来源在对应特征输出处捕获，后续平移/Boolean 消费后的最终活体不能冒充原路径。未知版本拒绝重放，旧直线向量定义不静默升级。
- 历史编辑通过 `feature.update` 的 `parameters.sweepDefinition`。`profile: {bodyId,faceId}`、`path: {bodyId,edgeIds}` 只有用户明确重新选取才替换，省略时保留已存引用；`placement,frame,reverse` 可独立修改。同位置的新来源不会借用旧来源的壁面属性。保存/重开、抑制/恢复及一次撤销均保留版本化定义。
- 预览/取消不写工程，也不修改主视口选择；结果必须是一个有效闭合 Solid，执行内核自交检查，显式拒绝奇异/自重叠圆环。复杂单面自折叠等尚非完整证明，仍需几何诊断和工业样本验证，不宣称任意路径/截面均可安全构造。
- 曲线历史修复复用同一 HistoricalInputTarget/重放链：截面使用 `sweepInputId: "profile"`，每条路径边保存独立 `inputId`。新路径显式替换时分配新的 UUID，Undo 后的新分支不复用旧键；旧 v2 无键路径采用限定于冻结定义的 `legacy-path-N` 键，读取本身不改文件。旧键不是 Face/Edge 显示序号，不能越过工程状态校验继续使用。
- 来源缺失或拓扑消失/分裂时返回 `SWEEP_INPUT_UNRESOLVED` 及确切 featureId/sweepInputId/selectionKind，原修改整体回滚。特征、变量、坐标系与抑制/恢复/删除窗口均可保留草稿，进入历史来源视图逐项暂存；也可与 Loft/坐标系/普通特征的修复混合，完整重算通过后一次提交/撤销。路径仍限定同一历史 Body，换源时需逐边复核；界面只清除该特征已暂存的路径选择，保留其截面及其他修复。依赖图先暂存所有权，在来源真实输出处再核验身份/指纹/实际索引；独立失效分支不妨碍只读检查，正式提交检查整图与循环。
- 曲线编辑器提供“查看 / 更换历史截面”和逐条历史路径边入口；取消保留放置、标架、反向等草稿，结果预览明确显示实际 Sweep/Pipe 输出 Body，不用源体替代。纯 Wire 历史来源以真实 Edge 渲染和拾取，不要求虚假 Face 网格。过期修复不能提交，显式重载才放弃旧草稿。
- 边界：不提供自动猜测的最近面/边重绑；无法证明的旧整面属性保留值并待复核，不能因重选一小块分裂面而假装原关联正确。未命名导入边变化后的自动命名/属性继承仍不完备，需要显式修复；尖角过渡、任意自折叠以及复杂路径的自动简化仍未支持。

### 网格来源与有效性

- 工程网格统一对全部几何联合共形剖分；工程 API 不再接受仅 Body/Face 的局部生成请求。选择用于结果显示，不改变输入范围；独立文件工具仍保留原有能力。
- 网关在同一工程队列中取得几何摘要并导出 BREP/身份清单，二者必须一致。剖分期间允许继续建模，结束后再次校验完整 Body 集合、对象身份和拓扑身份；不能仅按可能复用的修订号判断有效。
- 结果区显示“来源有效／已过期／无法验证”和来源版本；来源有效只表示几何一致，不表示质量合格。改名、材质、透明度、显示隐藏不使几何网格过期；新增/删除 Body、几何修改及撤销后的不同建模分支会使旧结果过期。撤销回完全相同的来源身份可恢复有效性。过期网格不渲染，服务端也拒绝开启其显示；仍可下载来源版本的历史文件。
- 新结果默认隐藏，并停止旧结果显示，工作台只显示当前结果；继续保留每个 Body 一个显示按钮和结果窗口一个整体显示按钮。隐藏几何时同步隐藏该 Body 的网格，恢复几何显示时保留网格显示意图。
- 拥有 BREP 清单的工程输入先按 Solid Index 验证原始导入，再逐来源体修复、组合 Fragment 的输出关系；不在全局去重后用质心最近来补归属。重叠区的一个网格实体可以有多个 Body 来源，导出 `.msh` 包含 Body Physical Groups；视口去重绘制共用实体。
- 共形报告核对接口节点 ID 是否确实被两侧体单元引用，不只比较坐标。CAD Face 与修复后 Gmsh Face 保留多来源关联；缺失归属或存在非共形接口的结果不能作为可用工程网格显示。复杂离散交叉重构仍需继续。
- 网格任务及来源、设置、状态保存在 `.data/mesh-jobs/<documentId>/<jobId>/`；完整显示数据与 `.msh` 分开保存并记录长度/SHA256。读取结果及重新开启显示时检查文件完整性，缺失或损坏明确标为失败，保留原文件供诊断，不自动重新剖分。当前显示意图不落盘，恢复结果默认隐藏。
- 任务状态为准备几何 → 排队 → 剖分 → 完成，失败、取消和服务中断有独立终态。工程层负责轮询/恢复，关闭网格窗口不会丢失任务，页面刷新会找回记录和已完成结果。任务记录中可选择历史结果，但同一时刻仍只显示一个结果，且必须通过当前几何来源验证。
- 浏览器任务由每工程独立的 `ProjectMeshTaskStore` 观察，React 只订阅其快照；它不是第二套后台队列，任务持久状态仍由 Gateway 管理。工程切换或卸载会中止旧 HTTP 观察并废止其回复，不取消真实后台任务、不重发创建/取消。人工选择历史结果后，轮询完成的新任务不会抢走当前选择；明确发起新任务时才恢复跟随。旧选择的迟到失败不能覆盖较新的选择，恢复历史结果也不能清除创建回复未确认的警告。
- 工程剖分默认串行，每个任务使用独立 Gmsh 进程，不与独立文件工具共用。取消排队任务不会启动进程；取消运行任务等待该进程实际退出，重复取消不绕过退出确认。BREP 准备阶段采用合作取消，等导出结束后停止后续剖分，不终止 OCCT 几何进程。服务停止时终止所属剖分进程，重启后未完成记录标为“已中断”，不会重放或自动重试。
- `POST /api/documents/:id/mesh/jobs` 传 `background:true` 返回 HTTP 202 的任务描述；省略时保留等待结果的接口。`GET /api/documents/:id/mesh/jobs` 查询记录，`GET /api/mesh/jobs/:jobId` 读取状态/完整结果，`POST /api/mesh/jobs/:jobId/cancel` 取消，终态任务可通过 DELETE 删除。每个工程仅允许一个未完成任务，避免重复提交。
- 网格结果仍不随 `.cadproj` 携带；恢复依赖原服务器的数据目录，复制/打开工程包不会串用其他工作区的结果。已下载的文件不会被自动改写，不能把历史文件当作当前工程有效结果。大任务的精细内核进度仍未实现；网格线的分块读取见下方候选能力，不能将它等同于全部结果已流式化。

### 网格质量检查与定位

- 入口：网格 → 剖分 / 修复 / 质量 → 结果卡 → 网格质量检查。提供质量分布、Body/问题类型筛选、动态阈值和分页问题列表。筛选只查询已保存数值，不重跑 Gmsh，不修改几何。
- 质量和面来源报告以任务、筛选条件和打开轮次绑定响应；更换条件时立即隐藏旧表格/旧筛选统计，旧成功或失败都不能覆盖新查询。重开报告及“查询已有结果”会重新只读读取；展开内部的分布或属性详情不会重新请求整个报告。“全部单元”显示为单元明细，不把正常单元叫作问题单元。
- 工程结果使用 `minSICN` 形状指标，反转另按自适应 `minDetJac < 0` 判定；数值退化按最小/最大 Jacobian 的相对量级判定（阈值 `1e-12`，零 Jacobian 不归类为反转）。指标定义及采样/自适应区别见 [Gmsh API 文档](https://gmsh.info/doc/texinfo/#gmsh_002fmodel_002fmesh_002fgetElementQualities)。线性和高阶四面体都参与计算；独立文件工具仍支持原有其他 Gmsh 质量指标。
- 统计区分低质量、反转、退化和无法计算；“所有问题”取并集，分类计数可能重叠，不能简单相加。平均值以有限质量值数量为分母，空结果/无法计算返回空值而不是伪造零。接近 ±1 的浮点误差仅在 `1e-12` 内归一，真正越界值明确报告。非四面体在文件分析中标记未覆盖，不能把部分统计当作完整质量验收。
- 质量单元索引单独保存为任务目录的 `quality.json`，包括原生单元编号、四个角点、完整高阶质量值、Gmsh 体标签和全部 Body 来源；纳入长度/SHA256 校验。`GET /api/mesh/jobs/:jobId/quality` 支持 `threshold`、`bodyId`、`issue`、`offset`、`limit`（最大 100）。编号以字符串传递，避免 JavaScript 数字精度损失。共用单元全局只统计一次，但可归属于多个 Body。
- 点击“定位”聚焦并透视高亮单元，清除原 CAD 选择着色，不改动几何、材料、透明度或整体网格显示。隐藏全部所属 Body 时诊断高亮隐藏，恢复 Body 时保留定位意图。上游变化后历史报告仍可查看，但不允许定位到当前几何；精确撤销恢复相同身份后可重新显示。WebGL 重建会恢复诊断图层，诊断对象不参与 CAD 拾取。
- 高阶定位目前显示四个角点的外框，不是曲边单元重建。旧任务没有单元索引时明确提示重新剖分，不显示伪造空列表。ASCII MSH 输入检查声明/读入单元数量，旧版 MSH 另核对编号，4.x 核对编号范围；本地 SDK 无法完整保留的混合阶次或超大编号输入明确拒绝，不静默重编号。二进制及其他网格格式仍依赖 Gmsh 读入，尚无独立全格式一致性验证。
- 原始质量索引仍有 256 MiB 上限。分页/筛选使用独立线程和可重建的分块查询索引；完整结果验收逐单元读取，首次分页构建也已采用分批排序和磁盘合并。原生分析仍保留全部单元向量，旧内联显示结果仍有全量路径，不能据此认定整个大网格工作流已完成流式化。

### 大网格质量分页（候选实现）

发布状态说明：当前候选尚未成套切换到日常前端/主进程。现有 Gateway 启动器仍直接运行工作区源码，按需新建线程会读取对应脚本；因此“未重启”不等于后台完全固定版本。后台和子线程的不可变运行快照是下一项优先整改，勿将前端固定发布当作整个服务链已隔离。

- 首次查询从已校验的 `quality.json` 建立 `quality-pages` 派生索引，按全工程及 Body 保存数值汇总和排序块；每块最多 1024 单元 / 512 KiB。共享单元在全局只计一次，各 Body 保留归属；原始单元编号仍用字符串，不转成 JavaScript 数字。阈值、问题类型、分页顺序、直方图和空状态与原算法保持一致。
- 首次构建复用逐单元读取器，将最多 8192 行 / 8 MiB 的批次排序后写入专属临时段，再以最多 16 路进行有界合并。每个 Body 接收全局有序流的归属子序列，不重扫整份数据；全部 Body 的待写分页共用 8 MiB 逻辑缓冲预算。原始顺序的补偿统计与排序后的分页分开计算，保持旧查询语义。
- 排序段逐段核对长度、摘要、行数和文件身份，确认完整读取后才删除；临时段、输出页和清单都计入本次重建的 1 GiB 工作区预算，不能每个文件分别享有该上限。完成后核对每组页数/分类计数以及工作区字节核销，再发布完整清单。取消、磁盘不足或损坏暂存不改坏原始结果；旧缓存无需仅因新排序方式而强制重建。
- 后续查询仍以 1 MiB 缓冲流式核对原始文件的 SHA256，不靠时间戳决定是否可信；只解析有内容凭据的清单、阈值边界块及当前结果所需块，不重新解析或排序全部单元。选中块的校验与解析使用同一打开文件所读的字节；派生索引绑定原始摘要、任务和完整来源身份。缓存缺失/损坏可重建，原始文件损坏则拒绝并保留证据，不把两者混为原网格失效。
- 默认 1 个活动查询线程、最多 8 条排队，180 秒截止包含排队时间；关闭报告、切换筛选、浏览器断线会取消对应请求。取消、超时、资源不足不改坏原网格状态；删除任务及停机等待该线程确实退出后再清理。返回前重新观察几何状态，查询期间修改几何不会得到旧的“当前有效”标记；已删除的任务不再发布迟到结果。
- 原始文件最多 256 MiB、清单 16 MiB、单任务派生缓存 1 GiB、单次分页块读取 16 MiB；页大小仍最大 100 行。线程的 1 GiB V8 主堆设置并非进程总内存/RSS 上限，文件缓冲和其他线程另计，参见 [Node Worker resourceLimits](https://nodejs.org/api/worker_threads.html#new-workerfilename-options)。容量失败有独立查询错误，不将原网格标为损坏，也不自动重跑 Gmsh；达到固定容量上限时不能靠重复相同请求绕过限制。
- `GET /api/health` 的 `runtime.meshQualityQueries` 可观察活动数、排队数、构建次数、解析字节、分页读取量以及最近成功构建的 `lastBuild`（批次、合并轮次、并发输入段、逻辑工作区峰值/写出字节及分页缓冲），不包含模型参数、文件路径或密钥。缓存不随 `.cadproj` 导出；已有全局缓存预算与安全回收，原始结果总容量及空闲磁盘治理仍需继续。
- 后台质量/材料队列默认 180 秒总截止；前端质量报告、面报告和完整结果读取采用 190 秒预算，列表/控制读取仍为 15 秒。关闭报告、切换筛选/工程或停止工作区仍主动取消，超时不会自动重发建模或剖分命令。这些是本机网格处理预算，不改变大模型超时设置。
- 首次构建的独立进程对照为 `node scripts/benchmark-quality-sort.mjs`，可用 `CAD_QUALITY_SORT_COUNTS` 选择 10 万/50 万/100 万记录。各样本使用独立冷缓存与相同 1024 MiB 老代上限，记录 Node maxRSS、实际工作区峰值及总写出字节。更低大样本内存伴随更多 I/O 和更长首次耗时，小样本开销也可能上升；固定角点的合成数值样本不是实际工业网格认证。
- 压力脚本：`CAD_QUALITY_VARIANT=baseline|paged`、`CAD_QUALITY_COUNTS=10000,100000,500000,1000000`，运行 `node scripts/benchmark-mesh-quality.mjs`。这是合成数值/I/O 查询样本，不是百万四面体的真实剖分、空间有效性或视口渲染认证；报告包含环境、源码摘要与计时范围，首次索引构建和后续翻页分开记录。

### 网格线按需分块显示（候选实现）

- 工程联合剖分的新结果不再把全局、每个 Solid 和各 Face 的坐标数组重复塞入 JSON。Gmsh 将网格线写入任务私有 `render.bin`，结果只返回分组归属、共享 `wireKey` 和块清单；网关封存整文件及各块的长度/SHA256。原生仍在剖分结束时生成整个显示文件，并非隐藏时完全不做网格线工作。
- 默认隐藏时页面不请求任何网格线块，也不创建网格 BufferGeometry。仍只有每 Body 一个显隐按钮，以及网格窗口的整体显隐；整体开关保留各 Body 的显示选择，不额外增加一套面/体显示控件。Body 隐藏取消未完成读取，恢复后复用已验证的块；多个 Body 共享同一 Gmsh 实体时只加载和分配一次。
- `GET /api/mesh/jobs/:jobId/render?wireKey=wire-3-1&chunk=0` 返回 float64 小端二进制；面使用 `wire-2-<tag>`。每块最多 1 MiB，整显示文件最多 2 GiB，结果清单最多 16 MiB。后台检查工程来源、任务状态、经过独立验收的结果和块内容；删除、取消、来源变化及损坏回复不能发布迟到数据。准入证明只在进程内短暂复用，最长 30 秒后重核全部材料；每次提供的清单/数据块仍独立校验，不声称持续监控所有磁盘文件。
- 视口最多同时读取 4 块，15 秒单块截止；每个块只创建一次 Float32 属性，隐藏块可复用或按预算释放。默认 256 MiB 是 CPU 几何属性预算，不是浏览器总内存或 GPU 显存上限。超预算、超时、错误分组和内容校验失败会明确停止显示，不自动重试；需要用户改变显示选择后再读取。HTTP 错误诊断也限制读取量。原生 RPC 单条回复最多 64 MiB、请求最多 16 MiB，旧内联结果仍可读取，但超限不会无限积累。
- 显示状态使用现有消息条报告载入百分比及就绪块数，没有新增常驻窗口。旧原生程序不支持 sidecar 时保留内联兼容；新版网关、Gmsh 与前端应成套验收，不支持仅升级一端后宣称性能整改已生效。
- 专项入口：`node --test tests/mesh-render-store.test.mjs tests/mesh-wire-layer.test.mjs tests/mesh-wire-publication.test.mjs tests/mesh-wire-integration.test.mjs`；真实页面为 `node scripts/verify-mesh-wire.mjs`，需 `WORKBENCH_URL` 指向新版候选页面。CMake 选项 `MESH_WIRE_BENCHMARK=ON` 可构建独立 `mesh_wire_benchmark`，再运行 `node scripts/benchmark-mesh-wire.mjs`。该压力脚本使用真实 Gmsh 中的结构化离散四面体，验证实际原生序列化与封存读取，不是百万单元 CAD 修复/剖分、完整准入载入或浏览器/GPU 渲染认证。
- 尚未解决：原生质量分析的完整单元向量、原始结果总容量、复杂大归属回复预算及真实工业大装配/大网格全流程压力。在线验收和首次分页构建均已分块处理；按需显示或局部改造不能替代剩余工作。

### 完整网格载入与封存线程（候选实现）

- 在线路径通过 `MeshArtifactPool → mesh-artifact-thread → MeshJobStore` 完成完整结果读取、MSH/质量/显示文件校验、准入重算和结果封存。同步 Store 是材料线程内的底层实现，在线路由不直接扫描大文件。质量 JSON 的封存/首载验收和首次分页构建采用逐单元读取，仅显式离线参考入口保留整份解析。
- 默认 1 个材料线程、8 条排队、同一材料快照最多 32 个并发观察者、180 秒总截止（含排队）；相同读取合并为一次实际校验。单个观察者取消不影响其他观察者，最后一个取消才停止线程。删除任务、取消封存及停止服务都等真实线程退出后清理暂存。新结果先写专属暂存文件，父进程核对文件身份并在成功退出后发布；线程只发出回复不等于结果已发布。
- 完整 JSON 校验和解析使用同一个已打开文件读出的字节，前后核对文件身份，避免先哈希一个版本再解析另一个版本。读取取消、排队/内存/时间限制返回独立错误，不把原有有效网格标成损坏；新任务封存失败则不会作为“完成”发布。验收返回后再次观察几何及任务身份，删除或几何变化不能得到迟到的可显示结果。
- 材料线程的 V8 老代预算为 1 GiB、年轻代 32 MiB，回复最多 64 MiB；原质量文件仍最多 256 MiB。质量分页与材料队列保留各自状态，但现在共用一个重计算名额，不同时启动两类线程；这些不是整个 Gateway 进程、外部 Buffer、原生 Gmsh 或 GPU 的总内存上限。修复 BREP 快照复制和准备清单读取也进入此线程池，少量元数据保存和文件发布仍有同步路径。
- 原有每 Body 的网格按钮在校验中保持显示意图，并标记忙碌；再次点击同一个按钮可取消。不同 Body 的异步回复按当前选择合并，不恢复刚隐藏的 Body；整体隐藏会取消仍在等待的本地显示观察。未通过验收之前不会绘制网格，不新增确认弹窗、第二个按钮或主题配色。
- 工程任务下载增加流式内容验证、背压和有限缓冲，最后一块在长度/SHA256/文件身份核验后才发出；内容在下载中变化会中断，不完成错误文件的响应。`X-Content-SHA256` 表示期望摘要。独立文件级工具不因此获得工程来源或准入认证。
- 大量小数质量值原先使用普通累加，会把正常的大网格误判为汇总矛盾。原生、准入重算和质量分页现在使用 `neumaier-v1` 补偿求和；旧分页缓存重新建立，原文件不变。旧质量报告只兼容可从原数值顺序复现的旧累加结果或精确新结果，不放宽原有 `1e-12` 一致性容差；新报告必须匹配补偿结果。
- 健康检查的 `runtime.meshArtifacts` 报告活动/排队数量、实际线程次数、合并数和回复字节，不包含几何参数、路径或密钥。专项：`node --test tests/mesh-artifact*.test.mjs tests/mesh-download.test.mjs tests/mesh-statistics.test.mjs`。压力对照：设置 `CAD_ARTIFACT_VARIANT=baseline` 或 `threaded` 后运行 `node scripts/benchmark-mesh-artifacts.mjs`；默认 1 万到 100 万共形四面体条带的数值/I/O 样本，质量值、CAD 清单和 MSH 文本仍为合成夹具，不能替代实际工业剖分、任意空间无交叠证明或大网格 GPU 验收。新结果保存为 `mesh-artifacts-connectivity-<variant>.json`，不与此前重复单元夹具的报告直接混比。

### 大质量索引逐单元验收（候选实现）

- `MeshJobStore.writeResult/readResult → withStreamedQualityIndex → assessMeshAdmission` 不再同时保留完整质量 JSON 字节、字符串及全部单元对象。第一遍读取元数据与 Float64 坐标块、计数单元；第二遍逐单元解析、校验唯一编号/归属/连接和原有数值门禁。字段可任意排序，不强制调用方使用原生输出顺序。
- 两遍均从同一个打开文件按块读取并计算完整 SHA256/长度；首遍核对封存凭据，第二遍必须与首遍完全一致，最后再核对路径/句柄身份。只有全部校验完成才返回验收结果，未知质量版本等提前返回的判断也不能跳过剩余单元验证。继续使用原来的补偿求和、旧数值兼容及 `1e-12` 容差，不信任保存的 invalid/inverted 标志。
- 来源仍最多 256 MiB，默认 64 KiB 读取块，单值/单元最多 1 MiB、嵌套 64 层、根字段最多 64，坐标标量最多 128 字节。坐标按每块 16384 个 Float64 数值保存，累计最多 256 MiB；null 用内部标记保存，计算时恢复原语义。严格 UTF-8，兼容仅位于文件开头的 BOM，不接受值前 BOM、重复根字段或尾随数据。超限为资源错误，不把有效的原网格标坏。
- 这不是恒定内存算法：坐标仍随节点数增长，精确单元编号去重集合仍随单元数增长；旧内联结果 JSON 和原生分析向量尚未因此变成流式，首次分页排序另有磁盘工作区及元数据成本。`streamQuality:false`、`referenceBuild` 仅为本地离线对照选项，不是 HTTP 放松验收的入口。
- 专项：`node --test tests/mesh-quality-stream.test.mjs tests/mesh-quality-pages.test.mjs`。对照：`node scripts/benchmark-quality-stream.mjs`，默认 10 万/50 万/100 万重复数值单元，各样本新建进程、同样 1024 MiB 老代上限，原始质量文件及源码有摘要记录。报告 Node 的 maxRSS 和内存快照，不冒充整个 CAD/GPU/原生进程总峰值；固定四个节点的数值样本不代表真实百万单元剖分或节点密集大工程。

### 网格计算与缓存容量（候选实现）

- 一个 Gateway 的质量分页、完整材料验收共用 FIFO 计算名额；取消或超时不会提前释放，必须等实际线程退出及暂存清理完成。等待这个名额也计入原请求总截止。任务删除同样取得名额，避免它删除另一个缓存清点线程正在检查的目录。原生 OCCT/Gmsh、下载流及浏览器不属于这个名额的总内存保证。
- 可重建质量缓存默认总计 4 GiB，单个完成缓存及单次重建工作区各最多 1 GiB，均按逻辑文件字节计。新建缓存预留整个工作区预算，排序段和新页共同计入，旧缓存并存时也计入全局总量；总预算必须至少为单次预算的两倍。这不是“重建时新旧合计只占 1 GiB”。优先淘汰较久未使用的安全缓存；原始 `quality.json`、MSH、BREP、`render.bin`、工程历史和属性不会自动回收。
- 只清理受管任务下、具备归属记录的已知分页文件；规范 `sort-N.run` 仅在 UUID 专属暂存目录中视为可重建内容，在完成缓存中仍属未知文件。清点拒绝链接、共享硬链接、未知子目录和不完整清单；未知文件保留，不为达标强行删除。默认最多 10000 个任务、200000 个目录/文件条目及 128 MiB 元数据。预算不足或不安全时返回容量错误，原网格不被标成损坏；缓存被回收后从已验证原索引重建，不重跑剖分。
- 新任务记录默认全局 2000、单工程 500；失败和中断记录也计数。达到上限只拒绝新增，已有超量旧记录不截断、不自动删除；可通过已有任务历史入口明确删除不再需要的任务。此准入数量限制不是历史目录冷启动的分页实现，也不是原始结果总字节/磁盘剩余空间配额。
- `.env` 可设置 `GEOMETRY_MESH_CACHE_BYTES`、`GEOMETRY_MESH_CACHE_JOB_BYTES`、`GEOMETRY_MESH_MAX_JOBS`、`GEOMETRY_MESH_MAX_JOBS_PER_DOCUMENT`，示例值见 `.env.example`。变更在受控重启后生效，读取中不会静默更换预算。工作台日常服务没有因本批候选改动自动重启。
- `runtime.meshCompute` 报告共享名额和等待数；`runtime.meshTaskCapacity` 报告记录数量及上限；`runtime.meshQualityQueries` 的 `cacheBudget`、`cacheCapacity`、`lastError` 和累计缓存回收指标提供最近一次观察。它们不是连续磁盘监控或 OS 硬配额，不输出内部路径/参数/密钥。资源不足、内存峰值、原始结果容量和安装恢复的剩余工程化工作仍需继续。

### 修复快照与在线工程操作（候选实现）

- 活工程队列只负责捕获身份及执行 OCCT 原生导出。导出的任务专属 BREP/来源清单随后由现有材料队列检查、复制和解析；等待重计算名额或磁盘处理不会占住活工程的命令队列。期间可以继续编辑，旧来源得到的结果会明确过期并保持隐藏，不被重新标成新几何。
- `source-manifest` 读取严格 UTF-8 JSON，最多 16 MiB，核对完整 Body 身份和修订版。`capture-prepared` 保存修复预览快照；`reuse-prepared` 在同一后台操作内检查已封存预览并复制其 BREP/清单，避免先验证、回主线程再按路径盲复制。复用只返回诊断概要与来源清单，不把完整预览数组再传回主线程。
- 文件复制采用同一已打开来源、固定 1 MiB 缓冲和独占暂存文件；复用时以预期 SHA256/长度核对实际写出的字节。父进程等线程成功退出，复核两个暂存文件身份后才移动到受管目标；不覆盖已存在的目标。只有后续结果封存及任务元数据提交完成，预览才作为 complete 发布。两文件移动不是操作系统级联合事务，中途失败不会发布完整任务，残留未提交文件可能保留以供恢复。
- 来源或目标任务取消、删除以及服务停止均使用已有退出屏障，复制线程未退出不清理它的暂存；占满队列/预算、磁盘写入失败和原始内容损坏分别报告。拒绝跨工程、目录链接及共享硬链接。仅改名称/材料的修订仍可使用原几何身份相同的封存快照。
- 首次原生导出按受管不可变文件使用；文件身份/时间戳检查不等于对敌对外部写入的操作系统独占锁。已封存快照的复用另有内容摘要校验。JSON 主体仍非流式解析，主线程仍有结构克隆、元数据提交及少量文件移动成本。
- 专项：`node --test tests/mesh-preparation-files.test.mjs tests/mesh-job-lifecycle.test.mjs tests/mesh-preparation-integration.test.mjs`。I/O 对照：`node scripts/benchmark-mesh-preparation.mjs`，默认 16/128/256 MiB 重复字节文件，比较同步离线 Store 和在线后台处理；不是合法 BREP、修复吞吐或峰值内存认证，线程化也不保证总处理时间缩短。

### 工程网格验收门禁（候选实现）

- “任务已完成”“来源仍有效”“验收通过”是三个独立状态。验收按 `tetra-preprocessing-v2` 核对保存的数值索引、完整 Solid/Face 覆盖、Body 来源、共形接口及内嵌面报告，并独立检查角点连接拓扑，不以进程正常退出或正 Jacobian 代替整体可用性。
- 网关从 OCCT 的封存 BREP/v2 清单提取 `sourceInventory`，覆盖网格进程自报的同名字段。Gmsh 返回 `preparedSolidIndex`，专指封存后复合体中的 Solid 编号；原 `solidIndex` 继续表示原始 Body 内的 Solid 编号，不能混用。遗漏整个拆分体或来源面、接口漏检、空体、错误归属、反转/退化/非有限单元、数值与汇总矛盾均阻止普通网格显示和下载。
- 正常但低于用户质量阈值的单元是警告，不以任意形状阈值拒绝薄层。阻止使用的结果仍保存 MSH、数值索引和来源信息；数值质量问题可筛选定位，连接拓扑报告内最多 8 个已验证样例可直接定位。重复单元显示红色角点外框，公共面异常另显示黄色角点三角面；这不是完整问题分页，也不把网格三角面当作 CAD Face 拾取。显式“下载诊断 .msh”使用 `?diagnostic=1`，文件名带 `diagnostic-`，响应携带验收状态、策略及来源修订版。已保存后损坏的文件连诊断下载也拒绝，保留磁盘证据；执行阶段结构性无效的回复不作为可检查结果发布。
- 样例坐标在同一次完整内容校验内从质量索引提取，带参与单元与 Body 身份，不在点击时另读整个文件；超长编号明确截断且禁用定位，缺损坐标、错误归属、来源过期或所属 Body 隐藏时不显示错误热点。隐藏再显示、WebGL 恢复保留有效定位；清除定位不写几何历史。仅有边界总量不一致而没有可靠局部坐标时提示诊断下载，不随便挑一面代替。验收结论在报告滚动时保持可见，“数值质量检查”与“连接拓扑”分开，正质量值不表示所有连接合格。
- 角点连接检查拒绝不同编号的重复四面体、三个以上单元共用的面、共享面方向不一致及外露三角面数量与实际外边界不符；高阶四面体重复角点也按无效单元处理。键比较使用完整节点元组，不以哈希相等当作同一面。`admission.topology` 的依据为 `tetra-corner-connectivity-v1`，不会把总量核对描述为每一面空间匹配或任意交叉检测。
- 精确打包索引动态增长，四面体键上限 2^22 槽（80 MiB），面键上限 2^24 槽（256 MiB），装载率不超过 70%，每次查找最多 1024 次探测；扩容暂时同时保留旧/新缓冲，不能把 336 MiB 当前表上限当作进程峰值内存。容量、探测或分配失败返回独立资源错误并保留原始材料，不接受部分检查。原来的坐标、单元 ID、线程堆和文件预算仍分别适用，整个进程 RSS/全局资源预算尚未由此统一。
- 恢复后不信任持久化的“通过”标志，载入结果时重算验收。缺少完整证据的旧结果标为“尚未完成网格验收”，只供诊断，需用匹配的新版内核重新剖分。正常显示与下载在后台同样受门禁保护，不仅是禁用前端按钮。
- 13 个代表性合成样本验证接触、嵌套、交叠、多 Solid Body、薄板/铜层、内部交叉 Sheet、真实微小间隙、曲面通孔、参数/朝向修复和严格模式拒绝、开壳与交叉线框拒绝；逐字节核对原 BREP 不变，核对每 Body 体积与完整网格覆盖。这不是客户工业模型全集，更不等于任意离散 STL 相交三角形已完成重构。
- 本策略不是仿真求解认证、任意曲边单元或全格式 MSH 的独立数学证明。角点拓扑不验证高阶中间节点完全共形、所有边/顶点的流形链接、任意不相邻四面体空间相交或每个外边界三角形与 CAD 的逐点一致；离散交叉重构、自动局部优化、完整行业验收与大网格全流程规模能力仍在后续范围内。

### STEP 原始来源恢复与保留材料

当前源码及候选版本已完成以下功能和隔离验收；2026-11-15 的日常服务升级尚待明确停机许可，不能把本文的候选能力当作旧日常页面已发布。候选版本为 `frontend-1794726703586-2298b905-129e-4bed-a3ed-7e7c2d65cf0b`。

入口为“工程 → 来源检查”，其中“来源检查 / 恢复记录”共用原非模态窗口。`SourceRestoreProof` 核对真实持久检查点，`SourceRestoreTransactions` 管理文件事务，`SourceRestoreService` 管理受限上传、可查询记录及异步执行，Windows 辅助程序为 `cad_source_file_swap`。可先 `npm run build:worker`，再运行 `npm run test:source-restoration`；页面专项为 `npm run test:ui:source-restoration`，它使用临时工程和独立的受管生产前端，走真实同源转发，不操作日常数据或调用大模型。页面专项使用当前已选定的生产构建，需先运行 `npm run build:release`。

1. 明确选择当前工程或全部存储范围并运行检查。在缺失/变化且有真实引用的文件中展开详情，点击“选择原始文件恢复”。过期报告必须重新检查，保留材料没有此入口。
2. 上传原始 `.step/.stp`。目标路径由后台检查报告确定；候选必须匹配所有已发现引用，并有受校验持久检查点作为证据，不接受同名但不同内容的模型。
3. 候选通过后查看影响工程、实际引用数及前后文件证明；完整 SHA256 与原生指纹分开展示。点击“恢复原始来源”才替换文件；无嵌套确认弹窗，不重建几何、不改变工程修订版。
4. “恢复记录”可按当前工程或全部工程分页查看，允许重查、显式重校验、放弃并保留材料、回退或人工复核。关闭窗口不取消已接受操作；响应丢失时只查询原 ID，不自动重传候选或重发动作。
5. “回退到恢复前”恢复旧文件，旧文件可能仍损坏；原来缺失则回到缺失状态。这不是 CAD Undo，所有版本继续保留。固定角色下载可供核对，文件缺失会明确标出，不伪造可下载链接。

存在未确认来源事务时，视口显示全局阻断提示，建模按钮与构造输入禁用，来源诊断和记录仍可查看。未知外部版本不能通过“重新核对事务”强行覆盖；实际文件回到已证明的版本后显式重新核对，解除阻断，再点击“重新载入工程”。系统不自动重放之前的建模请求。

全局清点包括恢复区候选、操作前副本、替换/回退时实际移出版本及暂存材料，单独标明操作归属。它们不是可消费的建模输入，零几何引用不等于可以删除；不完整上传、孤立目录或损坏元数据会降低覆盖完整性。恢复证明自身排除该私有命名空间，避免把自身候选/暂存写入当成工程依赖变化。

恢复只认证与原导入指纹相同的 STEP 字节，不重算或改写 CAD 历史。候选、原文件、原生替换时实际移出的版本以及回退时移出的版本均保留；记录或实际内容不明确时进入人工复核，不自动重试。实现没有宣称能阻止外部程序改写，也没有宣称跨文件断电原子性。Windows 替换语义参见 [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) 与 [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)。

后台接口（动作必须显式发起，不应直接对日常数据做接口实验）：

```text

POST /api/source-restores/<restore-UUID>/prepare?scope=<current-undo-redo或storage>&documentId=...&auditJobId=...&assetId=...&fileName=...
GET  /api/source-restores/<restore-UUID>
POST /api/source-restores/<restore-UUID>/<commit|rollback|revalidate|abandon|review>
GET  /api/source-restores/<restore-UUID>/files/<candidate|before|retained-N|recovery-N>
```

准备请求使用 `application/step` 二进制内容，只能选择未过期的来源检查报告中缺失/变化且确有引用的资产；不接受客户端目标磁盘路径。操作 ID 在上传前生成，同一 ID 不能再次上传。上传限制复用 `GEOMETRY_STEP_LIMIT_BYTES`（并受 200 MiB 候选上限约束），全局只接受一个来源恢复任务，最多保留 1000 个操作目录；查询每页最多 50 条。执行动作只接受空 JSON 对象。HTTP 202 代表已接受而非已完成，后续必须 GET 原 ID；断线不重发写请求，关闭网页也不取消已经接受的后台验证。部分上传不能按完整候选重校验；放弃不删除保留材料。

启动先核对文件事务，再进入普通工程恢复；未完成或待复核事务阻断来源敏感的工程操作，来源诊断与记录仍可查看。健康状态在 `storage.sourceRestoration` 单独报告阻断与活动操作。正常文档队列使用共享访问门，来源替换使用独占门，读取状态不等待文件替换，也不扫描正在改名的暂存材料。停止时等待上传到验证的完整任务交接，文件替换进程未确认退出时不主动释放数据目录写入所有权。不同几何的显式重绑、来源安全回收和完整跨平台生命周期仍未实现。

启动会等待几何网关和工作台均可访问，重复启动会复用本次管理流程已启动的服务。默认后台隐藏运行，日志与进程身份保存在 `runtime-logs/services/`。停止前会核对进程 ID、启动时间、可执行文件和脚本路径，只停止匹配的受管进程树；不会按端口号直接结束其他进程。

受管前端默认使用 Node 生产运行器，不再使用 Vite/HMR 或 Miniflare 作为日常服务。构建先复制受校验的源码快照，在 `.releases/frontend-<时间>-<UUID>/` 生成独立版本并核对全部文件长度及 SHA256，再原子更新 `selected.json`。运行中的前端固定使用自己的版本；重新构建不会替换其资源或自动重启。没有可用发布版本、清单损坏、运行依赖不匹配时拒绝启动，不静默回退到开发模式。

受管 Gateway 默认也使用固定版本。`build:backend` 的 V3 发布将 Gateway、查询线程、共享规则及 CAD/MCP 适配器封存到 `.backend-releases/backend-<时间>-<UUID>/runtime/`，把 OCCT/Gmsh 及辅助程序的递归 PE 静态/延迟 DLL 依赖封存到独立的 `native/geometry`、`native/mesh`，并在 `pi-sdk/` 固定原生 Pi 源码与锁文件匹配的已安装运行依赖。默认 SDK 输入为相邻 `../pi`，也可通过构建进程的 `PI_SDK_ROOT` / `--pi-sdk-root` 指定。源码、模块语法、文件清单与 SHA256 均核对后才选择下次启动版本。Pi 启动另校验 SDK，不使用外部旧 `PI_CLI_PATH`；设置、历史、缓存和工程工作目录写入数据区。`.env`、工程、密钥和用户会话不进快照。

这个范围是 **项目代码、原生 PE 导入及 SDK 已安装依赖闭包隔离**，仍不是完整离线安装包或操作系统防篡改。Node/系统运行库、原生动态插件/资源和用户扩展仍为外部依赖，前端运行器仍需工作区 vinext；SDK 清单不等于 npm 包来源签名或许可证合规认证。健康接口 `backendRelease` 明确区分 V3 的 `project-code-native-pi-sdk-v1`、V2 原生闭包和旧 V1 项目代码。`--external-pi-sdk` 显式构建 V2，`--project-code-only` 显式构建 V1，不与自定义 SDK 输入混用。当前仅验证 Windows x64、相同 Node 精确版本，升级 Node 后须重新构建。旧源码 Gateway 仍显示 `WorkspaceSource`，需要显式停止再切换，构建或重新 Start 不会自动升级它。详见[后台发布范围](docs/BACKEND_RELEASE_zh.md)。

生产构建把浏览器 API 固定为当前网页的 `/api`，由本机前端流式桥接到启动时指定的 Gateway；更换后台端口不需要重新编译。STEP 上传、普通请求及 Pi SSE 不整体缓冲，不自动重试。后台连接失败返回 `FRONTEND_GATEWAY_UNAVAILABLE`：刚提交的操作结果仍须查询工程或任务记录，不能据此重发。服务仅绑定 `127.0.0.1`，检查本机 Host 与浏览器 Origin；它不是可直接对公网开放的多用户部署。

开发时显式使用以下方式（若生产服务已运行，须先在允许停机时停止；开发模式的前后端均会读取工作区）：

```powershell
npm run services:stop
npm run services:dev
```

升级日常页面时，先构建并验证候选，待工程和 Agent 空闲后显式切换；只更新前端不需要重启 Gateway：

```powershell
npm run build:release
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-web-cad-demo.ps1 -Action Stop -Service Frontend
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-web-cad-demo.ps1 -Action Start -Service Frontend
```

回退时先只停止前端，再以 `-FrontendReleaseId <已有版本ID>` 启动，可另指定 `-FrontendReleaseRoot <目录>`。显式版本不改写 `selected.json`；下一次不带版本启动会使用选中版本。启动不同模式、不同版本或不同 Gateway 的前端之前必须显式停止原前端，启动器不会自动结束健康服务。请保留需要回退的版本；当前没有自动版本清理/回收器，也不要编辑发布目录中的文件。

仅更新后台时，先完成候选验证，在工程和 Pi 空闲且允许停机后执行以下流程；前端进程可以保留，但后台停止期间不能建模：

```powershell
npm run build:backend
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-web-cad-demo.ps1 -Action Stop -Service Gateway
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-web-cad-demo.ps1 -Action Start -Service Gateway
```

后台回退同样先停止 Gateway，再用 `-GatewayReleaseId <已有版本ID>` 启动，非默认目录可加 `-GatewayReleaseRoot <目录>`。显式版本不会改写下次启动选择；几何、来源、属性和历史仍使用原数据目录。不能将“代码可回退”理解为任意未来数据格式也支持降级，跨数据版本仍需兼容性验证和备份。完整边界见 [后台代码版本固定](docs/BACKEND_RELEASE_zh.md)。

`services:status` 报告前后端的 `Mode`、`ReleaseId` 及前端 `GatewayApi`；曾就绪但页面或资源检查失败的存活进程显示 `unhealthy`，而不是永久“starting”。生产前端健康接口 `/__cad/health` 核对运行版本、所属 PID、资源状态与 Gateway 地址；Gateway 的 `/api/health` 携带已启动的 `backendRelease`，受管就绪要求版本和清单摘要与登记一致。它们不是大模型可用性或所有工程/几何操作成功的保证，也不代表后台代码被 OS 写锁持续保护。客户端资源运行时发生变化会返回 503，保留证据，恢复原文件后仍须显式校验并重启。

发布包包括编译后的前后端、固定版本的本项目启动/桥接代码和 SSR 外部依赖闭包（当前为 React/React DOM/Scheduler），不会复制 `.env`、工程数据和 Pi 历史。当前仍依赖同一工作区的已安装 vinext 生产运行器，核对锁文件及入口 SHA256；不是全依赖树安全认证，也不是可脱离工作区运行的安装包。已验证 Windows/Node 24，本批不声称其他 Node 主版本、跨平台或断电后运行均已认证。

验证入口 `npm run test:services` 使用临时中文目录、独立端口和模拟 Pi，覆盖真实生产页面/资源、同源接口/SSE、前后端分别升级/回退、损坏版本拒绝、存活前端资源损坏、重启恢复、双写保护及端口/PID 冲突。`node --test tests/backend-release.test.mjs` 另验证工作区变更不影响新线程/适配器、子进程快照校验及实际 Gateway API。有限的 30 次页面读取不能替代长时压力、系统休眠恢复、Windows 服务管理或工业样本认证。此前开发运行器 HTTP 500 的故障证据保留；分离运行方式消除了日常服务对开发模拟器的依赖，不等于证明所有失联原因均已消失。

当前 Gateway 支持有界安全停机：拒绝新请求、取消尚未开始的排队操作，给已开始的工程事务留出收尾窗口，再核验所属几何/网格/Pi 进程退出。超时保留恢复证据，不自动重放建模命令；网格进程未退出前保持“正在停止”。启动器优先使用本机私有控制通道，旧后台或超过预算才走受管进程树停止。配置、状态判读、安全边界和验证入口见 [后台安全停机与恢复](docs/RUNTIME_SHUTDOWN_zh.md)。

若端口被旧启动方式或其他应用占用，启动会报错而不会自动接管。先关闭原先启动该服务的终端或确认其进程身份后手动停止，再运行受管启动。状态命令仅报告受管服务；未登记进程不代表不存在。

Pi 随几何网关按需启动，不需要独立 Python Agent。旧 Python Agent 的启动脚本仍保留为显式手动入口，不会随工作台自动启动。

工程几何也按需载入：启动只读取工程目录、处理未完成事务并验证内核握手，不在开放服务前恢复全部历史几何。首次打开工程时走唯一的恢复链路，校验几何与绑定属性；同一工程的并发打开合并为一次读取。工作台及工程管理显示实际恢复阶段，工程列表区分未载入、已载入和失败，不把尚未读取的几何宣称为已验证。

坏清单、不可读几何或损坏事务日志只锁定对应工程，不用新空模型替代。存在有效较早检查点时沿原恢复策略回退，保留原文件并显示异常恢复警告；较早检查点本身可能是合法空工程，须核对数据。若只是属性文件损坏，但绑定的完整检查点有效，工程列表仍提供恢复入口，恢复时备份坏文件并保留检查点中的实例值。没有完整证据的旧属性数据不会被猜测修补。

`GET /api/documents/{documentId}/load-status` 只读返回加载阶段，不触发几何恢复；`GET /api/health` 包含启动阶段耗时、载入数量和原生恢复请求数。动态 JSON 响应使用 `Cache-Control: no-store`。几何进程中断后废止旧载入状态，不把迟到回复记为成功，不自动重放建模命令。当前仍是单个几何进程顺序计算：长耗时几何请求可能阻塞其他工程的几何请求，不能将加载去重等同于多进程计算隔离。

验证入口：`npm run test:ui:loading`；多工程基准：`npm run benchmark:startup`。默认 10/50/200 个单 Box 工程，各做 5 次后台进程冷启动，系统文件缓存不清空；报告保存于 `.artifacts/performance/cold-start-on-demand.json`。这个基准不包含浏览器启动、复杂 STEP 首次打开和原生总内存，也不表示完整工业数据规模已验收。

### BRep 空间摘要、查询成本与发布审计

测量入口位于“检查 → 测量体 / 面 / 边”。结果带有独立单位及 Global 坐标说明，默认显示 8 位有效数字，极大/极小值采用工程计数法，不会把非零微小尺寸格式化为 0。悬停数值可看完整浮点值，展开原始数据或复制结果保留未按显示位数舍入的数值。显示位数不代表内核精度、建模容差或精确算术保证。

测量结果绑定工程状态标识和实际测量对象。切换选择显示“上次选择”，工程状态改变显示“已过期”，不能将旧结果当作当前对象。测量期间更换选择、工程状态变化、关闭窗口，迟到回复不会被采用。Body 的“拓扑边总长”将共享边只计一次，包含曲面的拓扑接缝，不是模型外轮廓周长；旧内核缺少口径标记时明确显示“旧口径”。Face 周长沿该面的参数边界计量，可能包含拓扑接缝的两侧。

测量专项验收：`npm run test:ui:measurements`，在独立临时工程中覆盖实际体/面/边、微小尺寸、完整数值复制、同 R 状态变化、迟到响应、关闭窗口和窄屏操作，不调用大模型或修改日常工程。

- 当前原生响应声明 `spatialPolicy.version:1`。包围盒统一使用 OCCT `AddOptimal`，不使用三角化，也不按形状容差扩张；数值曲面极值仍受 OCCT 数值容差约束，不是精确算术保证。Body 元数据、体/面/边测量、BREP 输出清单和修复诊断采用同一分析策略。API 空间数值保留 Float64 往返精度，不先截成六位小数；负零归一化。Sheet/Wire 的质心分别按面积/长度计算。
- OBB 基于 BRep，明确 `source:occt-brep-obb`、`exact:false`、`minimum:false`，不承诺全局最小体积盒。全模型概览使用各 Body 的分析 AABB；需要有向包围盒时使用现有 `query_model` 的 Body 查询。AABB 近邻关系仍是近似接触/包含判断，实际几何关系使用现有 BRep 关系查询。旧内核概览明确标为 `legacy-worker-bounds`，不将缓存相关结果伪装成新策略。
- Body 的几何统计在实际 TShape、位置/朝向和几何种类不变时复用；名称、颜色等元数据独立输出，缓存不持久化。网关测量缓存按工程与持久几何身份隔离相同修订号的撤销分支，最多 32 个工程、每工程 256 条；只保留空间字段，不保留整份模型/显示缓冲。近邻只保留 Top 32 对，采用有界堆和安全的轴向剪枝；大量重叠时最坏时间仍可能为平方级。
- 网格快照的 `bounds` 是分析包围盒；`indexCertificate` 单独声明保守 OCC 包围盒的版本和策略，用于严格 Gmsh 索引验证。新快照要求证书齐全；旧 V2 修复快照仍按原保守证书解释。质量/质心、索引、邻接与身份校验不放宽，也不按最近几何补配。旧版合成放样的历史构造语义保持兼容，新模型继续使用真实截面放样。
- `npm run audit:project -- --output .artifacts/before.json` 生成只读、空闲状态审计；下一次加 `--baseline .artifacts/before.json --output .artifacts/after.json` 检查工程状态、对象身份及全部历史/属性文件哈希。它不是备份，也不代替写入锁或完整恢复演练；活动 Pi、网格或待恢复事务会阻止通过。本次旧空间策略到 V1 的升级使用单独的一次性审计分支，仍要求全部持久文件哈希精确一致；普通审计不忽略派生数值变化。
- `node scripts/verify-deployed-workbench.mjs --audit .artifacts/before.json` 在真实页面只读检查已审计工程、CAD 像素、STEP 状态接口和原 Pi 会话。生产发布增加 `--expect-release <版本ID>` 核对版本/所属进程、同源桥接及无 HMR。不会导入文件或发送大模型提示；输出保存在 `.artifacts/deployed-workbench/`，截图可能包含工程和已有会话内容，属于本地私有验证产物。应配合前后工程审计使用，不代替发布候选的隔离功能测试。

运行可复现的本地查询基准（临时工程，不访问大模型）：

```powershell
$env:CAD_BENCH_COUNTS = "10,100,500"
$env:CAD_BENCH_SAMPLES = "20"
$env:CAD_BENCH_VARIANT = "local"
npm run benchmark:spatial
```

默认使用空闲端口 8897，可通过 `CAD_BENCH_PORT` 修改；`GEOMETRY_WORKER_PATH` 可指定候选内核。报告保存在 `.artifacts/performance/`，包含环境、实际程序 SHA256、构建耗时、响应体大小、P50/P95、额外测量请求和网关 RSS。正式程序本机 20 次采样结果：

| 分离长方体数量 | 完整空间查询 P95 | 额外逐体测量 |
| --- | --- | --- |
| 10 | 1.65 ms | 0 |

### 多对象属性关联（集合模式说明）

- 工程树“属性类型 → 新增属性类型”中，关联范围选择 Body、Face 或 Edge，再将“关联数量”设为“关联集合”。一个实例最多关联 256 个同类几何对象；同一类型仍可创建多个独立实例。工程级属性维持无几何关联。
- Face/Edge 集合创建时选择分裂策略：默认“人工复核”，变成多个候选时不擅自选择；“跟随全部已验证后代”仅沿内核血缘与持久身份扩展。删除、身份缺失、不完整映射或后代超限仍需复核，不把剩余部分当作完整集合。数量模式与策略创建后固定。
- 保持实例窗口打开，在视口选择后“添加当前选择”，可逐项移除、清空或定位整个集合。工程树单击定位全部成员，双击编辑；隐藏 Body 不画其高亮，再次显示恢复。集合高亮不进入 CAD 拾取，图形恢复重建独立缓冲；属性修改或撤销后不沿用旧关联高亮。
- 待复核集合显示原成员及真实候选。可显式采用全部候选或重新选取并保存；只修改 value 不会重绑。清单显示前 100 项，但保存不截断其余成员。关联、属性值与几何共用事务/Undo；失败不部分保存，旧编辑状态不能覆盖新状态。
- 新集合使用属性快照/类型文件 `schemaVersion:2`；旧 V1 单关联工程保持原行为，读取不改写旧文件。工程包、历史检查点和导入导出验证两种版本。集合 API 使用 `targets` 数组，不伪装成第一个 `target`；Pi 复用现有属性工具。
- 共形网格按每个已验证 CAD 面挂载同一属性实例，每个面只挂载一次。待复核集合不应用任何部分属性；值更新不重剖分，历史网格不挂当前属性。

专项浏览器验收：`npm run test:ui:property-sets`。这不是任意导入面/边的完整命名保证，也不代表任意离散交叉修复或大规模性能已完成。

### 拖拽建模与 Pi 助手（交互说明）

- 视口上方可切换“拖拽建模 / 参数建模”，快捷键 `Alt+M`。基础体/面参数输入框内也可切换并保留表达式；其他文本输入框和中文输入法组字过程中不拦截。创建栏的 9 种基础体、5 种基础面都支持两种入口。
- 长方体等带高度几何：点击起点 → 移动鼠标画底面 → 点击锁定底面 → 沿屏幕中的 Z 轴方向拉高 → 点击完成。也支持按住拖出底面再松开。顶视图使用上下鼠标位移调整高度；`Esc` 取消，不提交几何。球体/球面只需确定半径，矩形面/圆面只需确定平面范围；圆环第二阶段调整管半径。
- 底面锁定后须沿构造高度的正方向移动至少 4 个屏幕像素再完成定高。横向移动、向底面下方移动、鼠标抖动或原地双击都不会误建出被钳制为 1 mm 的薄体；顶视图以向上移动作为定高方向。“重选底面”会重置此保护。需要直接指定薄体高度时可随时使用参数建模。
- 首次落点也使用 4 像素意图阈值：即使轻微抖动跨过吸附网格，也不会提前锁定底面，或直接提交球体/圆面。点击落点后仍可不按鼠标移动预览，再点击确认。
- 定高投影以矩形底面中心或径向底面的圆心为基准，避免透视观察时半径线中点造成高度偏差。工程正在提交修改时，快捷键与按钮一样禁止切换建模方式。
- 拖拽默认使用 Global XY、1 mm 吸附；视口顶部可选择工程中的构造坐标系和 0.1/0.5/1/5/10 mm 步长。“正视构造面”沿局部 Z 观察，底面在局部 XY 绘制，高度沿局部 Z 确定。预览、最终落位及切换参数窗口使用同一坐标系；兼容旧工程的非单位轴偏移约定，不改写既有几何位置。切换坐标系或吸附会取消当前绘制；所选坐标系失效时明确提示，不静默改用 Global。
- 圆管内半径默认外半径的 60%，棱柱默认六边形，楔体和棱台顶部默认底部的 50%；需要精确控制时切到参数窗口。拖拽中切换会带入当前尺寸、位置和参考坐标系，不会自动创建 Body。
- 同一工具的“参数 → 拖拽 → 参数”往返会保留手工输入、变量表达式和坐标系；重新绘制后以新绘制尺寸为准。重复点击当前拖拽方式不取消正在绘制的底面。更换工具、构造坐标系或工程时不沿用旧工具的参数草稿。
- 新建面坐标系默认“跟随来源面”，原点为面参数范围中心，轴为正交单位方向，Z 方向遵循面朝向；上游参数/变量变化会更新坐标系及依赖模型。可显式改为固定快照；失效引用不能通过冻结旧位置假装有效。旧工程面坐标系保持原快照及原始轴，不自动升级；升级须重新选面并选择跟随方式。复制关联坐标系复用持久锚点，不重新使用旧面编号。
- 拖拽提示区用步骤条区分起点/中心、底面/半径和高度，当前步骤高亮；可直接点击“参数输入”或“取消绘制”。高度阶段可用“重选底面”或 `Backspace` 返回底面绘制，保留起点，不提交几何；输入框中不拦截退格键。球体/圆面提示半径，矩形面提示平面范围。创建完成保留当前相机位置和观察中心，连续绘制时不自动缩放；需要调整范围时使用“适应窗口”。打开参数或分析窗口时暂停视口绘制，避免误建模。
- Pi 助手不再提供 Plan/Edit 模式。讨论、澄清和建模均由 Pi 原生会话及 CAD MCP 工具处理；仍保留工具参数校验和工程事务保护。
- 历史 `ModelingAgentPanel` 导入名仅为 Pi 面板别名，不再保留第二套对话界面。旧后端兼容接口尚未整体删除；其兼容性测试与当前 Pi 界面验收分开。界面契约通过实际 React 渲染和浏览器行为验证，不用废弃面板的源码字符串断言证明当前功能。
- 思考默认折叠；每次工具调用的参数和结果合并到一条折叠记录，概要显示工具名、状态及结果对象 ID/Body 数量，点击展开或复制完整内容。模型选择、可用模型的思考级别、压缩、历史、新会话、停止使用原生 RPC；运行中可追加“引导当前任务”或“完成后继续”消息。支持 `/compact`、`/new`、`/stop`；其他斜杠请求原样交给 Pi。
- 原生 `tool_execution_update` 的累计进度会更新同一条工具详情，不重复追加整段文本、不提前显示成功；完成后以最终结果为准，迟到的进度事件不能把已完成/失败/中断的调用改回运行中。此展示不改写 Pi 原生历史或大模型上下文。
- 工具记录以原生调用 ID 保持同一个展示身份；实时执行切换到历史快照时保留已展开的详情，不重复工具行，也不把“执行中”退回“未收到结果”。
- 重连恢复已有会话，不重发上一条建模请求；历史从 Pi 读取，新事件按游标订阅，避免重放旧进程退出提示。首次连接、网络恢复和手动重新连接完成同步后，各进行一次只读工程显示核对；普通历史刷新不会反复载入几何。`SIGTERM` 表示进程被终止，本身不代表大模型超时或几何数据丢失。运行中的调用遇到进程退出会显示“已中断，结果待核对”，不能当作已成功或未执行；重新连接不会自动继续或重发该调用。并发连接等待同一个原生 RPC 启动握手。
- Pi 扩展不再读取旧 Plan/Edit 环境开关；旧的外部 MCP 客户端仍可显式选择只读访问。原生进程退出后关闭其事件订阅，避免仅凭事件通道重连误显示“在线”；重连前一代请求的迟到响应不会覆盖当前连接。思考概要最多摘取 72 字，展开和复制保留完整原文。
- 参数窗口提供“切换拖拽建模”，保留变量表达式等草稿；绘制中右键取消当前草稿而不弹出选择菜单。没有对应按下的鼠标释放不会推进绘制阶段或提交几何。旧网关的英文 Pi 退出信息也会补充中文恢复说明，并保留 SIGTERM 等诊断信息。
- 中文输入法的回车选字不会发送消息；普通 Enter 发送，Shift+Enter 换行。此限制只作用于界面提交，不改写 Pi 的原生会话、工具结果或思考内容。
- 进程退出同时废止该连接仍在途的历史和状态请求；即使旧响应迟到，也不能恢复忙碌状态、覆盖中断提示或替换会话记录。
- 连接协议 v2 使用“原生进程 UUID + 事件序号”，网关重启后不会用旧序号过滤新事件。回放缺口或连接中断时只重连并读取原生快照，不重试发送 prompt/steer/follow_up；原生进程退出则需要手动重新连接。输入草稿与当前工程绑定并在重连时保留。
- “会话在线”要求事件通道与原生历史/状态完成同步，不代表大模型服务可用。快照携带请求前、回复后游标，等待 SSE 追上后重放重叠区间；原生完整消息按身份更新，防止迟到快照抹掉新文本或重复追加。事件回放缓存最多 1000 条 / 4 MiB 序列化数据，慢订阅者待发队列也有 4 MiB 限制；这不是整个 Pi 进程的内存上限。

交互回归：`npm run test:interaction` 检查拖拽尺寸、定高基准、Pi 折叠记录、单模式 MCP 和进程重连；`npm run test:ui` 在隔离工程中验证 14 种绘制工具及真实浏览器操作，不向大模型发送收费请求。

`npm run test:ui:pi-recovery` 使用真实浏览器、SSE 和隔离网关重启验证原生历史/草稿恢复、进程代际切换、快照重叠、折叠进度和 5 MiB 结果分段。Pi RPC 是确定性夹具，不调用收费模型或真实 CAD 工具；为验证视口确实采用最新状态，测试会显式创建少量隔离 Box，最终核对预期工程，而不是声称整个测试中几何完全不变。实际默认 Pi 源 CLI 的握手/关闭和原生工具结果循环另有独立测试。

最新候选版本、测试数量、失败记录及是否部署统一记录在[工业化路线与验收记录](docs/INDUSTRIAL_PREPROCESSING_ROADMAP_zh.md)，不把旧批次的数字当作当前总数。日常工程另做只读状态和文件核对；夹具、源码 SDK 或页面在线均不等同于付费模型端到端建模验证。

### 脱敏诊断导出（无需重启服务）

遇到页面打不开、后台不可用或版本不匹配时，可在本项目目录运行：

```powershell
npm run diagnostics:export
# 只核对默认安装文件及已选发布元数据，不访问任何服务
npm run diagnostics:export -- --offline
# 自定义本机端口；不读取 .env 中的 URL 或凭据
npm run diagnostics:export -- --frontend http://127.0.0.1:3002/ --gateway http://127.0.0.1:8790/api --timeout-ms 3000
```

报告写入 `.artifacts/diagnostics/diagnostics-<UUID>.json`，只新建、不覆盖已有报告、不上传。可以先检查内容再手动分享；其中仍含软件版本、组件哈希及运行计数，不应把它当作完全匿名报告。即使后台不可达也生成带明确诊断状态的报告；命令成功表示报告已生成，不表示服务都健康。

- 只做三个固定健康 GET：前端生产健康、后台健康及前端同源桥接健康。不启动/停止/重启服务，不查询模型、不调用大模型、不读取 Pi 会话，也不重发未确认命令。离线模式完全不发请求。
- 仅允许回环 HTTP 地址、1024 以上端口及固定路径，不接受用户名/密码、query/hash 或远程地址，拒绝跳转。每次请求默认 3 秒、最多 5 秒，响应默认最多 128 KiB；HTTP 错误正文、连接异常原文和任意后台扩展字段不进入报告。
- 按字段白名单导出版本、就绪/阻断状态、加载/排队计数和内存用量。不会把 `.env`、Provider 配置/密钥、原始日志、工程名称/内容、会话、绝对路径、PID、所有者身份及控制凭据复制到报告。状态缺失或格式不符保持未确认，不把未知来源阻断状态强制转成已解除。
- 对依赖锁及四个默认安装组件固定路径计算 SHA256，1 MiB 读取缓冲，单文件最多 32 MiB、累计文件预算 128 MiB，文件打开前后核对身份和变更元数据；链接、硬链接、读途中变化和超限均不发布可信哈希。只读取已选发布指针及对应的有界清单，不遍历工程或日志目录。
- 区分“运行版本 / 下次启动选择”，不一致会提示但不自动切换服务。默认安装文件哈希不能证明进程实际加载了哪个程序，自定义部署路径未纳入；发布元数据读取不替代完整发布文件验证。三个健康回复也不是同一事务快照，不能证明页面像素、大模型可用、任意几何正确或工业规模性能。

专项测试：`node --test tests/diagnostic-report.test.mjs`。当前工具独立于运行服务，可直接用于旧日常版本；来源恢复候选的发布仍需另行批准，不会被此命令顺带升级。

## 操作步骤

1. 在顶部“创建”分类选择基础体或基础面；视口顶部切换拖拽或参数建模。
2. 拖拽建模先确定起点和底面，再确认高度；参数建模可使用数值、单位、标量变量或表达式。
3. 视口顶部切换体、面、边选择；树节点支持右键管理和双击修改。
4. 在变换、布尔、特征分类执行编辑；操作成功后修订版、几何树和视口同步更新。
5. 在工程管理树中管理变量、材料、坐标系、属性类型和实例；实例关联面或边时可定位高亮。
6. 使用工程分类保存、打开工程包或交换 STEP；底部命令日志可检查失败原因、请求 ID 和耗时。

## 工程文件

“保存工程”下载 `.cadproj` 便携工程包，包含精确 XBF 几何、特征历史、变量、材料、坐标系、直接对象属性、属性类型与实例，以及 STEP 导入特征重放所需的来源文件。打开时保留属性类型和实例 ID，并将来源重新绑定到当前数据目录，不依赖原电脑的绝对路径。

工程包具有版本、数据长度和 SHA256 完整性校验，拒绝损坏文件、不支持的版本及不匹配的属性数据。解压上限默认 512 MiB、上传上限默认 256 MiB，可分别配置 `GEOMETRY_PROJECT_UNPACKED_LIMIT_BYTES` 和 `GEOMETRY_PROJECT_LIMIT_BYTES`。来源文件只允许从受管的导入和工程资产目录打包，不会按 XBF 内的任意路径读取本机文件。

打开采用独立工作区身份；校验失败不会替换可见工程。网关通过恢复日志协调几何快照、属性数据和历史清单的提交，失败时回滚，中断打开在重启时恢复。不要手动删除 `.data/project-transactions` 下的恢复文件。

旧 `.xbf` 仍可打开，但仅包含原格式内的几何数据，不会自动带回独立属性类型/实例或缺失的 STEP 来源。旧文件打开时会提示此限制。若原 STEP 来源丢失或位于非受管路径，需重新导入后才能保存包含全部来源的工程包。

工程包保留建模特征历史，但本版不携带撤销/重做栈、网格结果、Agent 会话或模型服务配置；打开后的撤销栈从新工作区开始。文件以浏览器下载方式交付，界面报告“已交给浏览器下载”，不把下载请求等同于已写入用户磁盘。

### 统一工程事务与属性历史

属性类型/实例的新增、修改、删除、重新关联和类型文件导入，现在与几何操作共用一条本地撤销/重做时间线。纯属性操作不会伪造几何修订号：它可以保持同一个 R，但具有新的历史事件。前端按历史事件刷新属性和撤销按钮，因此不需要刷新页面才能看到属性恢复。

| 层 | 职责 |
| --- | --- |
| `PropertySchemaStore` | 在副本上验证整个修改，原子保存后才发布；类型文件导入全有或全无；损坏数据保持不可用，不当作空属性 |
| `PersistentHistoryStore` | 每个 XBF 检查点绑定独立的属性快照、SHA256/长度和几何 SHA256；撤销/重做恢复成对状态 |
| `CheckpointReader` | 以复用的 1 MiB 读取缓冲分块计算完整几何 SHA256，不缓存文件内容或按时间戳跳过验证；读取前后核对文件身份/长度/变更元数据 |
| `ProjectTransactionService` | 用恢复日志保护几何、属性与历史提交；失败整体回滚，未完成恢复阻止后续修改和不一致读取 |
| Gateway 工程队列 | 几何查看、Agent 查询/上下文、导出和网格快照使用同一工程串行边界，不读取半提交状态 |
| `project-state.mjs` | 从持久化历史事件派生不复用的编辑标识；幂等比较区分操作内容和传输/前置条件 |
| 属性编辑器 / 迁移预览 | 保存读取时的状态标识；冲突保留草稿；默认值采用类型化输入和与提交共用的只读校验 |
| `CommandEditSession` / `CommandEditScope` | 基础体/面、变换、Boolean、特征历史、阵列/面特征、材料/变量/坐标系和几何设置共用编辑基线、忙碌保护及显式重新载入；绘制基线从起点捕获 |
| `CoordinateReference` / `CoordinateSystemStore` | 面参考持久选择器与来源特征身份、稳定依赖排序/循环检测、派生坐标及变换矩阵更新；未完成或失败的重算仅保留局部暂存值，成功后与特征一起提交 |
| `HistoricalInputTarget` / 历史重放器 | 区分特征执行前输入、坐标系、Loft sectionId 及曲线 sweepInputId 历史来源；复用同一重放，先暂存依赖所有权，精确输出处核验身份/指纹与实际面/边，整图通过才统一发布 |
| `TopologyNaming::FeatureResult` / `TopologyHistory` | 创建与重算共用真实生成/修改关系；保留表面、偏置新皮和开口替换面分开命名；完整唯一来源才产生可信生成名，未知/歧义不按位置补绑 |
| `TopologyNaming::SweepResult` / `PatternIdentity` | 以真实内核起止面区分端盖；抽取截面不丢失完整来源歧义；阵列按逻辑行列/序号管理持久槽位，真实变换传播面/边而非枚举对齐 |
| `LoftBuilder` / v2 截面引用 | 真实有序平面截面、显式布置、历史来源身份及端盖/侧面命名；旧 v1 定义独立保留原重放公式，不静默迁移 |
| `SweepBuilder` / v2 曲线引用 | 实际平面截面、有序 OCCT Edge 路径、完整截面放置、G1 验证与实际生成历史；保存截面/路径的历史来源身份，旧直线向量语义保留 |
| 前端控制器 | 同步 `history.eventId` 和 Undo/Redo 可用性；纯属性撤销不替换为错误的几何或要求几何 R 增加 |

工程本地历史包含 `state-*.xbf.properties.json`；单个属性检查点上限 32 MiB，超限在发布前拒绝。恢复日志位于 `.data/document-transactions/<documentId>.pending.json`，v2 日志只引用经过校验的清单备份，不重复装入大显示数组。备份优先使用同盘硬链接，不可用时复制；历史清单只通过原子替换更新。不要手工编辑或删除这些恢复文件。

- 提交前进程停止：重启整体恢复到事务前状态；提交标记已落盘后停止：保留已提交状态。不会自动重放建模命令。
- 普通写入、批次和 Undo/Redo 共用外层事务已经核验的历史基线，不再在内层命令重复扫描；操作前的全历史检查和提交时的完整 SHA256/属性绑定校验仍保留。不会靠修改时间、文件长度或进程缓存代替内容校验。`/api/health` 的 `storage.checkpointIntegrity` 仅提供进程累计读取量、耗时、拒绝数和扫描次数，不含文件路径或内容；不是每个请求的独立性能统计。几何读取缓冲固定为 1 MiB，不代表工程、JSON、内核和视口总内存上限。
- `PROJECT_ROLLBACK_FAILED` / `PROJECT_RECOVERY_REQUIRED` 返回明确的 503 且 `recoverable=false`；`PROJECT_DATA_OUT_OF_SYNC` 返回 409。这里的不可直接恢复表示不能自动重试原写入，应先保留证据并恢复存储/重新载入；不是丢弃工程或清空历史。恢复错误不再转成笼统的 `GATEWAY_ERROR`。
- 检查点、属性或恢复记录损坏：保留证据并明确标记不可用；有完整较早检查点时可整体回退，并在工程标题/命令警告中提醒核对。隔离目录保留原几何、属性快照及活属性文件，不用只有同一个 R 就推断数据正确。
- 旧历史没有属性快照：第一次后续修改先绑定当前已知属性；更早的几何-only历史仍保留。撤销到这些旧版本时只恢复几何并保留当前属性，明确提示不能还原当时的属性值，不猜测或伪造历史。
- 类型编辑/导入是原子的。给已有实例增加必填字段时，需要提供有效默认值，否则整次修改失败；有效默认值会同时补到各实例。类型窗口提供 Bool / Int / Double / 表达式 / 枚举 / 三维向量默认值控件。对已有实例新增字段，先“预览字段迁移”，核对影响实例数、补入值及前 5 个示例，再保存；修改草稿会使旧预览失效。预览与保存共用验证，预览不写属性文件或工程历史。
- 所有涉及新建/重绑 Body、Face、Edge 关联、面坐标系引用或历史输入重选的公共写入，必须携带选择时实际观察到的 `baseStateToken`；缺少返回 428 `SELECTION_STATE_REQUIRED`，过期返回状态冲突。网关/MCP 不会自动查询新令牌后替旧编号续签。完成的幂等重放先于状态校验；新写入不能借此绕过。批内引用新输出使用显式生产步骤 `$ref`，不能以相同显示编号证明来源；失败批次的临时成功统一报告 rolled-back/not-executed，不作为已提交几何返回。该强制要求针对几何选择写入，不代表所有其他写入都已改为必须携带状态标识。
- 属性类型/实例编辑、类型文件导入及树上的复制/删除携带 `baseStateToken`。它来自最近一次读取的 `stateToken`，独立于几何 revision，并随每次工程提交、Undo/Redo、打开工程而变化；后台检查点维护、幂等记录和失败回滚不改变它。跨标签页修改产生 HTTP 409 / `PROJECT_STATE_CONFLICT`，旧草稿保持，不自动合并或覆盖；点击“重新载入最新…（放弃草稿）”后才能基于新数据继续。已删除记录的旧草稿不能误走新建路径。
- 外部命令 API / MCP 可选择传入 `baseStateToken`，`query_model` 返回同一工程状态标识。旧客户端仍可提交不含该前置条件的命令，因此不能把编辑窗口的保护理解为所有外部调用都强制乐观锁。新接入的读改写客户端应始终携带标识；冲突后先查询并重新决策，不能悄悄更换标识重试。幂等键按操作内容比较，重试更换传输请求 ID 不重复执行；已完成请求优先重放，不被其旧前置条件误拦截。
- Int 编辑保留超出 JavaScript 安全整数范围的精确整数字符串，拒绝已经丢失精度的数字值；向量的空分量不再被隐式转换为零。已有实例使用的字段定义只读，新增字段可单独设置默认值。类型树的展开箭头与名称双击分离，避免折叠引起滚动位置变化后误开相邻记录。
- 几何/工程数据编辑窗口现在保留“打开窗口时实际显示模型”的基线，而不是保存时借用最新控制器标识。只读查询不续签旧表单；自身成功提交才推进基线；冲突后锁定旧参数、保留值并要求“重新载入（放弃草稿）”。重新载入会重置参数草稿，需面/边输入的操作还会清除旧拾取，要求用户重新选择。Boolean 不会把消失输入自动换成别的 Body；原特征删除后也不再静默编辑列表第一项。
- 已移除变量/材料/坐标系窗口的“遇到旧 revision 就改用新版本重试”。材料基本数据、自定义属性增加/修改/删除作为一个命令批次整体提交、整体回滚、一次撤销；新增缺失变量并实施建模/特征修改也是一个批次，不遗留半成功的变量。通用批次仍最多 64 步，超限明确拒绝，不分段提交。
- 历史清单增加可选 `stateSequence`（旧文件从 0 兼容读取），响应携带此单调顺序。Undo/Redo 的几何 R 可以降低，工程状态顺序不会降低；客户端按工程 ID 和顺序拒绝迟到响应，不只比较几何 R。幂等记录和检查点维护不推进顺序；若已经发布临时历史后发生事务回滚，顺序保持向前，但编辑标识恢复到原状态，不伪造新的业务修改。重启、工程打开/切换、显示缓存恢复均带入对应顺序。
- 控制器读到新状态而视口还显示旧内容时，会补读完整视图，不把新标识直接贴到旧像素/旧 ID 上。显示缓存合并保留工程级顺序和历史字段；上下文丢失后，过期缓存须重新查询再重建。大装配下该补读流程的带宽/内存仍需 I6 性能基准，未宣称所有大模型场景达标。

本机串行事务与编辑窗口冲突保护不等同于多人实时协作：文件交换入口、外部客户端的强制前置条件策略、多人同步与合并、大历史性能优化及统一追加式审计仍在后续范围。便携 `.cadproj` 仍不携带本地撤销栈。面/边输入的完整可视化引用修复、所有生成拓扑命名和复杂离散交叉重构也仍未全部完成。

## 网格面来源与属性检查

工程剖分使用 OCCT 临时深拷贝完成修复和共形分块，再由 Gmsh 严格导入并生成网格，工程几何不被修改。结果保留 CAD Face→Mesh Face 的多来源关系与面 Physical Groups；自由 Sheet 和内部嵌入面同样保留来源。结果仍默认隐藏，既有每 Body 一个显隐按钮保持不变。

网格窗口的“面来源与属性”可按 Body 筛选、展开属性值并定位 CAD 面。属性按当前持久身份解析；修改属性值后刷新即可，不用重新剖分。过期网格不关联当前面属性、不允许定位到当前几何。旧结果无面来源时明确提示重新剖分，不按面编号猜测。

协议、API、修复模式与能力限制详见 `docs/GMSH_MESH_WORKER.md`。复杂离散交叉重构和大样本脏几何验证仍在后续范围。

## 几何诊断与只读修复预览

在“网格 → 剖分 / 修复 / 质量”中点击“诊断并预览修复”，可先检查当前全部几何，再决定是否剖分。报告按 Body 对照原始几何与修复快照的拓扑有效性、错误/警告、小边、狭长面、开放边、最大容差及有符号体积。开放 Sheet 的边界属于信息项，小特征属于警告，不会被当作应删除的设计错误。

- “深入自交检查”默认用于诊断预览，检查输入与修复后的各 Body；联合分块结果另做拓扑与体积检查。未运行、未完成和已运行分别显示，不能把“快照可用”理解为所有工业验收项目已通过。
- 只读预览显示完整工程的修复快照（包括原本隐藏的 Body），暂时替代原工程显示，不进入 CAD 拾取；退出、关窗或来源变化后恢复工程显示，不提交 Feature 或更改属性。预览限 2 万三角形/1000 条边，截断时明确提示；实际剖分仍使用完整 BREP。
- 原始问题可定位到同一持久身份的 Body/Face/Edge；隐藏 Body 或过期来源禁止定位。修复后及分块后问题不伪装成原工程的可编辑拓扑。
- “使用此快照剖分”复用已验证保存的 BREP/来源清单，不再次修复；模式、工程身份或文件校验不一致时拒绝。质量阈值仍可调整，包括 0。
- 任务、报告、预览和 BREP 保存到受管任务目录，刷新/重启不重做任务，恢复后默认不显示预览或网格。取消几何准备为合作取消，不杀死工程的 OCCT 进程；失败报告仍可检查，但不发布有效网格。

当前可重复生成的原生样本包含健康 Box、反向 Solid、偏大容差、小边/狭长面、自交轮廓面、开放壳、异常 SameParameter 标记及其实际 ShapeFix 修复结果。它是回归基线，不等同于覆盖真实工业导入模型的大样本验证，也不代表任意离散三角形交叉已能自动重构。

当前工程四面体流程支持 Solid 与 Sheet；工程中含独立线框/点，或实体复合体附带游离边/点时，会保留诊断并明确拒绝，不把这些几何悄悄漏掉。线约束/点约束的完整剖分支持仍需后续实现。

候选后台的网格验收已增加线性四面体正体积重叠检查：即使质量数值为正、连接计数正确，内部穿透也会阻止正常显示/下载，并保留诊断材料。正常共面/共边/共点接触不误报为体积重叠；这不等同于完整接触共形证明。高阶曲边单元明确提示空间检查未覆盖，不把角点近似当作曲边无交叉证明。方法、预算与限制见 `docs/GMSH_MESH_WORKER.md`；本候选尚未主动切换日常服务。

候选界面的“空间重叠”样例可同时定位 A/B 两个参与单元，并分别显示来源 Body；任一方归属无效、隐藏或来源过期时禁用/暂停整对。图层不进入 CAD 拾取、不改变工程显隐，不需要显示整份失败网格。线性空间索引改为按实际参与单元分块分配，全高阶路径不预留线性索引；这不等于整个网格流程零内存或完整高阶空间检查。

候选视口使用“显示局部原点”：CAD、边线、属性高亮、网格分块、修复预览和历史输入的 GPU 坐标保存相对偏移，对象位置仍采用原工程坐标。它不平移 BREP、不改参数/坐标系或拓扑 ID；用于避免远原点处的小零件被 Float32 压成零尺寸。无效或不可表示的局部跨度明确显示错误，不保留旧几何作为假成功。不能恢复源 Float64 已经丢失的信息，也不保证任意极端尺度/超大跨度下的细节精度。

边拾取采用约 5 屏幕像素的容差，不再使用固定工程单位下限；不透明面的遮挡、显隐和相机裁剪参与筛选，透明体允许透视拾取。微小零件可用视口“适应窗口”重新聚焦。专项入口 `scripts/verify-view-origin.mjs` 使用临时工程验证真实 OCCT/Gmsh 和 WebGL，不应对用户工程运行破坏性测试；整体候选验收及发布状态见 `docs/INDUSTRIAL_PREPROCESSING_ROADMAP_zh.md`。

网格显示的单块 15 秒读取预算覆盖 HTTP、响应流、异步摘要校验及转换后的单调截止检查；不响应取消的操作、永不结束的流清理或立即就绪的片段洪泛不能让本层无限等待。空片段累计超限失败，有效小片段分批让出输入/计时任务。隐藏/切换任务会撤销旧请求的发布资格，迟到结果不回挂，失败不自动重试；显式隐藏/显示可恢复。这里只停止显示读取，不取消原生剖分或修改 CAD。具体资源范围、第三方传输取消限制及回归入口见 `docs/GMSH_MESH_WORKER.md`。
